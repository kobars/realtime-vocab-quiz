## PR-100 — The load bot's protocol rules and latency samples

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Write the protocol core of the load bots in `load/player.py`, with no I/O: the web client's reconnect backoff and final close codes, what a bot sends for each server message, and the two latency samples (answer → `answer_result`, accepted points → the first `leaderboard` or `rank_update` that shows the new total) with timed-out and missing counts. Add `load/` to the lint, type and test steps of `make check`.
- **Prompt / interaction:** The agent read the protocol spec (reconnect, `seq` and answer rules) and the web client's backoff module, wrote the bot as a pure state machine driven by `handle()` and `due()` with an injected clock, and tested it with plain message dicts. The swarm runner was written in the same session and moves to a later PR.
- **What was wrong or changed:**
  - In the first draft, a timed-out answer set `sent_at` to `None` and the resend set it again. The retry's reply would then have counted as a fresh latency sample, from the resend instead of the first send. A `timed` flag now marks only the first send, and `test_a_retried_answer_keeps_its_submission_id_and_is_never_timed` checks that a retried answer adds no sample.
  - `backoff_s` computed `250 * 2**attempt`, which mypy (strict) typed as `Any` because an int power can be a float. It now uses `250 << attempt`.
  - The review after the merge found protocol-recovery rules that the code missed, fixed in a later PR with one test each in `load/tests/test_player.py`: the resync after a second `joined` skipped the 1 s limit, and a refused `resync` left the bot waiting for a snapshot for good (`test_a_rejoin_keeps_the_resync_limit_and_a_refused_resync_is_retried`); a `next` or `join` refused with `UNAVAILABLE` or `RATE_LIMITED` was never sent again (`test_a_refused_join_or_next_is_sent_again`); a gap resync due inside the 1 s window was dropped (`test_a_gap_inside_the_resync_limit_waits_for_it`); broadcasts between `resync` and `snapshot` were dropped instead of buffered (`test_broadcasts_during_a_resync_are_applied_after_the_snapshot`); every frame of one gap was counted, and resyncs were not counted (`test_a_seq_gap_schedules_one_resync`); `snapshot` ignored `you.score` and `status` (`test_a_snapshot_settles_waits_and_can_end_the_quiz`); and there was no `pong` rule (`test_a_pong_ahead_of_the_last_seq_resyncs_a_second_later`).
- **Verification:**
  - `make check`: green (459 pytest, 323 vitest).
  - Tests in `load/tests/test_player.py`: backoff values and the 10 s reset, the close codes with no reconnect, a full join → answer → leaderboard round with both samples, a `seq` gap that leads to one resync, a retried answer, a rejoin error, and the leaderboard waits (settled, timed out, missing). Making the `seq` rule accept any higher `seq` fails `test_a_seq_gap_schedules_one_resync`.
