## PR-101 — The bot swarm runner and its CLI options

- **Tool:** Claude Code (claude-opus-5-5); Codex CLI (`gpt-6-astra`, xhigh reasoning) for a read-only analysis of `load/` and its contract with the server
- **Task:** Build the runner on top of `load/player.py`: `load/bots.py` plays bot slots in cohorts over N quizzes for a ramp and a duration, with a fresh ticket and an `Origin` header on every connect, and parses the run's options. The run summary, `--procs`, quiz setup and the result file follow in the next PR.
- **Prompt / interaction:** The agent wrote the runner with the bot's protocol rules and smoke-ran it against one API node with the memory store. After the review it fixed each confirmed finding with a test, had Codex analyze the fixed runner, verified and fixed what it found, and moved the summary half to its own PR to keep both within the size budget.
- **What was wrong or changed:**
  - The reconnect loop never looked at the run's deadline: with a refused upgrade the bots retried forever and the run never ended. `play()` and `converse()` now stop a bounded drain (`--timeout-ms`) after the deadline; `test_reconnects_end_at_a_final_close_or_after_the_deadline` and `test_converse_sleeps_to_its_next_timer_and_closes_at_the_stop`.
  - A reconnect kept the open answer: one still in its think time went out before `joined`, and a final answer whose reply was lost was never resent or cleared, so the player never settled. Open waits now end with their connection and `joined` re-serves the question; `test_a_reconnect_drops_the_open_answer`.
  - When `play()` raised, or the quiz ended with an answer in flight, the open waits were dropped without being counted missing; `test_a_stopping_player_counts_its_open_waits`.
  - Smaller gaps: a reconnect was counted before the final-close check; after an answer retry, a late reply left a past timer that made the receive loop spin; negative, `nan` and `inf` option values were accepted (`test_the_cli_checks_its_options`).
  - Found by the Codex analysis: the receive wait left out the answer-retry and leaderboard-expiry times, so a finished player lingered up to 1 s and the 1 s test run played one cohort per slot instead of about four (the end-to-end test now requires a second cohort); an overload wait longer than the time left made the slot start a new cohort at once, and a final close ended the player but not its slot; queued frames were still sent after the quiz ended (`test_converse_sends_nothing_once_the_quiz_ended`).
- **Verification:**
  - `make check`: green. Each new test fails on the first version of the runner.
  - `load/tests/test_bots.py`: the tests above, the leaderboard header regex against the server's own encoding, and `test_a_swarm_plays_whole_quizzes_against_the_app` (`create_app()` on a free port: each slot plays more than one cohort and its first answers all ten questions, with no timeouts, missing samples, failed opens or reconnects).
