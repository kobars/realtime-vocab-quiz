## PR-102 — Keep the leave grace with the newest connection and bound the heartbeat test

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix three verified defects from the post-merge review of PR #98: the drop of a replaced socket cancelled the newer socket's grace timer and left the player present, a read-only join after the end cancelled a pending leave, and the heartbeat test could hang `make check` when the server failed to start.
- **Prompt / interaction:** The agent worked from the review's verified finding list, wrote a failing test for each registry defect first, then changed the registry; the test-only defect was checked by starting the new helper with an app whose lifespan raises.
- **What was wrong or changed:** The registry now records the newest writing connection per quiz and player; a socket that a newer join replaced starts no timer, and a read-only bind touches neither the record nor the timer. Because only the newest connection's drop starts a timer and every writing bind cancels it, the timer no longer needs to check that it is still the current one before it clears its entries. The heartbeat test runs uvicorn through a `served` context manager with a 5 s bounded start that also fails when the server thread exits, and a `finally` that stops the server. The first version of the new test helper had a line over the 100-character limit; `make check` (ruff) caught it before the commit.
