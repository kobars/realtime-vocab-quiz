## PR-102 — Keep the leave grace with the newest connection and bound the heartbeat test

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix three verified defects from the post-merge review of PR #98: the drop of a replaced socket cancelled the newer socket's grace timer and left the player present, a read-only join after the end cancelled a pending leave, and the heartbeat test could hang `make check` when the server failed to start.
- **Prompt / interaction:** The agent worked from the review's verified finding list and wrote a failing test for each registry defect before changing the registry. Next to the review, a Codex (`gpt-6-astra`, xhigh reasoning) read-only analysis of the gateway's connection lifecycle checked the first version of the fix. The test-only defect was checked by starting the new helper with an app whose lifespan raises.
- **What was wrong or changed:**
  - The first version of the fix recorded the newest connection per player in the order of the local binds, and let only that connection start a grace timer. The Codex analysis showed that two joins of one player on one node can bind in the reverse order of their Redis writes when a reply is delayed. The node then treats the replaced socket as the newest one, and the last `leave` is still lost. The final version keeps one timer per dropped connection and cancels none, so the store's compare on the connection id alone decides which `leave` removes the presence. A rejoin within the grace now costs one stale `leave` call. `test_a_replaced_socket_that_drops_last_keeps_the_newer_sockets_leave` runs both bind orders, and its out-of-order case fails on the first version.
  - Because a rejoin no longer cancels the earlier timer, `test_a_drop_leaves_after_the_grace_unless_the_player_comes_back` now expects the first socket's `leave` to come back stale and the second socket's to remove the presence.
  - The heartbeat test runs uvicorn through a `served` context manager with a 5 s bounded start that also fails when the server thread exits, and a `finally` that stops the server.
  - The first version of the new test helper had a line over the 100-character limit; `make check` (ruff) caught it before the commit.
- **Verification:** `make check` (exit 0) and `make test-integration` (126 passed). `api/tests/integration/ws/test_connections.py::test_a_replaced_socket_that_drops_last_keeps_the_newer_sockets_leave` (both bind orders) and `::test_a_read_only_join_keeps_the_pending_leave` fail on the previous registry (`online_count` 1, expected 0) and pass after the change. `scripts/check_internal.py --commits origin/main..HEAD` (exit 0).
