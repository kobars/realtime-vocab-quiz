- **Prompt / interaction:** The agent read the inputs from `api/src/quiz/config.py`, `api/src/quiz/contracts/`, `api/src/quiz/adapters/mock_auth/tokens.py`, `api/src/quiz/adapters/ws/heartbeat.py`, `docs/spec/` and `docs/DECISIONS.md`, computed the `leaderboard` frame sizes by encoding sample frames in compact JSON (as the tick script's `cjson` writes them), and derived every other number from those with the formula next to it.
- **What was wrong or changed:** The first draft cited ADR-005 alone for the 24 h expiry of quiz data; the TTL rule is in ADR-008, so the trade-off now cites both. The review before the merge found more mistakes in the draft, all fixed in this PR: the per-socket memory "bound" of 320 KiB left out the transport write buffer and the inbound frames parsed from one read (now a table of buffers, labelled a partial estimate); the 32-character frame column ignored that the name cap counts characters, not bytes; the empty-tick formula assumed every answer marks the quiz dirty; the Redis load per second left out the `pong` reads, the rank-shift reads and the per-scorer calls inside the tick script; `WAITAOF 1 1` lacked its timeout argument; a crash was said to lose only answers that clients retry, but an answered submission is never retried; quiz-ID routing was placed in an L4 balancer, which cannot see the URL; random spread was said to put every quiz on all 10 nodes (the occupancy formula gives about 6.5); A11 cited a `--think-ms` option that does not exist and A12 cited `compose.yaml`, which defines only Redis. A second analysis of the corrected text found that the inbound read size is uvloop's 256,000 bytes, that pongs to client pings skip the write flow control, that joins and leaves also mark a quiz dirty, and that a renewal of the `seq` epoch needs a compare and set; those are fixed too.
