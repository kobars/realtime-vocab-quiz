## PR-105 — Run the coalescing tick and relay broadcasts on one node

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Run one tick loop per quiz while this node holds a socket of it: call `publish_if_dirty` every 200 ms tick, relay each published frame to every local socket with the bytes built once, and send `rank_update` to local players outside the top 50 above 200 players (scorers in the same tick, shifted ranks at most once per second).
- **Prompt / interaction:** The agent read `docs/spec/redis.md` §3 and §5 and the feed port, wrote the ticker, the relay, the registry hooks and the wiring, and three integration tests that run on both stores. The work first grew past the 400-line budget, so the store-side feed went into its own PR (#104) and this branch was rebased on it after its review.
- **What was wrong or changed:**
  - With the tick running, a leaderboard frame can reach a socket at any time, so the existing session replacement test read a relayed frame where it expected `joined`. The test now skips leaderboard frames (`reply()` in `api/tests/integration/ws/test_connections.py`).
  - The rebase met a reworked registry on `main`: the grace timers are now per connection and never cancelled. The first version of this branch cancelled a pending leave on rejoin; the resolved registry keeps `main`'s timers and adds only the per-player sockets and the watcher.
  - The fan-out tests' store fixture requested the Redis fixture for the memory variant too, the same mistake the review of #104 had found in the feed tests. It now requests Redis only for the Redis case.
- **Verification:**
  - `make check`: green. `make test-integration`: green (138 passed).
  - `api/tests/integration/fanout/test_fanout.py` on both stores: `test_100_answers_in_1_s_make_at_most_6_frames_ending_on_the_standings`, `test_the_tick_runs_only_while_the_quiz_has_local_sockets`, `test_players_outside_the_top_50_get_rank_updates` (one `ranks_of` read per second for all local players, the newest value, nothing for a player in the top 50).
