## PR-107 — Confirm the end mark's fsync on every host end before announcing

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix a verified durability defect in the host end: a retry after a failed `WAITAOF`, or a second overlapping host end, published `quiz_ended` without any fsync of its own.
- **Prompt / interaction:** The agent worked from a verified finding of a whole-codebase analysis, wrote the two integration tests first, confirmed both fail on `main`, then changed the Lua script and the store method.
- **What was wrong or changed:** `end_quiz.lua` returned `marked` only when `endedMs` was absent, so any host call that found an existing mark went on to `INCR seq` and publish, and `end_by_host` ran `WAITAOF` only after a fresh mark. The script now takes a third reason, `mark`, which never publishes and writes `endedMs` again with its own value when it exists; `end_by_host` always starts with it, so the `WAITAOF` on the same dedicated connection covers the mark before `end_quiz(host)` publishes. The Redis and protocol specs describe the new step.
- **Verification:** `make check` (green) and `make test-integration` (134 passed). `api/tests/integration/test_deadline.py::test_a_retry_after_a_failed_fsync_waits_for_its_own_fsync` and `api/tests/integration/test_deadline.py::test_overlapping_host_ends_each_wait_for_the_fsync_before_announcing` fail before the change (one fsync wait seen instead of two) and pass after it. `scripts/check_internal.py --commits origin/main..HEAD` (exit 0).
