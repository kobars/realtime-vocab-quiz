## PR-11 — Add Pydantic models for every protocol message

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add one strict Pydantic v2 model per wire message of protocol v1, the client and server discriminated unions on `type` with their TypeAdapters, and a valid, an invalid, a missing-field and an unknown-field example per message.
- **Prompt / interaction:** The agent built the models from the message catalog and field table of `docs/spec/protocol.md`, wrote table-driven tests with one valid and one invalid example per message, and re-checked every field and range against the spec before opening the PR.
- **What was wrong or changed:** The first version put the models, the inbound parser and the JSON Schema generation in one change of 718 changed lines, over the 400-line limit per PR; it was split so this PR holds only the models and their tests, with the parser and the generation in follow-up PRs. No field or range mistakes were found when the models were re-checked against the spec. The post-merge review then confirmed two mistakes in this code, fixed in a follow-up PR: `message_types()` always unwrapped one `Annotated` level, so for the plain union `Broadcast` it returned an empty set; and `strict=True` made `code: ErrorCode` reject plain strings in Python mode, so `validate_python` on decoded JSON failed for a valid `error` frame that `validate_json` accepted.
- **Verification:** `make check` (exit 0; 147 tests). Tests: `api/tests/unit/contracts/test_messages.py` (`test_every_message_has_examples` fails when a message in a union has no example; round-trip, invalid, missing-field and unknown-field tests per message). The two review findings are now caught in the same file by `test_message_types_reads_a_plain_union`, `test_decoded_json_validates_like_raw_json` and `test_error_code_is_parsed_into_the_enum_from_decoded_json`.
