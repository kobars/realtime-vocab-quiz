## PR-110 — Close a replaced socket whose join reply reaches the node last

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix a confirmed gateway defect: when the store took an older socket's `join` first but that reply reached the node after the newer socket's `join` had finished, `Registry.replace` ran before the older socket was bound and did nothing, so the older socket was joined and stayed registered for broadcasts. The registry now tracks each socket from the start of `serve`, so the replacement closes it with `SESSION_REPLACED` and 4001.
- **Prompt / interaction:** The agent got the verified finding with its reproduction (the older socket received `joined` and no close; both sockets stayed registered), wrote a test that holds the older join's store reply until the newer join returns, confirmed it failed on the old code for that reason, then made the change.
- **What was wrong or changed:** (1) The first draft of the test assigned the wrapped `join` to the store with only `type: ignore[method-assign]`; mypy also reported `assignment`, because the wrapper's parameter name differs from the port's, and the ignore now names both codes. (2) A first version of the fix also skipped binding a socket whose sender was already closing; that would have left `drop` indexing a quiz entry that was never created, so it was removed, and the closing socket stays bound until `drop`, receiving nothing because its sender queues nothing after a close.
- **Verification:** `make check` (exit 0); `make test-integration` (exit 0, 133 passed); `scripts/check_internal.py --commits origin/main..HEAD` (clean); test `api/tests/integration/ws/test_connections.py` (`test_a_replaced_socket_whose_join_reply_comes_last_is_closed_with_4001`).
