## PR-113 — Make the load bot follow the protocol's resync and retry rules

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix the protocol-recovery findings of the review of PR-100 in `load/player.py`: throttle every `resync` to one per second and postpone a due one, retry a refused `resync`, `join` or `next` after 1 s (`RATE_LIMITED`) or the backoff (`UNAVAILABLE`), buffer broadcasts between `resync` and `snapshot`, count one gap per pending resync and count resyncs, settle board waits from the snapshot's `you.score` and end on `status: "ended"`, and add the `pong` rule.
- **Prompt / interaction:** The agent read the verified review table and protocol spec §3 and §7, wrote one test per finding in `load/tests/test_player.py`, checked each new test fails on the old `load/player.py`, then changed the bot. A first draft that fixed every finding of the review together came to more than the 400-line limit, so the answer-replay and latency fixes were moved to a separate PR.
- **What was wrong or changed:**
  - The draft kept the retries of a refused `join` or `next` across a rejoin, so a stale `next` could go out after the `join` that reads the cursor again. `joined` now clears pending retries, and `test_a_refused_join_or_next_is_sent_again` checks that nothing more is sent after it.
