## PR-116 — Add make dev-api so the Vite dev proxy reaches an API that allows its origin

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make the local dev setup work end to end with the default settings: the Vite dev server proxies `/ws` to `127.0.0.1:8001` with `Origin: http://localhost:5173`, while the API's default allowed origins are the `:8080` ones, so the WebSocket upgrade got 403, and nothing started the API on 8001 (`python -m quiz` binds 8000).
- **Prompt / interaction:** The agent worked from a verified finding of a whole-codebase review, with the evidence (the Vite defaults, the settings' default origins and the gateway's 403), and chose between a launcher and wider default origins itself.
- **What was wrong or changed:** Adding the `:5173` origins to the defaults would have widened the production allow-list, so the defaults stay and `make dev-api` sets `ALLOWED_ORIGINS` for the dev node only. The target runs `python -m quiz`, which now takes `--host` and `--port`, rather than the `uvicorn` command line, so the heartbeat, frame cap and `permessage-deflate` setting of `server_config` apply as in the image instead of being repeated as flags. The first version of the new test failed ruff (a combined assertion and a long marker line). The existing `python -m quiz` test now passes the argument list to `main`, since `argparse` would otherwise read pytest's own `sys.argv`.
- **Verification:** `make check` (exit 0 after the rebase: pytest 473 passed, Vitest 329 passed); `scripts/tests/test_dev_setup.py` fails without the `dev-api` target and passes with it; `scripts/tests/test_images.py` checks `python -m quiz` with and without `--host` and `--port`; with `make dev-api` and `pnpm -C web dev` running, a session, a ticket and a WebSocket upgrade with `Origin: http://localhost:5173` through the proxy succeeded (subprotocol `quiz.v1`); `scripts/check_internal.py` and `--commits origin/main..HEAD` are clean.
