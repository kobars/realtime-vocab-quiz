## PR-117 — Add CodeQL, a secret scan and dependency audits

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add security scanning to CI: CodeQL for Python, TypeScript and the workflows; a gitleaks scan of the whole git history; dependency review on pull requests; pip-audit and pnpm audit of the locked dependencies; `make audit` to run the audits and the scan locally; `SECURITY.md`.
- **Prompt / interaction:** The agent worked from a task description listing the scanners and the acceptance checks, ran each scanner against the current repository and its history first, then wrote the make targets and the two workflows so that the CI jobs call the same targets.
- **What was wrong or changed:** The first draft of `make audit-secrets` ran gitleaks from its Docker image. In a git worktree the container could not see the repository (`.git` is a file pointing outside the mount), and gitleaks logged the git error yet printed "no leaks found" and exited 0, a silent pass. The target now runs a native gitleaks binary (CI installs release 8.30.1 and checks its SHA-256), and a scratch clone with a fake key committed and then removed confirmed that the scan fails on history. The full-history scan found one false positive, the RFC 6455 sample `Sec-WebSocket-Key` nonce in the handshake tests; `.gitleaks.toml` allowlists that value only. `pip-audit` and `pnpm audit` found no known vulnerabilities.
  - Review findings, fixed before the merge. (1) The native binary still allowed a silent pass: outside a git repository gitleaks prints `0 commits scanned`, `no leaks found` and exits 0, and in a shallow clone it scans only the fetched commits. The earlier fix had changed the runtime and left that path open. `make audit-secrets` now fails before gitleaks runs unless `git rev-parse --is-shallow-repository` prints `false`; `scripts/tests/test_audit_secrets.py` runs the target outside a repository and in a `--depth 1` clone and expects the failure. (2) The top-level `[[allowlists]]` table in `.gitleaks.toml` needs gitleaks 8.25 or later, which the docs did not say; `SECURITY.md`, the README and `make help` now state it. (3) `uv export` exported only the default dependency groups, so the `load` group was not audited; the export now uses `--all-groups`.
- **Verification:** `make check` (green); `make audit` (python and web audits: no known vulnerabilities; secret scan: no leaks found over the history that contains the nonce in `api/tests/integration/ws/test_connections.py`); `make audit-secrets` on a scratch clone with a planted key (exit 1, `leaks found: 1`); `scripts/tests/test_audit_secrets.py` (the full-history guard, 2 tests, pass); `actionlint` on both workflows (clean); `scripts/check_internal.py --commits origin/main..HEAD` (exit 0).
