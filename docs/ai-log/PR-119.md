## PR-119 — Check the containers and infrastructure files in CI

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add a CI workflow for the container and infrastructure files (hadolint, shellcheck, `docker compose config`, `nginx -t`, Trivy configuration and image scans, a non-root and read-only image smoke test) and fix what the scans report.
- **Prompt / interaction:** The agent ran each tool locally first (hadolint and shellcheck from their images, Trivy 0.69 on the built images), fixed the findings in the Dockerfiles, wrote the static tests before the Dockerfile and workflow changes and saw them fail, then wrote the workflow and checked it with actionlint.
- **What was wrong or changed:** (1) hadolint stopped at the heredoc that held the web image's nginx site, so the site moved to `web/nginx.conf`. (2) The image scan found 49 fixable HIGH OS findings (the base tags lag the Debian and Alpine fixes) and HIGH advisories in pip's vendored msgpack, urllib3 and setuptools; the runtime stages now upgrade their packages and the API runtime removes pip. (3) Trivy DS-0002: the web image had no `USER`; it now ends with `USER 101:101`. (4) The agent's first version of the nginx test asserted that `$uri/` does not appear in the whole config file, which failed on the file's own comment; it now checks only the `try_files` lines. (5) A test line over 100 characters failed `ruff` in `make check` and was shortened. Review before the merge found four more agent mistakes, now fixed: (6) the `infra/` branch of `nginx -t` mounted the folder over `conf.d` outside the compose network, so a proxy upstream named by a compose service failed with `host not found in upstream`; `scripts/check_nginx.sh` now mounts each `infra/**/nginx.conf` as the main config and adds every compose service name as a host (`test_infra_nginx_config_is_tested_with_the_compose_service_names_resolvable`). (7) The README read as if the Trivy config scan had the image scans' CRITICAL/HIGH threshold; it fails on any finding, and the README now says so. (8) `scripts/smoke_images.sh` left its detached container running after an abort or Ctrl-C; an EXIT trap now removes it (`test_smoke_removes_its_container_when_the_script_aborts`). (9) The workflow test matched substrings that the step names already contained and never checked the `pull_request` trigger; it now asserts the `run:` commands and the `on:` key.
- **Verification:** `make check` (exit 0); `make build && scripts/smoke_images.sh` (both images healthy as uid 10001 and 101 on a read-only root; exit 1 for an image rebuilt as root); `trivy image --severity HIGH,CRITICAL --ignore-unfixed` on both images (no findings); `scripts/check_internal.py --commits origin/main..HEAD` (clean); `scripts/check_nginx.sh` against a scratch `infra/nginx/nginx.conf` with an upstream on `api-1:8000` and `api-2:8000` (passes; the same `nginx -t` without the hosts fails); an interrupted `scripts/smoke_images.sh` leaves no container; tests `scripts/tests/test_images.py`, `scripts/tests/test_repo_config.py` and `scripts/tests/test_image_scripts.py`.
