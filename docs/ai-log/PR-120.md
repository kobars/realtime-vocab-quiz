## PR-120 — Add coverage, link and spell-check gates and run the pre-commit hooks in make check

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add test-quality and documentation gates: API branch coverage and web coverage floors, an offline Markdown link and anchor check in `make check` plus a weekly online run, a typos spell check, and one set of checks shared by the pre-commit hooks and CI.
- **Prompt / interaction:** The agent measured the current coverage before setting any floor, set each floor to the measured value rounded down, wrote the hook-parity test in `scripts/tests/test_repo_config.py` first and saw it fail, then replaced `make check`'s separate guard, ruff and ESLint steps with `pre-commit run --all-files`. Each gate was shown to fail on purpose: a removed test file for both coverage floors, a scratch Markdown file with broken links and anchors, and a scratch file with a misspelling.
- **What was wrong or changed:** (1) The first API coverage run had no `source` setting, so it measured the test files too, including the integration tests that `make check` does not run, and reported 76%; `[tool.coverage.run] source_pkgs = ["quiz"]` limits it to the package, which measured 86.63% (floor 86). After the rebase on `main`, which added the fan-out tick that the integration tests cover, the same run measures 84.85%, so the floor is 84. (2) The new parity test first had a line over 100 characters; the ruff hook, now run by `make check` through pre-commit, rejected it and the line was reformatted. (3) A first typos run flagged two abbreviated commit hashes in AI-LOG entries and the `Caf\u00e9` literal of a Unicode normalization test; `_typos.toml` allows hex hashes and that one word instead of changing the files. (4) Review found that moving the internal-content guard into pre-commit stopped `make check` from scanning tracked symlinks: pre-commit's default `types: [file]` drops them, because `identify` tags a symlink only as `symlink`. Adding `types_or: [file, symlink]` alone was not enough, since `types` still defaults to `[file]`; the hook now sets `types: []` as well. The test `test_internal_hook_scans_every_staged_file_and_symlink` in `scripts/tests/test_repo_config.py` runs pre-commit's own file filter on a file, a dotfile and a symlink, and failed before the fix. (5) Review also found that `ignore-hidden = false` in `_typos.toml` had no effect on the gate (the hook passes file names, and typos checks a named hidden file either way) while making a plain `typos` run walk `.git/`; the setting was removed. (6) The new test imports pre-commit, which ships no `py.typed`, so strict mypy rejected it; a mypy override for `pre_commit.*` reads its typed sources instead of skipping them.
- **Verification:** `make check` (exit 0, API coverage 84.85%); with `api/tests/unit/app/test_service.py` removed locally, the pytest step fails (81.46% < 84%); with `web/src/protocol/seq.test.ts` removed, it stops at the vitest step (lines 96.49% < 97%); `scripts/check_internal.py --commits origin/main..HEAD` (clean); test `scripts/tests/test_repo_config.py`.
