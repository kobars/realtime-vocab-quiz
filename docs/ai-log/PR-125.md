## PR-125 — Bot swarm run summary, processes, quiz setup and result file

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Finish the bot swarm on top of the runner of PR #101: `load/latency.py` turns the samples into p50/p95/p99 with missing and timed-out counts and decides whether a run is valid; `load/bots.py` gains `--procs`, `--admin-token` quiz setup, `--label` and a JSON result file in `load/results/`.
- **Prompt / interaction:** The agent wrote this half together with the runner, then moved it to its own PR to keep both within the size budget, carrying the review fixes that concern this code. After the runner merged it applied the commit on `main` unchanged and added two small fixes that a read-only analysis of the merged runner had found.
- **What was wrong or changed:**
  - The first quiz setup treated every 409 from `POST /admin/quizzes` as a running quiz, so a run against an ended quiz started and measured nothing. It now reads `GET /quizzes/{id}` and stops on `ended`; `test_quizzes_are_created_or_found_open`.
  - A run with no answer samples was reported valid; it is now invalid with the reason in `problems` (`test_a_run_without_answer_samples_is_invalid`). The swarm's CPU was measured over the whole run, ramp included; it now covers the steady window from the ramp's end to the deadline. Message rates were divided by the duration alone; they now use ramp + duration.
  - Result names had one-second resolution and could overwrite a run; they now carry microseconds and the file is created exclusively. A run longer than the quiz window was silently capped at one hour; the server's 422 for a too-long window now stops the run before any bot starts (`test_quizzes_are_created_or_found_open`). `--procs` had no end-to-end test; `test_a_swarm_over_two_processes_writes_its_result` runs it through `main()`.
  - The first fix for a timer at the drain stop skipped every timer there, so a retry timer that ran out at the stop counted a missing answer instead of a timeout. On `main` an answer that was never sent is already dropped once the deadline has passed, and the stop is the deadline plus the timeout, so the guard was removed; `test_a_timer_at_the_stop_counts_no_missing_answer` covers both timers. The app fixture derived its allowed origins from `QUIZ_PORT` in the environment, so an exported port refused every bot; it now pins them, and `test_a_swarm_plays_whole_quizzes_against_the_app` runs with the variable exported.
  - Found in review: a `--label` with a path separator was accepted and the write failed after the run, and since the report was printed in the same call as the save, the run's report was lost; the CLI now refuses such a label and the report is printed first (`test_the_cli_checks_its_options`, `test_the_report_is_printed_before_the_result_is_saved`). The edit of the bad-input list had dropped `--bots 0`; it is back.
  - Found in review: a quiz that ended before the deadline stopped its slots silently and the run was still valid, and the CPU window ran on until the deadline, so the idle time hid a busy swarm. Slots that stop on a quiz end before the deadline now make the run invalid, and the CPU window ends with the slots (`test_a_quiz_end_before_the_deadline_ends_the_cpu_window`, `test_a_quiz_that_ends_before_the_deadline_makes_the_run_invalid`).
- **Verification:**
