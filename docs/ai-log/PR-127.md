## PR-127 — Bound the socket close and keep the leave of a late repeated join

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix two gateway lifecycle defects in earlier AI-written code, found by a whole-codebase analysis with Codex and checked against the code: the sender awaited the close frame outside its flush deadline, so a transport that never became writable held the handler, its registry entry and its connection slot; and a socket that joined while open and repeated `join` after the deadline became read only, which made `Registry.drop` skip its leave, so the player stayed present.
- **Prompt / interaction:** The agent got both findings with their reproductions, wrote one test per finding (a fake socket whose `close()` never returns, driven through `serve()`; join, deadline, join again and drop on the memory store), confirmed that each failed on `main` (the test's 1 s wait timed out; `onlineCount` stayed 1), read uvicorn's sans-I/O WebSocket `send` to confirm that the close waits for a writable transport, then made the fixes.
- **What was wrong or changed:** (1) The earlier sender bounded only the drain with `asyncio.timeout_at`; the close now runs under the same deadline, and a close that is still blocked once it has passed is given up. (2) The earlier registry used `read_only` to mean "holds no presence", but a present socket also becomes read only when it joins again after the end; `Connection.present` now records a join the store accepted while open, and `drop` checks it. Three existing registry tests built connections by hand and relied on the old meaning, so they now pass `present=True`.
