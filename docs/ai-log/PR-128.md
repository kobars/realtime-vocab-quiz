## PR-128 — Say which answers a Redis restart can lose in the Redis spec

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Correct the "Redis restarts (AOF `everysec`)" row of the failure table in `docs/spec/redis.md` §5, which said that a lost answer is scored again when the client retries it.
- **Prompt / interaction:** The agent worked from a verified review finding. It read the client's resend logic in `web/src/protocol/client.ts` (`settle` removes a submission from the resend set when its `answer_result` arrives), rewrote the row to match, and searched `docs/spec/` for other sentences making the same claim.
- **What was wrong or changed:** The earlier spec text claimed that every answer lost in the AOF `everysec` window is scored again on a client retry. The client resends only answers without an `answer_result`, so an acknowledged answer in the lost second is gone and the player's total drops back by its points, as DESIGN §10 already states. The row now says so. The other "retried" sentences in `docs/spec/` describe resends of unacknowledged requests and were already correct. The review before the merge found that the AI's rewrite still described the loss too narrowly, and the row was corrected: (1) it said only that a lost acknowledged answer "is gone", but its `answered` field is lost too, so the question is open again for that player, closed as a 0-point skip by the next `next` (`serve_question.lua`) or shown again by a rejoin (`join.lua` returns `cursorOpen`); (2) it promised that every resent answer is scored, but a resend whose question serve was also lost gets `QUESTION_NOT_OPEN` (`score_answer.lua`), is settled without a score, and the client rejoins; (3) it left out that a lost finish (`finished = 1`) puts a player who saw the result screen back on the last question at the next rejoin.
