## PR-131 — Declare starlette and check dependencies with deptry

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Declare starlette, which `api/src` imports directly but which arrived only through fastapi, and add deptry to `make check` so that an undeclared, transitive-only or unused dependency fails the gate; check `scripts/` and `load/` as well where deptry's rules fit them.
- **Prompt / interaction:** The agent added the dependencies with `uv add` (so `uv.lock` was regenerated, not edited), ran deptry on `api/src` with and without the starlette entry, then ran it on `scripts/` and `load/` and chose which rules apply to dev tools from the findings it reported.
- **What was wrong or changed:** The first run on `scripts/` and `load/` reported DEP004 on every dev-group import (expected for dev tools, so that step ignores DEP004 and DEP002), DEP003 on `quiz` (the project itself, now `known_first_party`), and a real DEP003 on `pydantic_core` in `scripts/gen_contracts.py`. A planned DEP002 ignore for `httpx2` was left out: deptry never applies DEP002 to dependency groups. Review before the merge found three AI mistakes, now fixed: (1) the `pydantic_core` DEP003 exception sat in the shared `[tool.deptry]` table, so `deptry src` also accepted a direct `pydantic_core` import in the service code; it now lives only on the tool step's flags (caught by `test_dependency_check_fails_when_src_imports_pydantic_core`); (2) the tool step never scanned `api/tests`, `scripts/tests` or `load/tests`, because deptry's default exclude skips every folder named `tests`; the step now adds `tests` as a root and replaces the default exclude (caught by `test_make_check_runs_the_dependency_check_on_every_python_root` and `test_tool_dependency_check_fails_on_missing_and_transitive_imports`); (3) the Makefile test checked only the command prefix, so a step that ignored every rule still passed; the new test runs the step's own flags on a fixture and expects DEP001 and DEP003 findings. The Makefile comment no longer claims the tools import none of the runtime dependencies.
- **Verification:** `make check` (exit 0, 513 pytest, 347 vitest; both deptry steps report no issues, the tool step scans 65 files, the number of tracked Python files under its roots); `cd api && uv run --locked deptry src` exits 1 with three DEP003 findings when the starlette line is removed; `scripts/check_internal.py --commits origin/main..HEAD` (clean); the four deptry tests in `scripts/tests/test_repo_config.py`, three of which fail against the first review round's Makefile and `pyproject.toml`.
