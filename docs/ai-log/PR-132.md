## PR-132 — Type-aware ESLint rules for the client and extra mypy error codes

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Turn on four type-aware ESLint rules for the client (`switch-exhaustiveness-check`, `no-floating-promises`, `no-misused-promises`, `await-thenable`) through the TypeScript project service, make the reported switches name every union member, and enable eight extra mypy error codes with the reported overrides marked `@override`.
- **Prompt / interaction:** The agent added the ESLint block, ran eslint to list the hits (three switches, no promise misuse), handled each switch explicitly, and checked in a scratch copy that a new `ServerMessage` member fails the lint at the `receive` switches. It then enabled the mypy codes and fixed the nine `explicit-override` reports.
- **What was wrong or changed:** (1) The type-aware block broke the existing `.vue` globals test in `web/src/lint-config.test.ts`: it linted text under `src/LayoutProbe.vue`, a path that does not exist, and the project service types only files that the tsconfig includes, so ESLint returned a parsing error. The vitest run caught it before the push; the test now lints under existing paths, and a new test checks that each of the four rules reports on a sample (it fails with the previous config). (2) After `@override` was added, ruff reported three `noqa: ARG002` comments as unused (RUF100), because ruff does not flag unused arguments of an override; they were removed. (3) The first CI run timed out the `.vue` globals test at Vitest's default 5 s: the first type-aware lint builds the TypeScript program, which took about 9 s on the runner but under 2 s locally. The ESLint config tests now have a 30 s timeout. (4) The review before the merge confirmed three findings. The agent had silenced the exhaustiveness rule in the store with an unreachable `case 'pong'` instead of narrowing the type: `QuizClient` consumes `pong` and never emits it, so `ClientEvent` now excludes it and the case is gone; `web/src/protocol/client.test.ts` checks that no `pong` event reaches the UI and that the type has no `pong` member (the type check fails with the old `ClientEvent`). The agent also missed that the type-aware rules make every eslint process build the TypeScript program, while the pre-commit hook ran eslint in parallel chunks (about 9.5 s wall and 64 s CPU against 3.1 s and 6 s in one process); the hook is now `require_serial`, checked by `scripts/tests/test_repo_config.py`. Last, the PR description had been overwritten with the text of a different change; it was restored to describe this PR.
