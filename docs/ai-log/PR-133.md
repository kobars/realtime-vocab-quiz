## PR-133 — Fail a hung test within a minute, with a stack dump

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make a hung async, Redis or WebSocket test fail within about a minute and name itself instead of running to the CI job limit: `pytest-timeout` (60 s, default signal method) in `api/pyproject.toml`, the `check` and `integration` jobs capped at 10 minutes, and a 10 s deadline on the in-process WebSocket client's receive.
- **Prompt / interaction:** The agent read Starlette's `WebSocketTestSession` and found that `receive()` (which `receive_text` and `receive_json` call) waits with no deadline; it wrapped that one method in `anyio.fail_after` through a session-scoped fixture rather than editing every call site, wrote the test for it first, and checked the timeout settings with a deliberately hanging test in a scratch copy. Review then checked the plugin's source against the first version of the settings.
- **What was wrong or changed:** The first version set `timeout_method = "thread"`, claiming a signal could not stop a hang in TestClient's portal. That was wrong: the thread method ends the whole pytest process with `os._exit(1)` at the first timeout, so later tests, fixture teardown (a local run's Redis container was left behind) and the summary never ran, while SIGALRM does interrupt the main thread's wait on the portal. The suite now uses the default signal method, and a test runs a hung test under the suite's own config and checks that it fails as `Timeout` while the next test still passes. The first version also set `faulthandler_timeout = 50` for a stack dump before the kill; pytest-timeout already prints the stacks on timeout, so it only added a second dump and was removed. The fixture is session-scoped so it adds no function-scoped fixture to the Hypothesis tests; the raw `websockets` client's `recv()` in the heartbeat test was the other read without a deadline and now has `timeout=2`.
- **Verification:**
  - `make check`: green. `make test-integration`: green.
  - `api/tests/unit/test_per_test_timeout.py`: under the suite's config with `-o timeout=1`, a test calling `time.sleep(30)` fails as `Timeout` and the next test passes; it fails with `timeout_method = "thread"` or with no `timeout` set.
  - `api/tests/unit/test_ws_receive_deadline.py`: a WebSocket server that never sends makes `receive_json()` raise `TimeoutError` at a 0.2 s deadline; it errors without the fixture.
  - A scratch integration test that hangs after starting its own Redis container fails as `Timeout`, and the container is removed in teardown.
