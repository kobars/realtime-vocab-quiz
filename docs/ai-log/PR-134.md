## PR-134 — Fan-out tick and relay tests under store faults and at their boundaries

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Unit-test the resilience paths of `fanout/tick.py` (a store blip, a lost quiz, another refusal, a relay error) and the exact boundary comparisons of `fanout/broadcast.py` (`full_list_max`, `top_n`, the seq guard of the shifted read, the end seq against the seq read after subscribing), with a scripted store instead of Redis.
- **Prompt / interaction:** The agent was given the uncovered lines and a list of hand-made mutants that the suite let survive, wrote one test per path or boundary, then applied each mutant in a separate checkout to confirm a new test fails.
- **What was wrong or changed:**
  - Tests only; no source change. `ScriptedStore` plays a list of `publish_if_dirty` results and errors, and its feed stays open after its messages like a live subscription, so a loop that wrongly waits for `quiz_ended` times out instead of passing.
  - The first mutant run reported the seq-guard mutant as killed by the `full_list_max` test. Two mutants of `broadcast.py` had the same file size and were written within the same second, so Python reused the bytecode of the previous mutant. Rerun with `PYTHONDONTWRITEBYTECODE=1`, each mutant fails the test written for it.
  - Review before the merge found three gaps the agent left: the store-blip and the `quiz_ended` rank-read tests raised only `ConnectionError`, so narrowing `except ConnectionError, TimeoutError:` in `tick.py` or `suppress(ConnectionError, TimeoutError)` in `broadcast.py` to `ConnectionError` passed; and every boundary test called `shifted()` once, so loosening its guard `self._seq <= self._read_seq` to `<` passed. Both fault tests now run with `ConnectionError` and `TimeoutError` (`test_tick_faults.py`), and `test_a_second_shifted_read_waits_for_a_newer_frame` (`test_broadcast_bounds.py`) asserts one rank read for two `shifted()` calls with no frame between; each of the three mutants now fails one test.
- **Verification:**
  - `make check`: green. `cd api && uv run --locked pytest tests/unit/fanout -q`: 14 passed.
  - `api/tests/unit/fanout/test_tick_faults.py` and `api/tests/unit/fanout/test_broadcast_bounds.py`. With the unit run, `fanout/tick.py` misses only lines 37 and 68-69. Eleven hand-made mutants (end seq `>=`, the blip re-raised, `rank >= top_n`, `player_count < full_list_max`, the seq guard `>`, no suppression at `quiz_ended`, `QUIZ_NOT_FOUND` re-raised, a relay error re-raised, `TimeoutError` dropped from the tick or the end, the first seq guard `<`) each fail at least one new test.
