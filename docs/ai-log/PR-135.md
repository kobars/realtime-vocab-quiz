## PR-135 — Property test: the frame parser never raises on hostile input

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add a Hypothesis property that `parse_client_message` returns a client message or a `ProtocolError` for any bytes and never raises, with strategies for raw bytes, mutated valid frames, frames across the size limit, nesting around the depth limit and over-long number literals.
- **Prompt / interaction:** The agent read the parser and its unit tests, probed it by hand with lone surrogate escapes and a 5,000-digit number, then wrote the strategies and measured which outcomes a 3,000-example run reaches before committing.
- **What was wrong or changed:** The first draft of the mutation strategy sampled the key to drop from the frame's own keys, so a frame emptied by earlier drops made Hypothesis fail with "Cannot sample from a length-zero sequence"; it now samples from the fixed list of wire field names plus arbitrary text. No production code changed: the parser held under every strategy. The review before the merge found two AI mistakes. The text alphabet merged lone surrogates into one interval set, where they are about 0.2% of the code points: 1 of 2,000 text draws had one and no frame in 2,000 decoded to JSON holding one, although the comment named that case. Surrogate-only text now has its own branch; the same measurement gives 972 of 2,000 text draws and 128 of 2,000 decoded frames, and `api/tests/property/test_codec_fuzz.py` now exercises the case. The first PR description described an unrelated nginx change; it was rewritten to describe this test. A tautological `result.type in CLIENT_TYPES` assertion and a default `codec=None` argument were removed.
- **Verification:** `HYPOTHESIS_PROFILE=ci uv run --locked pytest tests/property/test_codec_fuzz.py -q`: 1 passed; `make check`: green. With the parser's `except ValueError` narrowed to `except UnicodeDecodeError`, `api/tests/property/test_codec_fuzz.py` fails at once with a `JSONDecodeError`.
