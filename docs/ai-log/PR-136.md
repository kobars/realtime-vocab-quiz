## PR-136 — Send security headers from the web image and check them in the smoke test

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make the web image's nginx send `Content-Security-Policy` (with `frame-ancestors 'none'`), `X-Content-Type-Options`, `Referrer-Policy` and `Permissions-Policy` from one snippet, `web/security-headers.conf`, which each location that sets `add_header` includes. Then make `scripts/smoke_images.sh` check each header on `/` and on a hashed asset.
- **Prompt / interaction:** The agent wrote the failing tests first: a static guard on the nginx config and the Dockerfile, and docker-stub tests of the smoke script. It then added the snippet, the includes and the curl checks. It checked the built image with `make build`, the smoke script, `nginx -t`, a scratch copy without one include, and a Chrome session against the image.
- **What was wrong or changed:**
  - Before choosing an enforcing CSP, the agent checked the Vite build output: `dist/index.html` and the assets have no inline scripts, no inline styles and no `data:` URIs. So the policy is enforced, not Report-Only.
  - In the first version of the smoke check, a snippet line that was not in the quoted `add_header Name "value" always;` form was skipped without notice, so a header written another way would never be checked. The agent's fix was incomplete: the review found that the smoke script still passed when the snippet was missing or no line parsed, because the header list came from a process substitution whose failure the loop ignored. The script now reads the headers into an array and fails when the snippet is unreadable or yields fewer headers than it has `add_header` lines. `test_smoke_fails_when_the_snippet_yields_fewer_headers_than_it_adds` in `scripts/tests/test_image_scripts.py` catches it.
  - The agent's static guard looked only at lines starting with `add_header `, kept them in a dict (a repeated header overwrote the first), and split `nginx.conf` on the text `location `, so a comment made a fake block and a nested block hid a later include. The review found both. `test_snippet_headers_reject_an_indented_or_repeated_header` and `test_location_blocks_skip_comments_and_keep_nested_blocks` in `scripts/tests/test_images.py` now catch them.
  - The agent's CSP left out `form-action`, which has no `default-src` fallback. The review found it; the policy now has `form-action 'self'`, and `test_web_image_sends_the_security_headers_from_every_location_that_adds_headers` asserts it.
  - In the first draft of the stub tests' response helper, the regular expression and the CRLF line ends were escaped twice, so the helper matched no header. The agent fixed this before the first run.
- **Verification:**
  - `make check`: green. `make build && scripts/smoke_images.sh`: passes. `/` and `/assets/<file>` return every header, and `scripts/check_nginx.sh` passes.
  - In a scratch copy without the include in `location /assets/`, `smoke_images.sh` fails with `/assets/<file> lacks Content-Security-Policy: ...`.
  - Before the change, the three new tests failed. `scripts/tests/test_images.py` checks the includes, the header set and the Dockerfile copy. `scripts/tests/test_image_scripts.py` checks that the smoke test passes with every header, fails when `Content-Security-Policy` is missing, and still removes its container.
