## PR-14 — Scaffold the Vue client: routes, design tokens, shadcn-vue components and the dev proxy

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Set up the client shell in `web/`: routes for join, quiz and 404 with a header layout, Pinia, the direction A tokens from `docs/spec/ui.md` §7.2 as CSS variables and the Tailwind theme, the shadcn-vue button, input, card, badge, progress and toast components, the Vite dev proxy for `/api` and `/ws`, and the client build in `make check`.
- **Prompt / interaction:** The agent worked from a written list of the routes, components, proxy and checks, plus the merged UI spec, and chose the file layout, the token mapping and the tests itself.
- **What was wrong or changed:** The shadcn-vue v4 registry has no `toast` component, so the toast is the `sonner` component and `vue-sonner` was added. The copied components failed the existing ESLint config (one-word names, optional props without defaults) and `vue-tsc` with `exactOptionalPropertyTypes`, because the reka-ui, vue-sonner and VueUse prop types pass `undefined`; the agent scoped the ESLint exceptions to `src/components/ui/` and turned that compiler option off. The first token test passed nothing to check: Vitest stubs CSS imports, `?raw` included, so the test saw empty strings and failed; `css.include` now loads `tokens.css`, and `server.fs.allow` (in the Vitest config only, not the dev server) lets the test read the spec table. The first draft was 469 changed lines, above the 400-line limit; the proxy moved into `vite.config.ts` and is tested through it, and the separate Vitest config was kept. The post-merge review found eight mistakes in this PR, fixed in a follow-up PR: the dev proxy forwarded `/api/sessions` unchanged although the API serves `/sessions` at its root (`web/src/dev-proxy.test.ts` now checks the rewrite); the proxy test's default case failed when `QUIZ_API_URL` was set in the shell or a `.env` file (the test now sets it in every case); Tailwind's `dark:` variant followed the OS dark setting in a light-only theme, and the default transition duration (150 ms) ignored the motion tokens and reduced motion (`web/src/styles/main.test.ts`); the copied shadcn-vue components kept a translucent focus ring of 2.48:1 and 36 px button and input heights, below the UI spec's 3:1 solid ring and 44 px targets, and Progress filled against 100 instead of `max` (`web/src/components/ui/ui.test.ts`); `web/index.html` had no `AI-ASSISTED` marker. A later whole-codebase review found that the proxy's default target, `127.0.0.1:8001`, had no matching way to start the API: nothing ran it on 8001 and its default allowed origins are the `:8080` ones, so the WebSocket upgrade from `http://localhost:5173` got 403; PR-116 adds `make dev-api`, and `scripts/tests/test_dev_setup.py` now catches it. A later keyboard pass found two AI mistakes in the shell, fixed in PR-154: the header link was about 24 px tall, under the 44 px touch target, and the base styles left elements focused from code with the browser's thin, translucent outline. `web/src/views/JoinView.test.ts` ("the header link is a 44 px touch target") and `web/src/styles/main.test.ts` ("gives every focus-visible element without ring classes a 2 px solid outline with a 2 px offset") now catch them.
- **Verification:** `make check` (exit 0 after rebasing on `main`: ruff, mypy, pytest, ESLint, vue-tsc, Vitest 42 passed, `pnpm -C web build`); `web/src/router.test.ts`, `web/src/dev-proxy.test.ts` and `web/src/styles/tokens.test.ts`, which fails when a token value in `tokens.css` differs from the spec; `scripts/check_internal.py` and `--commits origin/main..HEAD` pass.
