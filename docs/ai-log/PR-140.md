## PR-140 — Test exact store limits and the gateway frame size boundary

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add tests at the exact limits where the memory store and the Redis Lua scripts could drift: a snapshot at `FULL_LIST_MAX` and `FULL_LIST_MAX + 1` players, an answer at the deadline ms itself, a question served closer to the deadline than its time limit, a quiz start ahead of the server clock (the reached-time clamp), and a gateway frame of exactly `max_payload` and `max_payload + 1` bytes.
- **Prompt / interaction:** The agent worked from a list of boundaries and the source lines behind them. It wrote the contract cases over both stores, added a `move_start` step to the contract harness, replaced the far-above-limit gateway case with an exact-boundary one, then applied one mutant at a time in a scratch worktree (`>=` to `>` on the Lua deadline check, `<=` to `<` on `full_list_max`, the reached-time clamp and the remaining-time cap removed, `>` to `>=` on the gateway size check) and confirmed each makes a new case fail.
- **What was wrong or changed:** Two mistakes in the AI output, both fixed on this branch. First, the deadline case relied on the Redis `pass_deadline`, which read `TIME` and wrote `deadlineMs` in two round trips; only about 1 in 20 following scripts read the same ms, so with 50 tries the `>=` to `>` mutant still survived 1 run in 15. Repeating the mutant run showed it; `pass_deadline` now writes the server's `TIME` in one script, about every other try lands on the exact ms, and the mutant failed 20 runs out of 20 with 30 tries. Second, the start-ahead case indexed the `ranks_of` rows, which are optional per user, so mypy failed in `make check`; the case now reads the order from a standings page.
- **Verification:** `make check` (exit 0). `make test-integration`: 162 passed. The cases are in `api/tests/contract/test_store_contract.py` and `api/tests/integration/ws/test_gateway.py`; each mutant above fails at least one of them on Redis or the gateway. `scripts/check_internal.py --commits origin/main..HEAD` is clean.
