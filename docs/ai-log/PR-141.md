## PR-141 — Wait retry_ms + 1 in the Redis tick-token step-back contract test

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make `test_tick_token_holds_at_most_200_ms_after_a_clock_step_back[redis]` in `api/tests/contract/test_store_contract.py` pass reliably; it failed now and then with `Publish(status=busy, retry_ms=1)` after a fixed 200 ms wait.
- **Prompt / interaction:** The agent first reproduced the failure by repeating the test 100 times in one session against a Redis container (3 failures), then read `publish_leaderboard.lua` and the tick loop. Redis expires a key only when `now > expireat`, so the token lives through the millisecond in which its PTTL reaches 0; the tick loop already sleeps `retry_ms + 1` ms for this reason (`docs/spec/redis.md` §5), but the test waited exactly 200 ms.
- **What was wrong or changed:** The contract test written earlier assumed a token cut to 200 ms is gone after exactly 200 ms, which holds for the in-memory store but not for Redis's millisecond expiry. The test now waits `busy.retry_ms + 1` ms, as the tick loop does; the `retry_ms <= 200` assertion still checks the cut. No production change.
