## PR-142 — Update the registered metrics from scoring, the gateway and the tick

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make the four registered metrics that nothing updated report real values: `answers_total{result}` once per first scoring of an answer, `ws_connections` from accept to close, `leaderboard_frames_total` per published frame and `tick_duration_seconds` per tick; and make the metric tests read deltas instead of exact values or `Counter._value`.
- **Prompt / interaction:** The agent traced where each value is known (the scored result in `QuizService._on_answer`, the accepted socket in the gateway, the publish result in the tick loop), found that the store port could not tell a first scoring from a replay, and added a `replay` flag to `Answered` on both stores, outside the stored reply. Each metric got a test first, run red on `main` before the change.
- **What was wrong or changed:** The first version counted frames inline in `Ticker._tick`, inside the new timer block; ruff's complexity rule refused it (C901, 11 > 10), so the count moved to a small `_publish` helper. Changed on purpose: the tick test counts each publish call before awaiting it, so a call cancelled by `ticker.stop()` is still matched by the timer's observation and the histogram count must equal the call count exactly; the scrape test's exact `answers_total{result="late"} 0.0` check, which breaks once answers count on the shared registry, now checks each series by name.
