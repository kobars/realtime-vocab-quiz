## PR-144 — Accept a live tick token at PTTL 0 in the tick integration test

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make `test_publishing_continues_after_1000_writes` independent of whether `PTTL` and `EXISTS` land in the tick token's last millisecond. Test-only change.
- **Prompt / interaction:** The agent was given the failing case (the 1000 joins take about one 200 ms tick) and the cause; it replaced the assertion, then ran the test repeatedly against Redis.
- **What was wrong or changed:** The earlier AI-written check, `0 < PTTL <= 200 or not EXISTS`, assumed a key is gone once its `PTTL` reaches 0. Redis expires a key only when the clock passes its expiry time and clamps `PTTL` to 0, so a live key reads `PTTL 0` and `EXISTS 1` for up to a millisecond. The test now reads `PTTL` once and accepts `-2` or `0..200`; `-1` (no expiry) and values above one tick still fail.
