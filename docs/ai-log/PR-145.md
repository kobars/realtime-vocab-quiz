## PR-145 — Serve one quiz from two nodes: resubscribe with backoff and repair snapshots

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make two API nodes on one Redis act as one for a quiz: the fan-out loop subscribes again with full-jitter backoff after any subscribe, feed or tick failure, sends each local player a snapshot after the resubscribe, skips queued frames the snapshots hold, and treats a silent redis-py pub/sub reconnect as a drop; prove it with a two-node integration test.
- **Prompt / interaction:** The agent read the fan-out loop, the relay and redis-py's pub/sub client, found that redis-py reconnects and subscribes again without telling the caller, and made the Redis feed raise on that second confirmation. It then wrote the two-node test with two uvicorn apps in one event loop and real protocol clients, and checked that the pub/sub kill test fails on `main`.
- **What was wrong or changed:** In the first version of the two-node test, the pub/sub kill test sent an answer through the client after the kill, and the unasked repair snapshot was taken as the reply to `next` (a `KeyError` on `score`); the change after the repair now goes through the store. The first seq check reset its count at the resync's snapshot and failed when a frame published during that read arrived before the snapshot; it now tracks the newest seq seen, which is what the test is meant to prove (frames relayed in order, no gap). A fault test merged meanwhile asserted the old behavior, a loop that stops for good after a refusal; it now expects the new subscription and the snapshot. The first draft was above the 400-line budget: the convergence check joined the delivery test, and a store-level resubscribe test that the fault suite and the pub/sub kill test already cover was dropped.
- **Verification:**
  - `make check`: green. `make test-integration`: 162 passed.
  - `api/tests/integration/test_two_nodes.py`: delivery within a tick, contiguous seqs, at most 5.1 frames per second and convergence across two nodes; a snapshot on every socket after `CLIENT KILL TYPE pubsub` (fails on `main`); `rank_update` from each node to its own players; presence kept across a move within the grace.
  - `api/tests/unit/fanout/test_tick_faults.py`: a refusal from the tick logs its traceback, the loop subscribes again and sends the snapshot.
