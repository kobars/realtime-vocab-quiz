## PR-148 — Open the swarm's CPU window before its slots run when there is no ramp

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make `test_a_quiz_end_before_the_deadline_ends_the_cpu_window` reliable. It failed about one run in four with `cpu_pct` near 0.5 against a bound of 50.
- **Prompt / interaction:** The agent rebuilt the event-loop ordering of `swarm` in a standalone script and printed the CPU and wall time of the window. It then wrote the ordering assertion first, saw it fail on every run, made the fix in `load/bots.py`, and ran the test in loops on a heavily loaded machine.
- **What was wrong or changed:** The test, written with the CPU window in an earlier PR, passed by chance. With `--ramp 0`, `steady_cpu` awaited a zero timeout before its first `process_time()` sample, and the slot task finished its whole busy run during that await. The window held only about 0.1 ms of loop overhead, so its ratio was noise: 24-73% across runs, sometimes above the bound and sometimes not. A real run with no ramp had the same blind spot. `steady_cpu` now samples before its first await when no ramp is left. The first fixed version still failed 6 runs in 50: the fake player spun for 0.3 s of wall time, and under a load average near 19 the process got only a third of a core, so the fixed `> 50` bound did not hold. A second attempt with a fixed 1 s wall bound failed once in 43 runs for the same reason. The fake player now burns 0.1 s of CPU time, and the test checks `cpu_pct` against that CPU over the elapsed wall time. That bound holds however loaded the machine is, because the window lies inside the elapsed time and holds the whole busy run.
- **Verification:**
  - `make check`: green.
