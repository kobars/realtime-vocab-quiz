## PR-150 — Run two API nodes, Redis and an edge nginx as the full compose profile

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add the `full` Compose profile: `api-1` and `api-2` on one password-protected Redis, the web app, and nginx as the only published port, every service hardened (read-only, tmpfs `/tmp`, no capabilities, `no-new-privileges`, 65536 open files). Write the edge config `infra/nginx/nginx.conf`: prefix strip, WebSocket upgrade, read timeout above the heartbeat, failover, body limit, hidden metrics, rate limits, `X-Forwarded-For`, and a log format with no query string.
- **Prompt / interaction:** The agent wrote the compose profile and the edge config, then checked them against a running stack: `make build`, `docker compose --profile full up -d --wait`, curl through `127.0.0.1:8080`, `scripts/check_nginx.sh`, and a WebSocket client that rejoined through nginx after the node holding its socket stopped. It then wrote static tests of the rules that a config change could silently break.
- **What was wrong or changed:**
  - In the agent's first `.env.example`, a comment followed each empty secret on the same line. Compose's dotenv parser took the comment as the value, so `${ADMIN_TOKEN:?}` accepted the comment text as a token. `docker compose --env-file .env.example config` showed it; the comments now sit above the values, and `test_the_example_env_leaves_both_secrets_empty` in `scripts/tests/test_full_stack.py` catches it.
  - Moving the development Redis into the `dev` profile broke `make down`: in a scratch project, `docker compose down` without a profile left the profiled containers running. `make down` now passes `--profile '*'`, and `test_make_down_stops_every_profile` checks it.
  - Compose interpolates the whole file in every command, so the required `${ADMIN_TOKEN:?}` and `${REDIS_PASSWORD:?}` made `make up` fail without a `.env`, and they would have failed the `docker compose config` and `nginx -t` steps in CI. Running `docker compose config` in an empty environment showed it. `make up` and `make down` pass placeholders, and `containers.yml` sets them.
  - The review before the merge found three defects in the agent's edge. Every client of the 127.0.0.1-only port reaches nginx and the nodes from Docker's one address, yet compose did not pass `PER_IP_CONN_CAP` and the edge limit was 20 requests/s for the whole stack, so a load run stopped at about 100 sockets; `test_two_api_nodes_with_distinct_ids_share_one_redis_and_trust_only_the_stack_network` and `test_the_identity_rate_limit_lets_a_load_run_join` catch both. `proxy_next_upstream http_503` replayed a WebSocket upgrade whose single-use ticket the first node had already redeemed, and with passive failure marking one Redis blip took both nodes out; `test_a_refused_upgrade_is_not_replayed_and_a_503_takes_no_node_out` checks the fix. A node's trailing-slash redirect left `/api/` and the port; `test_a_node_redirect_stays_under_the_api_prefix_and_port` checks it, and `curl /api/healthz/` through nginx now answers `Location: /api/healthz`. Two smaller agent mistakes: `scripts/check_nginx.sh` read the compose services through a process substitution, so with the secrets unset it went on with no hosts (`test_the_nginx_check_stops_when_compose_cannot_list_the_services` in `scripts/tests/test_image_scripts.py`), and the compose comment claimed only nginx reaches the nodes, while a host process can from the bridge gateway's trusted address; the comment now states that gap.
- **Verification:**
  - `make check`: green. `scripts/tests/test_full_stack.py` (ten tests) fails on `main`, where the profile and the edge config are missing.
  - `make build && docker compose --profile full up -d --wait`: all five services healthy. `scripts/check_nginx.sh`: `nginx -t` passes on `infra/nginx/nginx.conf`.
  - Through nginx: the security headers on `/` and `/api/healthz`, 404 on `/api/metrics`, 413 for a 20 kB body, API requests alternating between the nodes, and access-log lines without a query string. A client that joined and scored rejoined through nginx in 0.1 s after `docker compose stop` of its node, with its total in `joined` and in the resync snapshot.
