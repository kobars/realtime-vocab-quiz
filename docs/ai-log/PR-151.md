## PR-151 — Scan only the history of HEAD in the secret scan

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Stop a secret-like line on one branch from failing the `secrets` check of every other pull request: `make audit-secrets` ran `gitleaks git .`, whose default log options include `--all`, and the security workflow fetches every branch. The target now passes `--log-opts='--full-history HEAD'` and keeps the full-clone guard.
- **Prompt / interaction:** The agent first reproduced the behavior in a throwaway repository with a token only on a second branch (`gitleaks git .` found it; with `--log-opts='--full-history HEAD'` it scanned no commit of that branch), then wrote the tests, ran them red against the old target and changed the Makefile.
- **What was wrong or changed:** The first version of the test file's `AI-ASSISTED` marker was 110 characters long; ruff refused it (E501, limit 100) in `make check`, and it was shortened. The test token is built at run time (`ghp_` plus random hex), so the test file holds nothing that the repository's own secret scan would flag.
- **Verification:**
  - `make check`: green. `make audit-secrets` on the branch: 0 leaks.
  - `scripts/tests/test_audit_secrets.py::test_passes_gitleaks_the_history_of_head_only`: runs the target against a gitleaks stub and pins the `--log-opts=--full-history HEAD` argument; it fails on `main`.
  - `scripts/tests/test_audit_secrets.py::test_ignores_a_secret_on_another_branch` (fails on `main`) and `::test_finds_a_secret_reachable_from_head`: the real gitleaks, skipped when it is not on the `PATH`.
