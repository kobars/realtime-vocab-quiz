## PR-152 — Accept a live tick token at PTTL 0 in the standings-limits test

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make `test_frames_snapshot_and_final_standings_use_the_configured_limits` independent of whether the `PTTL` read lands in the 50 ms tick token's last millisecond or after it expired. Test-only change.
- **Prompt / interaction:** The agent was given the failing assertion and its cause; it replaced the assertion with the check the tick integration test uses, then ran the test repeatedly against Redis.
- **What was wrong or changed:** The earlier AI-written check, `0 < PTTL <= 50`, assumed a live token always reads a positive `PTTL`. Redis expires a key only when the clock passes its expiry time and reads `PTTL 0` in the last millisecond, then `-2` once the key is gone, so a stall of about 50 ms after the publish failed the test. The test now reads `PTTL` once and accepts `-2` or `0..50`; `-1` (no expiry) and values above the configured 50 ms tick still fail.
