## PR-156 — Run the acceptance tests in make check and make test-integration, with a skip check

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Run the acceptance tests in `make check` (memory store) and `make test-integration` (Redis), each run checked by `scripts/check_junit_skips.py` for skips its store does not expect; keep the Redis acceptance harness, which flushes its database, away from the database that `REDIS_URL` names; and prove the scoring and `seq` invariants on a real Redis under 200 concurrent joins and two waves of 1,000 concurrent answers with duplicate `submissionId`s and retries.
- **Prompt / interaction:** The agent first ran the acceptance suite on both stores (13 passed on memory; 11 passed and 2 exact-time skips on Redis), so no scoring code needed a fix. It then wired the Makefile and CI, wrote the skip check test-first, wrote the invariants test, and confirmed the test fails when `score_answer.lua` is mutated to `INCR seq` (the published seqs read 1, 58, 100). The review before the merge confirmed nine findings, all fixed on this branch.
- **What was wrong or changed:** Mistakes in the AI output, all fixed on this branch:
  - The invariants test first used the shared `redis_store` fixture, whose plain redis-py pool refuses a burst above its size: the 200 concurrent joins failed with `ConnectionError: Too many connections`. The test now builds its client with `quiz.main.connect_redis`, the blocking pool the service uses, so the bursts queue the way they do in production; the first version copied that pool setup into the test instead of sharing it.
  - A target-specific `export` adds a second rule line for `check` and `test-integration`, and `scripts/tests/test_repo_config.py::test_every_make_target_is_phony_and_none_is_a_placeholder` failed because it counted those targets twice; the helper now counts each target once, and its own test covers a target-specific variable.
  - Running the acceptance tests in `make test-integration` handed the Redis harness, which runs `FLUSHDB` before each test, the database that `REDIS_URL` names: a developer's own Redis would have been wiped. The harness now gets database 15 of the test Redis, refused unless empty and emptied after each test; `api/tests/integration/test_acceptance_database.py` fails without the refusal.
  - The first version also added a CI `acceptance` job, so CI ran each store's acceptance tests twice, and the skip check ran only in that job. The skip check now runs in the Makefile step wherever the suite runs, and CI runs each store once, in the `check` and `integration` jobs; `scripts/tests/test_repo_config.py::test_each_acceptance_run_checks_its_report_for_the_skips_of_its_store` checks the wiring.
  - The invariants test left a 200-player quiz behind in one test, left its ticker and subscription open when an assertion failed, hard-coded the retried question's index, and reported a double score as an unpacking error; each is fixed in `api/tests/integration/test_invariants.py`.
- **Verification:** `make check` (exit 0; the acceptance step: 13 passed, then the skip check). `make test-integration` (exit 0; the acceptance tests on Redis: 11 passed, 2 skipped, then the skip check). The new tests are `api/tests/integration/test_invariants.py` (about 1 s), `api/tests/integration/test_acceptance_database.py` and `scripts/tests/test_check_junit_skips.py`; `scripts/tests/test_repo_config.py` checks the Makefile wiring. `git diff --stat origin/main -- api/tests/acceptance` is empty.
