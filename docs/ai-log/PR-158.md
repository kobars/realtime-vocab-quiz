## PR-158 — Add a full-stack smoke run that stops the node holding the socket

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add `load/smoke_full.py` and `make smoke-full`: against the running `full` Compose profile, read `/healthz` and `/readyz` inside both API nodes, join through nginx and answer one question, then stop the node that holds the socket and require a rejoin through nginx within 10 s, resynced, with the same total; start the node again afterwards. Document it in the README's full-stack section.
- **Prompt / interaction:** The agent rebased an earlier draft of the script onto the merged compose profile, replaced its socket count from `/proc/net/tcp` with the `ws_connections` gauge on each node's `/metrics`, split the run into testable steps, wrote tests against the in-process app, and ran the script twice against a real stack built with `make build`.
- **What was wrong or changed:**
  - The first real run failed with `quiz VOCAB-42 has ended`: the stack's Redis volume still held the quiz from an earlier run, whose window was the bot swarm's default of about three minutes. The script now creates the quiz with the longest window the server accepts (one hour), so later runs within the hour reuse it; `test_the_run_stops_the_node_with_the_socket_and_starts_it_again` in `load/tests/test_smoke_full.py` runs the whole script against the app, which accepts that window.
  - The agent first moved the shared in-process app fixture to `load/tests/conftest.py`; mypy rejected it as a second module named `tests.conftest` next to `api/tests/conftest.py`. It then lived in `load/conftest.py`, until a rebase onto a `main` with `scripts/conftest.py` made mypy reject a second top-level module named `conftest`; it is now `load/app_server.py`, which `load/tests/test_bots.py` and `load/tests/test_smoke_full.py` load with `pytest_plugins`.
  - mypy also rejected two other agent lines: a `**dict` of floats passed to `dataclasses.replace` on the bots' `Options`, and a test that patched `smoke_full.asyncio` instead of `asyncio`. Both now pass `make check`.
  - The review before the merge found these defects in the agent's script, each now covered by a test in `load/tests/test_smoke_full.py`:
    - `request()` restarted its 5 s reply timeout on every skipped broadcast, so a missing reply never timed out while broadcasts kept coming. It now has one deadline per request (`test_a_reply_that_never_comes_times_out_despite_broadcasts`).
    - The run accepted an answer that earned 0 points (a wrong or late answer on a reused quiz), and a kept total of 0 proves nothing. It now requires a correct, on-time answer with points (`test_only_an_answer_that_earned_points_counts`).
    - `make smoke-full` always aimed at port 8080, the bots' default, so it failed when the stack ran on another `QUIZ_PORT`. It now reads nginx's published port with `docker compose port nginx 8080`; `--url` and `--origin` still override it (`test_the_entry_is_nginxs_published_port_unless_an_option_names_another`).
    - A failed `join` left its socket open (`test_a_failed_join_closes_its_socket`); `docker compose` calls and the in-container probe had no timeout (`test_compose_gives_up_on_a_command_that_never_exits`); a failed restart replaced the run's own error, and a failed `docker compose stop` was reported only as a missing rejoin (`test_a_failed_stop_and_start_are_reported_around_the_runs_own_failure`, which also checks that the node is started again). `play_one` now takes `atSeq` from the `answer_result` instead of sending an extra `resync`.
- **Verification:**
  - `make check`: green (pytest 553 passed, vitest 354 passed). `load/tests/test_smoke_full.py` has eleven tests: the gauge reading against the real metrics exposition, the holder pick, a rejoin after a dropped socket that keeps the score, the kept-score check, the timeouts, the published-port entry, the scored answer, the failed join, and the whole run with faked `docker compose` calls, once passing and once with a failed stop and start.
  - After the review fixes: the stack on `QUIZ_PORT=18080`, then `make smoke-full` twice: the socket was on `api-1`, then on `api-2`; each time the player was back in 0.1 s with its total of 149.
  - `docker compose --profile full up -d --wait` then `make smoke-full` twice: the socket was on `api-2`, then on `api-1`; each time the player was back through nginx in 0.1 s with its total (150, then 149) in `joined` and in the resync snapshot, and the stopped node was healthy again.
