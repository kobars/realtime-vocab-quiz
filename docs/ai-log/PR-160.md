## PR-160 — Harden the CI supply chain: pinned actions and images, workflow lint, Dependabot, Scorecard

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Pin every workflow action to a commit SHA and every pulled image to a digest, lint the workflows in `make check` (actionlint, and zizmor failing on medium or higher findings and on unpinned actions), run CI and the container checks weekly with failures reported to one `ci-scheduled` issue, run the dependency audits on pull requests only when a lock file or a file that sets how they run changes, and add Dependabot with a 7-day cooldown, a pnpm release-age floor and an OpenSSF Scorecard workflow.
- **Prompt / interaction:** The agent resolved each action tag and image tag to the commit or multi-platform digest it pointed to, so no pinned version changed behaviour, then edited the workflows and Dockerfiles, checked each tool's real behaviour in scratch runs (zizmor on an unpinned action, pnpm 11 installs with the floor, `uv lock` with a cut-off) and wrote tests that fail when a pin is dropped.
- **What was wrong or changed:** Six mistakes in the first drafts, all fixed before review: (1) Setting `minimumReleaseAge` alone broke `pnpm install --frozen-lockfile`, because pnpm 11 checks every lock entry against the floor and 25 locked versions were under 7 days old; `web/pnpm-workspace.yaml` now lists exactly those versions in `minimumReleaseAgeExclude`. (2) The first note on lock upgrades (now in `CONTRIBUTING.md`) documented `uv lock --upgrade --exclude-newer` alone, but uv records the cut-off in `uv.lock`, after which `uv run --locked` reports the lock as out of date; the note now adds a plain `uv lock` that keeps the versions and drops the cut-off. (3) Adding the `scheduled` Hypothesis profile failed the smoke test that lists the allowed example counts (`api/tests/unit/test_smoke.py`). (4) After rebasing onto the full-stack `compose.yaml`, the shared-Redis test's pattern also matched the host name in `stack-redis:6379`; it now ignores a name that follows a hyphen (`test_the_tests_and_ci_run_the_redis_image_that_compose_runs`). (5) The same rebase reused a variable name with another type in `_pulled_images`, which mypy rejected in `make check`. (6) The Makefile relied on zizmor finding `.github/zizmor.yml` by itself, but it did not find it from a git worktree, so the settings were silently skipped (hidden at first by the medium floor); the command now passes `--config .github/zizmor.yml`, and the settings turn off the `self-repository` audit, whose suggested `$/` form actionlint 1.7.12 rejects. The review before the merge found five more, fixed on the branch: (7) `hadolint/hadolint` and `lycheeverse/lychee`, pulled with `docker run`, kept tag-only pins because the digest test read four fixed files; it now reads every Dockerfile, compose file, workflow and shell script (`test_every_pulled_image_is_pinned_by_digest`). (8) A pull request that changed the audit recipes or the security workflow, but no lock file, skipped the audits and passed the gate; the `audit-inputs` job now matches those files (`test_a_pull_request_that_changes_how_the_audits_run_runs_them`). (9) actionlint skipped shellcheck on machines without it, so `make check` could pass locally and fail in CI; `shellcheck-py` is now in the dev group (`test_workflow_lint_runs_the_locked_shellcheck_on_run_scripts`). (10) The web Trivy step ran after a failed `make build` and added a misleading second error; it now needs the build step's success (`test_web_image_scan_runs_only_when_the_images_were_built`). (11) This entry's Commit field named a commit from before a rebase. Rebasing onto `main` also brought new tag-pinned actions (the coverage job, `stack.yml`, `.github/actions/upload-test-results`), which zizmor's pin rule flagged, and a tag-pinned `load/Dockerfile`, which the digest test flagged in CI; they are pinned too, and the image decision is ADR-011 because ADR-010 was taken on `main`.
