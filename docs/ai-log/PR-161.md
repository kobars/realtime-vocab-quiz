## PR-161 — System tests and browser specs against the composed stack

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Test the composed stack (two API nodes, Redis and the edge nginx) end to end: a pytest system suite through nginx (`api/tests/system/`), Playwright browser specs with an axe scan (`web/e2e/`), the `make test-system` and `make test-browser` targets, and a CI workflow (`.github/workflows/stack.yml`) that builds the images, starts the `full` profile and runs both suites. An accepted upgrade now names its node in `X-Node-Id`, so a test knows which node holds each socket behind round-robin.
- **Prompt / interaction:** The agent read the compose file, the edge nginx config, the gateway and the web views, wrote the gateway header test first and saw it fail, then wrote both suites and ran them against a local stack. It checked that the system suite catches a broken edge by deleting the `Upgrade` header line from `infra/nginx/nginx.conf`: four tests then failed with 404 instead of 101.
- **What was wrong or changed:** (1) The first `test-system` recipe set `STACK_URL='…' $(PYTEST)`, but `$(PYTEST)` starts with `cd api &&`, so the variable reached `cd` only. It worked when `STACK_URL` was given on the make command line (make exports those), and failed with "set STACK_URL" without it; the recipe now sets the variable under `set -a`. (2) The first live-leaderboard spec matched a row's text against `/ 0$/`, but the row's cells render with no space between them (`#14Cy-…0`), so it timed out; the specs now assert on the score cell. (3) The browser target was first named `test-e2e`, which `make help` did not list, because its pattern matches only lower-case letters and dashes; it is now `test-browser`. (4) mypy rejected the first draft: a `UUID` passed as the string `submissionId`, and a list of httpx headers given websockets headers. (5) Running the system suite twice within a minute got 429 from `POST /api/tickets`: the cap test spends about half of each node's per-address ticket budget. The test's docstring and the PR description now say so. The review before the merge found six more AI mistakes: (6) both suites reused one quiz (`VOCAB-42`) with a 50-minute window and went on while it was open, but a quiz keeps its players and its window for 24 h in the stack's Redis volume, which `make down` keeps; a rerun after the window failed with advice that did not help, and each rerun added players until a new one fell out of the top 50 and the live-leaderboard spec timed out. Each suite now creates its own quiz (the system suite `BIZ-20`, the browser specs `VOCAB-42` and `ACAD-10`) and stops with the restart command when it exists: a second `make test-system` on one stack fails in the `quiz_id` fixture of `api/tests/system/conftest.py`, and a second `make test-browser` in `web/e2e/global-setup.ts`. (7) The cap test sized itself from `PER_IP_CONN_CAP` without a bound, so a raised cap opened thousands of sockets; it now skips above a cap of 100 (`PER_IP_CONN_CAP=500` skips it with the reason). (8) The workflow's path filter left out `.nvmrc` and `.python-version`, which pick the Node and Python versions of its jobs; the suites no longer import `load/`. (9) `STACK_URL` defaulted to port 8080 even when `.env` set `QUIZ_PORT`; it now defaults to `http://localhost:$QUIZ_PORT`. (10) The cross-node test left its leaderboard wait pending when the answer failed; it now runs in an `asyncio.TaskGroup`. (11) The browser setup read a quiz's status without checking the HTTP status; that read is gone, and every admin call reports its HTTP status. After the rebase onto the PR guards, the `system` marker moved out of `api/tests/conftest.py` and the pytest table of `api/pyproject.toml`, which the guards freeze with the acceptance tests: `api/tests/system/conftest.py` registers it and `api/tests/system/test_stack.py` sets it.
