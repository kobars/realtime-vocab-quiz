## PR-162 — Fix stale personal standing without you, and resend unanswered next and answers

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** In the quiz store (`web/src/stores/quiz.ts`), clear the player's rank and score on a `snapshot` with `you: null`, and after a `quiz_ended` with `you: null` that leaves out the player's row, send one spread `resync` (`QuizClient.refresh`), so the final snapshot sets the final rank. In `QuizClient` (`web/src/protocol/client.ts`), resend a `next` or an answer that gets no reply within the 5 s deadline that `resync` already used.
- **Prompt / interaction:** The agent was given both defects with the server code that produces them and the tests to write first; it wrote the failing tests, then the changes, and updated `docs/spec/ui.md` and `docs/spec/protocol.md`.
- **What was wrong or changed:** The first version made `standings()` return a boolean but left the `leaderboard` case as `return standings(...)` inside a function typed `void`; vitest passed, and `vue-tsc` in `make check` rejected it. The case now calls `standings()` and returns. Adding the reply deadline also made two existing client tests send a third `next`: they waited 5 s with an unanswered `next` to show that an older one does not repeat, and the new deadline resends the newer one at exactly 5 s. Both now wait just short of the deadline, which keeps what they check.
  The review before the merge found two more agent mistakes. (1) The first repair after `quiz_ended` sent a `join`: it had no reply deadline and no retry after a bucket `RATE_LIMITED`, every player of the node sent it on the same broadcast, and its `QUIZ_ENDED` reply showed an error notice. The repair is now a `resync` after the same random 0–250 ms wait as a gap (`SeqTracker.refresh`), which reuses the resync deadline and retries; the store test `quiz_ended with you: null and no row of mine keeps my last rank, and one resync after the gap wait repairs it with no error` and the client test `refresh sends one resync after the random gap wait, ...` catch it. (2) The answer deadline removed the first send from `inFlight` before resending, so a slow error reply to that first send was matched to the next answer and settled it; the deadline now leaves the first entry in place, and the client test `matches a late error to the first send of an answer that its reply deadline sent again, ...` catches it.
- **Verification:** `make check`: green (pytest 572 passed; vitest 364 passed). `web/src/stores/quiz.test.ts`: the snapshot and `quiz_ended` tests fail without the store change. `web/src/protocol/client.test.ts`: the three reply-deadline tests for `next`, answers and error retries, the late-error test and the `refresh` test fail without the client change.
