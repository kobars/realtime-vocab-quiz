## PR-163 — Share snapshot and page reads, bound memory-store work, give subscriptions their own pool, and hide an unconfirmed host end

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix five read-path and resource problems:
  - Snapshots fell back to one full read per client after a tick or join, and identical leaderboard pages were read once per viewer (`QuizService`).
  - The public quiz info ranked every player.
  - The memory store re-sorted every quiz on each read and never released quizzes.
  - Redis subscriptions used up the command pool, and `NOSCRIPT` recovery reloaded every script from disk.
  - A host end that was not yet durable was shown to clients as final.
- **Prompt / interaction:** The agent got each defect with its failure scenario and wrote the tests first: unit tests for the service, the memory store and the HTTP route, and Redis integration tests for the pool, the script loader and the host mark. It saw each test fail on the old code, then made the change, the spec text and one commit per part.
- **What was wrong or changed:**
  1. The first test helpers raised `AssertionError` with a literal message and read `standings` through the store module, which does not export it. ruff (EM101) and mypy caught these; the helpers now call `pytest.fail` and import `standings` from the domain.
  2. The first move of `QUIZ_TTL_MS` to the store port kept a re-export in `keys.py`, which ruff refused (PLC0414). The scripts and the three integration tests now import it from the port.
  3. The first HTTP test ended the quiz while `standings` was still patched to fail, but `quiz_ended` carries ranked entries. The test now undoes the patch first.
  4. Rebasing on `main` brought in a batched `standings` read that has its own bounded retry loop. The first snapshot retry was a second, separate loop. It was rewritten so that both use one helper, `_at_one_key`, with the per-user full read as the snapshot's last try.
  5. `test_noscript_twice_is_raised` patched `Scripts.load`, which recovery no longer calls, so it now patches `script_load`.
  6. `test_host_mark_survives_a_clock_step_back` expected an unannounced mark to read `ended`. It now expects `open`, with writes still refused at the store.
  7. A single in-flight reload shared by every `NOSCRIPT` caller was left out. It would have needed the task-sharing helper in a second layer, so each caller reloads only its own missing script.
