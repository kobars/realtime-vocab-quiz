## PR-164 — Bound the server transport, throttle upgrades, and tighten readiness, error metrics and logging

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Several server hardening fixes in one PR:
  - bound unfinished HTTP request heads (16 KiB, `HEADER_TIMEOUT_MS`) and WebSocket fragments (64 per message, close 1009) in `server_config`, and add a 5 s graceful shutdown;
  - drop uvicorn's false ERROR line after a denial response;
  - throttle `/ws` upgrade attempts per address before the ticket lookup;
  - make `/readyz` probe with a write;
  - count WebSocket error replies in `ws_errors_total{request,code}`, with a rate-limited outage warning;
  - write log lines from a listener thread through a bounded queue;
  - mark ADR-002 to ADR-008 as AI-drafted, and match the `AGENTS.md` trailer rule to the history.
- **Prompt / interaction:** The agent got each problem with its failure scenario. For each one it first wrote a test and confirmed that the test failed on `main` for the reported reason:
  - the head, fragment and shutdown tests timed out;
  - the refusal test found the ERROR line;
  - the upgrade test got `[401, 401, 401]`;
  - readiness stayed 200;
  - the counter stayed 0;
  - the blocked-sink test hit its timeout.

  Then it made the fix, read uvicorn 0.54's httptools and websockets-sansio protocols to choose the hooks, and ran the gates.
- **What was wrong or changed:**
  1. The first version of the head test sent 64 KiB of headers to a server with a 1 s deadline. It would also have passed if only the deadline worked. It now asserts that the oversized head is cut within 0.5 s, before the deadline.
  2. The first `redis.md` edit said requests get `UNAVAILABLE` while Redis refuses writes. In fact they get `INTERNAL` with close 1011 on the socket, or 500 over HTTP: a write refusal is an error reply, not a connection error. Refused writes now have their own row.
  3. The first drafts failed the linters:
     - `bounded_head` held the protocol class nested in a closure, which ruff rejected as too complex. The class is now at module level, and the factory only sets the timeout.
     - The upgrade checks pushed `Gateway.endpoint` past ruff's return limit, so they moved into `_refusal`.
     - The log writer's stop sentinel used names that mypy does not know on `QueueListener`.
  4. Design choice: stopping the log writer in the app's lifespan shutdown would lose the lines uvicorn logs after the lifespan ends. So closing the handler stops the writer instead, and `logging.shutdown` does that at exit; `test_closing_the_handler_writes_every_queued_line` checks it.
  5. Rebasing onto `main` conflicted in `endpoint.py`, `service.py` and `test_connections.py`, where a PR merged meanwhile kept cap slots for given-up closes. The changes were re-applied on top.
  6. Mistakes found in review and fixed in this PR, each with the test that now catches it:
     - `BoundedHead` measured a head only while it was still unfinished after a read, so a 22 KiB head sent at once reached the app. The finished head is now measured from its parsed URL and headers: `test_a_finished_head_above_the_limit_gets_400`.
     - It charged a whole read to the head that began in it, so a valid pipelined request after a 20,000-byte body got 400: `test_a_pipelined_body_does_not_count_toward_the_next_head`.
     - `BoundedFragments` kept handling fragments parsed from the same read after its refusal, and called `send_close` on a closing connection, which raised out of `data_received` and logged a fatal transport error: `test_fragments_past_the_limit_in_one_read_close_once_and_log_no_error`.
     - Stopping the log writer waited without limit, so a stalled stderr reader held the process exit: `test_closing_the_handler_gives_up_on_a_stalled_sink_after_its_wait`. Bounding the stop was not enough: the writer wrote through a `StreamHandler` on `sys.stderr`, and blocked on a full pipe it held locks that `logging.shutdown` waits for. It now writes each line to stderr's file descriptor itself: `test_the_process_exits_while_its_stderr_reader_is_stalled` runs a process whose stderr nobody reads.
     - The blocked-sink test asserted a 100 ms loop gap and released its sink only after its assertions. On a slow CI runner the gap was 176 ms, the sink stayed blocked, and the stuck writer made every later test that logged time out. The test now releases the sink in a `finally`, allows 0.5 s, and each log test removes the JSON handler afterwards.
     - The docs named uvicorn's `limit_concurrency`, which is never set; the readiness probe key was missing from the Redis key table; the per-address limiter formula was written twice and now comes from `address_limiter` in `limits.py`.
