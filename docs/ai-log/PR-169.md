## PR-169 — Add screenshot baselines and a WCAG 2.2 AA browser suite for every screen

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Guard how the restyled client looks: a Playwright suite on the production build with a mocked backend that compares screenshots of eleven screens at 320, 768 and 1280 px in light and dark, and checks axe (WCAG 2.2 A/AA), sideways scroll (also at 200% zoom), 44 px targets and focus rings. It runs in a Playwright image pinned by digest (`make ui-check`, `make ui-baselines`, the CI job `ui`).
- **Prompt / interaction:** The agent got the screens, the matrix, the checks and the tooling limits. It read the client's protocol flow (`join` → `joined` → `resync` → `snapshot`) to write a scripted socket mock, ran the suite in the pinned image, generated the baselines there, and then changed a colour token on purpose to show the suite fails.
- **What was wrong or changed:** (1) The first screenshot limit, `maxDiffPixelRatio: 0.01`, did not catch a broken `--muted-foreground` token: the changed text covers only 0.05–0.4% of a page, so all 33 light screenshots still passed. The limit is now `maxDiffPixels: 50`, and with the same token change every light screenshot fails. (2) axe hung until the test timeout because the paused page clock also stops the timers it waits on; the accessibility test resumes the clock before the scan. (3) The join-error screen clicked Join, but the quiz ID error that the field's blur shows moves the button down, so the click landed elsewhere and the name error never appeared; the screen now submits with Enter. (4) The last-5 s screen ran the clock exactly 15 s, and the last animation frame fell just before that, so the ring still read 6 s; it runs 15.5 s. (5) The focus-ring test started tabbing from the control the screen had focused, so on some screens the first Tab left the page and nothing was checked; it now starts from the top of the page. (6) The first container command let pnpm put its store in the repository root; the store now goes to `/tmp` in the container. The review then found more: (7) The container ran as root on the bind mount, so on a Linux host the build, the reports and new baselines were left owned by root and the next host `make check` could not empty `web/dist`; the container now hands them back to the host user on exit (`test_ui_container_hands_its_files_back_and_takes_ui_args_from_the_environment` in `scripts/tests/test_repo_config.py`). (8) The focus-ring check counted any change in `outline-color` as a ring, so a button with `outline-none` and no ring classes passed; it now compares only an outline that draws and shadows that are neither clear nor empty, and with the button's `focus-visible:ring-*` classes removed every focus test with such a button fails (`web/e2e/a11y.spec.ts`). (9) The axe test resumed the clock before every check, so on the last-5 s screen the countdown ran on (5 s to 2 s during a 3 s scan) and could reach the time-up state; the layout checks now run on the paused clock and the test fails if the time-up row appears during the scan (shown by reaching the screen with 1.5 s left). (10) `UI_ARGS` sat inside the single-quoted `sh -c`, so an argument with a quote broke the command; it now reaches the container as an environment variable (same config test). (11) The Tab walk ended silently at 40 stops and recognised a revisit by a document index that DOM changes shift; it now fails at the cap and tracks visited elements by identity. (12) At 1280 px the leaderboard screen repeated the intro screen byte for byte; it is skipped from 1024 px up and its two baselines are gone.
