## PR-171 — Keep the own score from moving backward and start the countdown at next

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** In the quiz store (`web/src/stores/quiz.ts`), stop a `leaderboard` frame or `rank_update` built before the last answer was scored (its `seq` or `atSeq` at or below that `answer_result.atSeq`) from lowering the player's score. Make the player's own row show the same score as the header when a `snapshot`'s `you` is newer than its rows. Start the question countdown from the `next` request instead of the `question` arrival, so it does not show more time than the server allows. State the rules in `docs/spec/ui.md` §3.5 and §5.3 and `docs/spec/protocol.md` §3 and §6.
- **Prompt / interaction:** The agent wrote the five store tests first and saw four of them fail on `main`. The fifth, a lower-score `snapshot`, is a guard that passes before and after. The agent then changed the store and the two specs.
- **What was wrong or changed:** The first full `make check` failed one existing test, the reconnect test in `web/src/views/PlayView.test.ts`. It moved its clock forward 8 s between the `next` sent on `joined` and the `question` reply, so under the new rule the re-served question lost those 8 s. The test checks that the re-served question keeps its stored remaining time, not a slow reply, so it now moves the clock forward before the `joined`. The first draft also declared a `const` in a `switch` case without a block, which ESLint's `no-case-declarations` rule rejects. That case now has its own block.
  The review before the merge found two more agent mistakes, fixed in this PR. (1) The store timed each question from its own `next()` call, but `QuizClient` (`web/src/protocol/client.ts`) resends a `next` itself after `RATE_LIMITED`, `UNAVAILABLE` or a 5 s silent drop, so every resend wait was cut from the countdown again (20 s of dropped requests left a fresh 20 s question at zero), and a second reply to a resend counted the round trip twice. The client now records when it last sent the `next` for a question on the current socket and passes the elapsed time with the `question` as `askedMsAgo`; the store subtracts it. The edit to the reconnect test in `web/src/views/PlayView.test.ts` was only needed for the first design and is reverted. The store tests `a next sent again after a silent drop restarts the countdown offset, so the question keeps its full time` and `a second reply to a resent next is timed from the resend, not from the first send` catch it. (2) The answer guard also applied to the player's row in a `quiz_ended` or `snapshot` with `you: null`, so after a store restart lowered `seq` below the last answer's `atSeq`, the authoritative final row was clamped to the score from before the restart. Only live `leaderboard` rows are guarded now; `final standings with you: null set my score from my row, even when their seq is below my last answer` catches it.
  (3) The fix for a `snapshot` whose `you` is newer than its rows copied only the score of `you` into the player's row and kept the row's rank, so the header could read rank 1 while the highlighted row's chip read 2, under a rival with fewer points. The store now moves the player's row to the rank of `you` and shifts the rows it passes by one (or leaves it to the pinned row when that rank is past the last row); `a snapshot whose you holds a better rank than my row moves my row there, so the header and my row agree` and `a snapshot whose you holds a worse rank moves my row down, or off the list when it is past the last row` catch it. (4) The new `docs/spec/protocol.md` §3 sentence said the answer's `atSeq` is compared only with broadcasts, but the store also compares it with a `rank_update`'s `atSeq`, a unicast; the sentence now names both comparisons. (5) The answer guard skipped the rows of a live "Show all players" page (`leaderboard_page`, reloaded at most once per second while its `atSeq` trails the standings), so a page read before the answer was scored showed the player's row at the old score under a header with the new one; the page's own row now goes through the same guard, and `a live Show all players page read at or before my last answer never shows my row below my score` catches it.
