- **What was wrong or changed:** (1) The first draft of `scripts/check_citations.py` cached the tracked files and each file's definitions in module-level `functools.cache` functions. Within one pytest process, those caches would have carried results from one throwaway test repository into the next. They now live on a `Repository` object built per run. (2) The first run on the repository reported citations in the AI-LOG history (tests renamed since those PRs merged) and the Hypothesis case `TestSessionMachine = SessionMachine.TestCase`, which is an assignment and not a class definition. The check now skips `docs/ai-log/` and accepts module-level names; `test_the_ai_log_history_is_not_checked` and the `::TestMachine` citation in `test_existing_citations_pass` cover both. (3) The first wording of the new `make check` step in `CONTRIBUTING.md` used a placeholder citation, `path.py::test_name`, which the check itself rejected; it is reworded. (4) The first version of the check's tests called `main()` without arguments, so argparse read pytest's own command line; they pass `[]`. The review before the merge confirmed nine more mistakes, fixed in this PR: (5) run from a subfolder, the check listed no Markdown and passed on zero files; it now runs from the repository root (`test_a_run_from_a_subfolder_checks_the_whole_repository`). (6) A cited file that git tracks but that is missing from the work tree raised `FileNotFoundError`; it is now reported (`test_a_tracked_file_deleted_from_the_work_tree_is_reported_not_raised`). (7) A `Class::method` citation passed when each name was defined anywhere in the file, so a method moved to another class or a nested helper still resolved; the names now resolve from the top of the file through each class body (the `TestGroup::test_kept` and `::inner` cases of `test_a_missing_file_or_test_fails`). (8) A short `::name` only followed a full citation on the same line, so a hard wrap broke it; it now follows the file cited last in the paragraph or table row, a bare `path.py` included (`test_a_short_citation_follows_a_file_cited_earlier_in_the_paragraph`, `test_a_short_citation_never_reaches_into_another_paragraph_or_table_row`). (9) The check ran after the unit and acceptance suites; it now runs right after the pre-commit hooks (`test_make_check_checks_the_test_citations_of_the_docs`). (10) The `pr_repo` fixture's docstring in `scripts/conftest.py` did not name the citation tests. (11) DESIGN.md §8 stated the 250 ms first retry without the 10 s joined reset and the extra 5 s after close 1013, and (12) cited `make smoke-full`, whose client retries on its own 250 ms loop, for the browser client's bounds; it now names `web/src/protocol/backoff.test.ts`. (13) DESIGN.md §12 leaned on single use for a ticket the failing node may not have redeemed, and said only the operator can read the error log, although a failed `stack` CI run uploads those logs as an artifact.
