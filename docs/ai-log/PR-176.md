## PR-176 — Fail load runs that miss the latency SLO and export delivery metrics

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make the bot swarm judge the 500 ms p99 leaderboard target with missing and timed-out samples counted as misses (`completion` per latency block, `slo_within` and `slo_met` in the summary, exit status 1 on a miss). Export `leaderboard_frames_conflated_total`, `resyncs_total` and the `leaderboard_publish_lag_seconds` histogram. For the histogram, the Redis `dirty` key holds the time of the first unpublished change and `publish_leaderboard` returns the lag. Update DESIGN.md §2 and §13, `load/README.md` and the Redis and protocol specs.
- **Prompt / interaction:** The agent wrote the failing tests first (the load summary and exit status, the sender and service counters, a store contract test for the lag), then the code. It chose to timestamp `dirty` in Redis because the node that accepts an answer is often not the node that publishes it.
- **What was wrong or changed:** (1) The first parse of the new `published, seq, lagMs` reply in `api/src/quiz/adapters/redis/store.py` called `int()` on the untyped reply items, and mypy rejected it in `make check`. It now parses them as the other replies do. (2) The first draft of the memory store's `leave` and `renew_presence` replaced the state on every call, with `dirty` set to "the quiz is open" or "an entry was stale". After the deadline, that would have cleared a pending `dirty`, and on each renew it would have thrown away the cached ranking. Self-review caught it before the tests ran. Both now replace the state only when they set `dirty`, as before. (3) The Redis integration tests that read `dirty` as `"1"` (`api/tests/integration/test_join_script.py`, `test_score_script.py`, `fanout/test_presence.py`) now check that the key exists. The join test also checks that a later change keeps the first change's time.
- **Verification:** `make check` (exit 0; 712 pytest, 13 acceptance and 624 Vitest tests) and `make test-integration` (exit 0; 205 integration tests, 11 acceptance tests on Redis). Tests: `load/tests/test_latency.py`, `load/tests/test_bots.py`, `api/tests/unit/adapters/test_ws_sender.py`, `api/tests/unit/app/test_service.py`, `api/tests/unit/fanout/test_tick_faults.py`, `api/tests/contract/test_store_contract.py`, `api/tests/integration/fanout/test_fanout.py`, `api/tests/integration/test_tick.py`.
- **Mistakes found in review and fixed:** (a) `load/latency.py` rounded the on-time share to four decimals before comparing it with 99%, so a run at 98.999% (989 of 999 updates on time) reported `slo_met: true`; the share is now compared unrounded and rounded only for the report, caught by `load/tests/test_latency.py::test_a_share_just_below_99_percent_misses_the_slo`. (b) The SLO share left out the totals a frame showed before their `answer_result` (`board_first`), which were delivered when the interval began, so a run with only such deliveries failed and mixed runs overstated the misses; they now count as on time, caught by `load/tests/test_latency.py::test_a_total_shown_before_its_answer_result_counts_as_on_time`. (c) `publish_leaderboard.lua` subtracted whatever `dirty` held from the Redis time, so the `1` that older scripts wrote gave a lag of about 1.8e12 ms; a value that is not a time at or after the quiz's `startMs` now gives no lag sample, caught by `api/tests/integration/test_tick.py::test_a_dirty_value_that_is_no_change_time_publishes_without_a_lag` and `api/tests/unit/fanout/test_tick_faults.py::test_a_frame_with_no_change_time_is_counted_but_not_timed`. (d) An answer whose `answer_result` was missing or timed out opened no leaderboard wait and dropped out of the SLO share, so slow replies could not fail a run; it now counts as a miss, caught by `load/tests/test_latency.py::test_an_answer_whose_reply_was_lost_or_late_misses_the_slo`. (e) A run with no leaderboard sample reported a missed SLO on a valid run; it is now invalid with `no leaderboard samples` (`load/tests/test_latency.py::test_the_slo_needs_99_percent_of_updates_below_500_ms`). (f) A `--timeout-ms` below 500 counted on-time updates as misses; the option now must be at least 500 (`load/tests/test_bots.py::test_the_cli_checks_its_options`). (g) The two-process swarm test accepted exit status 1 without checking that any leaderboard frame arrived; it now requires leaderboard samples (`load/tests/test_bots.py::test_a_swarm_over_two_processes_writes_its_result`). A cleanup made the memory store's lag expression direct and clears its change time when a host marks the end.
