## PR-177 — Add make demo and make new-quiz; default the API image to Redis and smoke-test it on Redis

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make the demo one command and give the API image a safe default. `make demo` builds and starts the full stack, starts a fresh 60-minute quiz (a run ID such as `VOCAB-42-7K3Q`, which the mock question bank resolves to the bank quiz), starts `BOTS` bots of the bot swarm image on it, and prints the quiz ID and the player URL. Alongside it come `make new-quiz`, `make demo-stop`, `scripts/seed.py` as the compose service `seed`, and a test profile that runs `make test` and the acceptance tests in a development image (`infra/dev/Dockerfile`). The API image defaults to `STORE=redis`, and `scripts/smoke_images.sh` checks that default, the image's Lua scripts and a Redis-mode `/readyz`.
- **Prompt / interaction:** The agent wrote the tests first for the bank's run IDs, the seed and the image default. It ran `make demo`, `make demo BOTS=200`, `make new-quiz`, `make demo-stop`, `make down` and the test profile against real containers, including from a fresh clone, and ran the image smoke on real images, including two images built without a Lua script.
- **What was wrong or changed:**
  1. In the development image, `pnpm -C web install` ran from the repository root. There Corepack does not read `web/package.json`, so it fetched the newest pnpm (12.8.1), which refused the project's `packageManager` (11.20.0). The image now installs that version globally with `corepack install --global`, read from `web/package.json`.
  2. Running the unit tests in that image found two problems. `scripts/tests/test_audit_secrets.py::test_fails_in_a_shallow_clone` cloned the checkout, which has no git history in an image; it now clones a throwaway repository. The seed left the reply of an `HTTPError` unclosed, which the pytest setting `filterwarnings = error` turned into a failure there; the seed now closes it, and `scripts/tests/test_seed.py` covers the 409 and 404 paths.
  3. The first version of the demo bots was a one-off `docker compose run --detach` container. It outlived `make down`, which then could not remove the stack network ("Resource is still in use"). Its stop step also trusted the exit status of `docker rm --force`, which is 0 for a container that does not exist, so it always said it had removed the bots. The bots are now a compose service that `make down` and `make demo-stop` remove (`scripts/tests/test_demo.py::test_the_bots_are_the_bot_swarm_on_the_demo_quiz_with_an_allowed_origin`).
  4. The first draft ran the bots from the new development image. After the rebase, `main` had a bot swarm image (`load/Dockerfile`), so the `bots` service now reuses the `load` service's build.
  5. The smoke first took the expected Lua list from `git ls-files`, which fails where there is no git history, as in the test image. It now lists the checkout's `lua/` folder, sorted with `LC_ALL=C` to match Python's `sorted()` in the image.
  6. The smoke started `redis:8-alpine` by tag, which the digest-pin test on `main` rejects. It now runs the digest-pinned Redis of `compose.yaml`, and `scripts/tests/test_images.py::test_the_tests_and_ci_run_the_redis_image_that_compose_runs` keeps the two the same.
- **Fixed after review:**
  1. `scripts/demo.sh` derived the connection cap from `BOTS` in steps of 1,000. `make demo` followed by `make demo BOTS=200` changed it from 1,000 to 2,000, and Compose recreated both API nodes and dropped every live socket. The cap is now 10,000 up to 1,799 bots (`scripts/tests/test_demo.py::test_the_connection_cap_stays_far_above_the_bots`).
  2. `scripts/demo.sh` built the bots image after the seed had started the quiz, so on a fresh clone the build ate into the 60-minute window. The image is now built first, and the bots start with `--no-build` (`scripts/tests/test_demo.py::test_a_fresh_clone_gets_secrets_the_stack_a_fresh_quiz_and_its_bots`).
  3. The `.env` that `scripts/demo.sh` writes, with the admin token and the Redis password, was created under the default umask (0644). It is now written under `umask 077` (same test).
  4. The `bots` service inherited the `load` build without an image name, so Compose kept two images of the bot swarm. The `load` service now names `elsaquiz-load`, which `bots` shares (`scripts/tests/test_demo.py::test_the_bots_are_the_bot_swarm_on_the_demo_quiz_with_an_allowed_origin`).
  5. `scripts/seed.py` added "Is the stack up?" to an HTTP refusal from a running stack. Only connection errors get that hint now (`scripts/tests/test_seed.py::test_another_refusal_stops_with_the_status`).
  6. `scripts/smoke_images.sh` went on silently when its Redis never answered PING, then failed later on a urllib traceback. It now stops with a clear error and the Redis logs (`scripts/tests/test_image_scripts.py::test_smoke_stops_when_its_redis_never_answers`).
- **Verification:** `make check` (exit 0: 670 pytest, 13 acceptance and 613 Vitest tests). `scripts/smoke_images.sh dev` passes on the built images. Images built without `score_answer.lua` or without `lib/points.lua` both fail it. A fresh clone's `make demo` printed a quiz ID and a player URL, with 40 players after 25 s. `docker compose --profile test run --rm test` passed 668 pytest, 613 Vitest and 13 acceptance tests.
