## PR-180 — Fail loudly on subscription limits, Redis write refusals and tick outages

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Close server paths that failed silently or with the wrong code. A node with every subscription connection taken now refuses a join to one more quiz with `UNAVAILABLE` and counts it in `feed_subscribe_failures_total`. A ticket renews the mock session. Redis `READONLY`, `OOM` and `MISCONF` replies become `UNAVAILABLE` and HTTP 503 (`api/src/quiz/adapters/redis_outage.py`). Tick failures back off with full jitter and a rate-limited warning. The snapshot cache ignores reads that started before a drop. Every writable join restarts an ended fan-out loop. Serving checks the question ID against the bank. DESIGN.md §9 to §13 and the Redis and protocol specs follow the changes.
- **Prompt / interaction:** The agent built the changes one commit per behavior, each with a test that fails without it. It chose a count of followed quizzes in the ticker over awaiting the subscribe during the join, so that the admission check runs before the store write and adds no latency to the first join of a quiz.
- **What was wrong or changed:** (1) The first draft of the session renewal in `api/src/quiz/adapters/mock_auth/memory.py` reused the variable `key` for the session's digest and then stored the new ticket under the ticket's digest but with the session's digest inside the entry, so every redeem would have failed its digest check. Self-review caught it before the tests ran; the ticket entry again holds its own digest, and `api/tests/unit/adapters/test_mock_auth.py::test_each_ticket_renews_the_session_for_its_full_lifetime` redeems a renewed session's ticket. (2) Adding the backoff to `Ticker._tick` pushed its complexity over the lint limit (ruff C901); the end handling moved to `Ticker._end` with the same behavior. (3) The first version of the bank-check test read the error text from the log message, which holds only the reference; it now reads the logged exception. (4) After the rebase, a test added on `main` built a `Ticker` without the new clock argument; it now passes one, in the commit that added the argument. The review then found more: (5) The admission check reserved nothing, and the loop opened only at the bind, after the awaited store join, so concurrent first joins of different quizzes all passed at the limit; a join now holds its subscription while it runs (`Ticker.admission`), and `api/tests/unit/fanout/test_tick_faults.py::test_a_join_in_flight_holds_its_subscription_until_the_bind_opens_the_loop` fails without the hold. (6) At the limit, a join to an ended quiz was refused although its final standings need no subscription, also on a socket that was already read only; such a join now gets the final snapshot (`api/tests/unit/app/test_service.py::test_a_join_this_node_cannot_follow_still_gets_the_final_standings_of_an_ended_quiz`). (7) A refused join on a bound, writable socket still reached `Registry.bind`, which opened a loop past the limit; `Ticker.open` now starts no loop past it (`test_tick_faults.py::test_no_loop_starts_past_the_limit_for_a_join_that_was_not_admitted`). (8) The capacity refusal kept the socket open, and the web client resends a refused join on the same socket, so it never reached a node with a free subscription; the refusal now closes with 1013 (`test_service.py::test_a_join_this_node_cannot_follow_is_unavailable_and_writes_nothing` and `api/tests/integration/test_main_redis.py::test_a_join_to_a_quiz_past_the_subscription_limit_is_unavailable` check the close). (9) The snapshot-cache fence was one counter for every quiz, so a drop of one quiz kept every other quiz's read in flight out of the cache; the fence is now per quiz (`test_service.py::test_a_drop_of_another_quiz_keeps_a_snapshot_read_in_flight_cached`). (10) `feed_subscribe_failures_total` mixed join refusals and failed subscribes in one series; it now has a `reason` label (`limit`, `error`), read by the tests above and `test_tick_faults.py::test_a_failed_subscribe_is_counted_and_retried`. (11) The admission check scanned every loop, finished ones included, on each join; a loop now leaves the ticker's table when it ends, so the count needs no scan (`test_tick_faults.py::test_a_writable_join_restarts_the_loop_of_a_quiz_whose_loop_ended` checks that an ended loop leaves).
