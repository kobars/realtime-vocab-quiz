## PR-181 — Let Dependabot PRs pass the PR guards and stop Node major updates

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Exempt Dependabot's commits from the commit-trailer check and Dependabot-only PRs from the AI-LOG check of `scripts/check_pr.py`, keep every other guard, and stop Dependabot from offering semver-major updates of the `node` image and `@types/node`.
- **Prompt / interaction:** One task description with acceptance criteria; the assistant wrote the tests first, then the exemption, the `dependabot.yml` ignore entries and the doc lines.
- **What was wrong or changed:**
  - The first version of `test_a_dependabot_pr_still_meets_the_other_rules` took six arguments and failed ruff's PLR0913 and PLR0917 in `make check`; the files and the commit message became one `change` tuple.
  - The first exemption keyed on the PR opener (a new `--author` option fed from `github.event.pull_request.user.login`), so a commit that someone else pushed onto a Dependabot branch, such as the `ci.yml` and `api/tests/conftest.py` follow-up a Redis bump needs, skipped the trailer check, and the whole PR skipped the AI-LOG check. Found in review; the exemption now follows each commit's author email, and the AI-LOG entry is skipped only when every commit is Dependabot's. `test_a_commit_pushed_onto_a_dependabot_pr_needs_the_trailer_and_the_entry` now catches it.
  - The `dependabot.yml` comment named `engines` as a Node 24 pin, but `web/package.json` allows `>=24`; the comment now names `.nvmrc`, the Dockerfiles and CI. One test hardcoded `PR-7` instead of the `PR` constant. Docs that state the trailer and AI-LOG rules (`docs/ai-log/README.md`, `CONTRIBUTING.md`) now name the exception.
- **Verification:** `cd api && uv run --locked pytest ../scripts/tests/test_check_pr.py -q` (26 passed; the new tests fail on `main`), and `make check` green. Test file: `scripts/tests/test_check_pr.py`.
