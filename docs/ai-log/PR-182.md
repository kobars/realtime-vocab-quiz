## PR-182 — Restart crashed stack services, cap Redis memory, bound slow edge clients and export delivery metrics

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Give every long-running full-stack service `restart: unless-stopped`; run the stack Redis with `maxmemory` (`REDIS_MAXMEMORY`, 256mb) and `noeviction`; set nginx's header, body and send timeouts and a `limit_conn` cap on `/api/`; make `ws_connections` span the connection cap slot and add `ws_pending_close`, `ws_send_delay_seconds`, `ws_closes_total{code}` and `event_loop_lag_seconds`; sweep the leaderboard page cache at most once per tick. Update DESIGN.md §11–§13, `docs/spec/protocol.md` and `.env.example`.
- **Prompt / interaction:** The agent wrote each test first and saw it fail (the page-cache scan count, the gauges during a given-up close, the compose and nginx checks), then changed the code. It sized `REDIS_MAXMEMORY` from a measurement: 2,000 players each answering 10 questions on a Redis 8.10 container took about 1.9 KB per player.
- **What was wrong or changed:** (1) The first draft of `test_ws_closes_total_counts_each_close_by_its_code` opened its 1009 socket on the app with a 2-byte send buffer, so the `MESSAGE_TOO_LARGE` error itself passed the hard limit and that socket closed with 1013; the 1009 case now runs on an app with the default buffers. (2) The first `/ws` send-timeout check in `scripts/tests/test_full_stack.py` matched `proxy_send_timeout` as well as `send_timeout`; it now matches the directive at the start of a line. (3) Adding the loop-lag timer as an app start and stop hook changed the hook counts that `api/tests/unit/test_main.py::test_redis_store_is_built_without_connecting` asserts; the counts were updated and a separate test checks that the timer runs only while the app runs.
