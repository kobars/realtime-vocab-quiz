## PR-183 — Fix empty, hidden and keyboard states of the play screens, add phone and full-quiz browser specs, and cap the demo bots

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix several states of the Vue client and the demo. On phones, the Leaderboard tab now shows the open question's time left as a header button that leads back to the Quiz tab, and the 10 s and 5 s warnings live in a region outside the tab panels. Keys 1–4 answer only from inside the question. A viewer of an ended quiz sees no score, and an ended quiz with no players says so. "Show all players" gets a loading status, keeps its rows while paging and drops "As of update N". The pinned own row is sticky. The app gets a skip link, and the join screen announces a quiz ID that finds no quiz. Browser specs now cover a phone (Pixel 7) and a whole quiz. `load/bots.py` gets `--cohorts`, and `make demo` passes 1, so its quiz holds one player per bot.
- **Prompt / interaction:** The agent read the play, results, join and leaderboard components, the quiz store, `docs/spec/ui.md`, the bot swarm and the compose services. It changed them with the spec, added one Vitest or pytest test per behaviour change, and ran the browser specs on a fresh full stack and the bots on a demo quiz.
- **What was wrong or changed:**
  1. The first cohort-limit loop condition, `cohort != opts.cohorts`, never played a single player with the default of 0 (no limit). The agent found it on reading the diff before the tests ran, and changed it to `opts.cohorts == 0 or cohort < opts.cohorts`. The existing swarm test in `load/tests/test_bots.py` ("a swarm plays whole quizzes against the app", default options) fails on the first form.
  2. The first "Show all players" version kept the shown page only in a watcher. On a reopen, a page already in the store for offset 0 does not change, so the watcher would not fire and the panel would show neither rows nor a loading line. The agent caught this in its own review before testing; the shown page is now `page ?? previous` (`web/src/components/leaderboard/leaderboard.test.ts`).
  3. The skip link was first hidden only by moving it above the window. `make ui-check` then failed on the 320 px feedback screenshots, because a full-page capture of a scrolled page drew it. It is now also transparent until focused, and the screenshot baselines (`web/e2e/visual.spec.ts`) match again.
  4. In `web/e2e/phone.spec.ts`, a first draft read the page width with `page.evaluate(() => document.documentElement)`, which serializes no sizes; the agent fixed this before the first run. The first run then failed on `/^\d+ s left$/`, because the button text starts with template whitespace. The anchor was dropped.
  5. Running `ruff format` from the repository root used ruff's defaults instead of `api/pyproject.toml`, and it rewrapped three files to 88 columns. The agent reverted that and ran the formatter from `api/`, as the pre-commit hook does.
  6. Existing tests that asserted the removed "As of update N" label, or an empty list while a page loads, were changed with the behaviour (`web/src/components/leaderboard/leaderboard.test.ts`, `web/src/views/ResultsView.test.ts`).
- **Verification:** `make check` (exit 0; pytest 740 passed, acceptance 13 passed, Vitest 19 files and 651 tests). `make test-browser` on a fresh stack: 6 passed, including the phone and whole-quiz specs. `make ui-baselines`: 192 passed, 6 skipped. A demo quiz with 5 bots kept 5 players.
