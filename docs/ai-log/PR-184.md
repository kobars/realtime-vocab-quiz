## PR-184 — Bound repair, presence-sweep and key-expiry work, and time load-bot frames when applied

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Keep per-tick work bounded and make the load bots measure what the web client shows. The subscription repair in `api/src/quiz/fanout/tick.py` encodes the shared snapshot once and splices each player's `you`, as the `quiz_ended` relay does. A per-quiz sweep token (`quiz:{Q}:sweep`) lets one presence renew per 3 s window, from any node, scan the `present` hash. The Lua `refresh` step re-expires the 13 data keys only once the `meta` TTL has dropped by 60 s, and gives a key a script creates the `meta`'s TTL. The load bot (`load/player.py`) holds frames after a gap or during a resync and settles a leaderboard wait only when it applies a frame. The Redis spec, DESIGN.md §9 and §11, ADR-008 and `load/README.md` follow.
- **Prompt / interaction:** The agent wrote each test first and saw it fail (15,050 entry builds for 301 players; two `HGETALL`s in one window; 26 or more `PEXPIRE`s per answer plus `next`; a 100 ms sample from a held frame), then made the change. For the expiry it chose to give a created key the `meta`'s remaining TTL rather than the full 24 h, so that no data key outlives `meta` and a reused quiz ID never finds an old key.
- **What was wrong or changed:** (1) The first change to `Player.on_seq` added the frame's own total as an argument but missed the second caller, the frame-head skim in `load/bots.py`; mypy and `load/tests/test_bots.py` caught it, and the skim now passes no total (a skimmed frame is read only while no wait is open, so it cannot settle a later one). (2) Holding a frame that arrives before the first snapshot, as `web/src/protocol/seq.ts` does, made `load/tests/test_bots.py::test_converse_reads_frames_in_full_while_an_answer_is_out` fail: its bot had no `seq` yet. The test now syncs the bot to a `seq` first, since its subject is the full read while an answer is out. (3) While checking that the sweep tests fail without the token gate, the agent edited `renew_presence.lua` in place and then restored it with `git checkout`, which put back the committed script and dropped the uncommitted sweep change; it was restored from a copy and the tests rerun before the commit. (4) The review found that the bot still applied and timed a `rebase` frame that arrived after a gap but before its resync went out, where `SeqTracker` holds every frame from the gap on; the bot now also holds frames while a resync is due, and `load/tests/test_player.py::test_a_rebase_frame_waits_while_the_resync_of_a_gap_is_due` catches it. (5) The sweep token's clock-step guard in `renew_presence.lua` cut back only a TTL above the window, so a token left without an expiry would have stopped every later sweep; it now also handles `PTTL -1`, as the tick token does, and `api/tests/integration/fanout/test_presence.py::test_a_sweep_token_without_an_expiry_gets_the_window_back` catches it. Review cleanups: `Place.you()` replaces three copies of the `Place` to `You` conversion, the `lib/quiz.lua` header names where each constant comes from, and a redundant assertion in `test_refresh.py` is gone.
