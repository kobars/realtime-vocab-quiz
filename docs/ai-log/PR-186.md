## PR-186 — Restart the stopped node without recreating it in make smoke-full

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Make `make smoke-full` (`load/smoke_full.py`) restart the API node it stops without recreating it, so a node started by `make demo` keeps the raised `PER_IP_CONN_CAP` that `scripts/demo.sh` exports only to its own compose calls.
- **Prompt / interaction:** The agent was given the defect (the restart used `docker compose up --detach --wait`, which recreated the node from the calling shell's environment and dropped the cap back to the default of 50). It changed the two smoke-run tests first, saw them fail, switched the restart to `docker compose start --wait`, and checked the result on a real stack. The review then replaced that command with `docker compose up --detach --wait --no-recreate`.
- **What was wrong or changed:** The original restart command chose `up`, which recreates a container whose computed configuration differs from the running one. The first fix used `docker compose start --wait`, but `start` only has `--wait` since Compose v5 while the stack asks for Compose v2, so on a v2 release the restart failed and left the node stopped; `start` also could not bring back a container removed while stopped. The fix now uses `up --detach --wait --no-recreate`, which starts the same stopped container with its settings, creates it only when missing, and works on every Compose v2 with `up --wait`; `test_the_run_stops_the_node_with_the_socket_and_starts_it_again` now fails on the `start` command. A test docstring that stated the cause backwards was corrected.
- **Verification:** `make check` (exit 0; 760 pytest, 13 acceptance and 656 Vitest tests); `load/tests/test_smoke_full.py` (10 passed; `test_the_run_stops_the_node_with_the_socket_and_starts_it_again` and `test_a_failed_stop_and_start_are_reported_around_the_runs_own_failure` fail with the old command); `make demo BOTS=5` then `make smoke-full` (passed): both API nodes printed `PER_IP_CONN_CAP=10000` before and after, with unchanged container IDs (with `start --wait`); for `up --detach --wait --no-recreate`, a probe compose project showed a stopped container started with `CAP=10000` coming back from a shell without `CAP` with the same container ID and `CAP=10000`, and a removed container being created again.
