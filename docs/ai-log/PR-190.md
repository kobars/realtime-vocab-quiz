## PR-190 — Dark-theme polish: one focus indicator, calmer shadows, password-manager opt-out, real quiz ID hint

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix four classes of visual defect on every screen. (1) Password managers offered to fill the join fields. (2) Focus stacked a box-shadow ring and an offset on top of a control's own outline, and two links painted a white offset in dark. (3) Hard offset shadows read as ghost boxes on the dark page and stacked in nested surfaces. (4) The join hint named a quiz ID that real runs never have. The PR also writes the depth and focus rule into the UI spec and amends ADR-010.
- **Prompt / interaction:** The agent traced each defect to its class names and tokens. It replaced the ring classes with the page's `:focus-visible` outline plus a `focus-hug` utility for outlined controls, redefined the dark shadow tokens as a glow and a 2 px edge, and dropped the nested shadows. It then rebuilt and checked the screenshot baselines of every screen in both themes at 320, 768 and 1280 px.
- **What was wrong or changed:**
  - The first draft of the test that dark shadow layers have no sideways offset split the token on commas outside one level of parentheses. A `color-mix()` that holds `var(--primary)` nests two levels, so the test cut layers in the middle and failed on correct tokens. It now collapses nested parentheses before the split.
  - A plain `make ui-baselines` rewrote only the join screens. The softer dark shadows differ from the old baselines by less than Playwright's per-pixel threshold, so the old dark baselines still passed while showing the old look. The dark baselines were rewritten with `--update-snapshots=all`, and the light screens that were not meant to change were left as they were.
  - Review fixes. `focus-hug` built the band by recolouring the border, and the compiled CSS put it before `aria-selected:border-border` and `hover:border-primary-hover` at the same specificity, so the selected tab and a hovered outline or secondary button showed a two-tone band; the border transition also showed two colours for 120 ms. The focus outline now widens to the border width plus 2 px at a negative offset of the border width, so it paints over the border.
  - The selected phone tab drew a 3 px outline inside the track's 3 px outline. The track keeps the one outline on the page colour and the selected tab is a card fill with the press shadow; on a muted track the dark card fill was nearly invisible.
  - The pinned "you" row sticks to the bottom of the window with nothing around it, so the row it covered showed half above it at every width. It now sits on an opaque, sticky card-coloured dock with 8 px above and below. Full-page screenshots draw sticky elements where the window ended, so two browser checks in `web/e2e/visual.spec.ts` cover what a baseline cannot: the point just above the pinned row is the dock, and the selected tab's border is transparent.
  - The shadow utilities dropped the ring slots (no ring utility is left); the dark-shadow test splits on top-level commas and accepts a unitless zero; a shared `stackedFocusClasses` helper replaces three diverging regular expressions; two tests check that the quiz preview and the "Show all players" panel cast no shadow inside their card; the UI spec's §6.2 focus rule and §7.3 dark-block list match the code.
  - The tab change also differs from the old baselines by less than the per-pixel threshold, so the 320 and 768 px play screens were rewritten with `--update-snapshots=all`.
- **Verification:**
  - `make check` (exit 0; 775 pytest, 13 acceptance and 667 Vitest tests).
  - `make ui-check` (200 passed, 10 skipped: the two new browser checks have no tabs to check from 1024 px; axe, a focus ring on every Tab stop, 44 px targets and screenshots in both themes).
  - Tests: `web/src/views/JoinView.test.ts`, `web/src/components/join/join.test.ts`, `web/src/components/ui/ui.test.ts`, `web/src/styles/main.test.ts`, `web/src/styles/tokens.test.ts`, `web/src/views/PlayView.test.ts`, `web/src/components/leaderboard/leaderboard.test.ts` and `web/e2e/visual.spec.ts`. The new dark-shadow test fails on the old tokens (`6px 6px 0 ...`), the new focus tests fail on the old ring classes, and the tab, nesting and focus-hug tests fail with the old classes put back.
