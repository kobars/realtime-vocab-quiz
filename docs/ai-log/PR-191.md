## PR-191 — One-command VM install with cloud-init, update with rollback, backup and restore

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Replace the eight manual steps of "Deploy to a VM" with `scripts/deploy/install.sh`, a one-command install for a fresh Ubuntu 22.04 or 24.04 VM. It installs Docker and the tools, clones into `/opt`, writes `.env` once with new secrets and a domain (the given one or `<ip>.sslip.io`), checks root, OS, ports and DNS, runs `make prod-up` and waits for readyz. Also add cloud-init user data for a Droplet; `make prod-update`, which rolls back when the new commit does not get ready; `make prod-backup` and `make prod-restore`; shellcheck in `make check`; and the operations guide for all of it.
- **Prompt / interaction:** The agent built on the existing `prod-*` targets and `.env.prod.example`. Before writing the backup and restore, it tested Redis 8's restore behaviour in throwaway containers. It then ran a real backup and restore against a separate compose project with the same hardened Redis and Caddy settings, and validated the cloud-init file with `cloud-init schema` in an `ubuntu:24.04` container.
- **What was wrong or changed:** (1) The first restore design copied only `dump.rdb` back into the volume. A throwaway container showed that Redis with AOF on ignores the RDB and starts empty (0 keys), so the restore now loads the snapshot with AOF off and turns AOF on to write a new AOF, and the round trip keeps the data. (2) The first argument parser used the `;;&` case fall-through, which only bash 4 has. Sourcing the script in bash 3.2 (the macOS shell the tests may use) would fail with a syntax error, so it now uses two plain `case` blocks. (3) The first test helper sourced the script with `bash -c '. "$0"'`. That made `BASH_SOURCE` equal `$0`, so the script's `main` ran (and its root check failed) when only the helpers were wanted; the helper now passes the path as `$1`. (4) mypy rejected the test runner's `**env` keyword arguments, because they could fill its `cwd` parameter; the environment is now an explicit dict. (5) On macOS, `tar` added `._` AppleDouble members to the backup in the test; the test sets `COPYFILE_DISABLE=1` (Linux hosts do not add them). CI found two more: (6) the runner's shellcheck warned SC2120/SC2119 on `check_os`, which took an optional argument that no caller passed (the locked shellcheck 0.11 did not warn); the caller now passes `/etc/os-release`. (7) Every commit put a blank line between the `AI-Assisted:` and `Co-Authored-By:` lines, so git did not read `AI-Assisted:` as a trailer and the PR guard rejected the commits; the messages were rewritten with both lines in one trailer block.
- **Review fixes:** The two reviews' findings, each checked against the code, were fixed in this PR. (8) Restore deleted the live AOF before the backup's snapshot had loaded, and waited for `PING` with no bound, so a corrupt `dump.rdb` hung it with the data already gone. It now loads the snapshot in `/data/.restore`, stops waiting when Redis exits (or after 10 minutes), swaps in the new AOF only once it is written, and on failure puts the previous `.env` back and restarts. A throwaway Redis 8.10 container confirmed both paths: a garbage `dump.rdb` exited 1 in under a second with the live keys intact, and a real snapshot replaced them. (9) Backup sent a plain `BGSAVE`, which Redis refuses while an AOF rewrite runs; it now sends `BGSAVE SCHEDULE`, reads `INFO` once per pass and has a real 5-minute deadline. (10) `tar` kept an older backup file's 0644 mode; the archive is now a new 0600 file. (11) The dev image's build copies the whole context, so `backups/` and `.env.before-restore` are now in both Docker ignore files. (12) A restore onto a new VM brought back the old VM's `<ip>.sslip.io` name; the new VM now keeps its own. (13) `git pull --ff-only` fails on a tag install's detached HEAD; `prod-update` now reuses `install.sh`'s `checkout()` and takes `REF`. (14) Restore ran `compose down` before `.env` existed, which compose refuses; it now stops the stack only when `.env` exists. (15) `FILE` was read after the `cd` to the repo; it is now relative to the caller's folder. (16) `curl get.docker.com | sh` ran an empty script when the download failed; the script is now downloaded first. (17) The DNS check used `getent`, which reads `/etc/hosts`, where the VM's own host name maps to 127.0.1.1; it now asks Google Public DNS's JSON API first. (18) `ops.sh` copied the Makefile's compose file list; the Makefile now exports `PROD_COMPOSE`. (19) The offline Ubuntu test failed instead of skipping when the Docker CLI was present but its daemon was not.
- **Verification:** `make check` (exit 0 after the review fixes; 818 pytest, 13 acceptance and 657 Vitest tests; shellcheck clean). `scripts/tests/test_deploy.py` (43 tests): stubbed checks of the IPv4, domain, DNS, OS and port logic, of the `.env` render, of each update and rollback path and of a backup and restore round trip, plus an offline `install.sh --dry-run` in an `ubuntu:24.04` container. `cloud-init schema` reported `Valid schema`.
