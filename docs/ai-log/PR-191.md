## PR-191 — One-command VM install with cloud-init, update with rollback, backup and restore

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Replace the eight manual steps of "Deploy to a VM" with `scripts/deploy/install.sh`, a one-command install for a fresh Ubuntu 22.04 or 24.04 VM. It installs Docker and the tools, clones into `/opt`, writes `.env` once with new secrets and a domain (the given one or `<ip>.sslip.io`), checks root, OS, ports and DNS, runs `make prod-up` and waits for readyz. Also add cloud-init user data for a Droplet; `make prod-update`, which rolls back when the new commit does not get ready; `make prod-backup` and `make prod-restore`; shellcheck in `make check`; and the operations guide for all of it.
- **Prompt / interaction:** The agent built on the existing `prod-*` targets and `.env.prod.example`. Before writing the backup and restore, it tested Redis 8's restore behaviour in throwaway containers. It then ran a real backup and restore against a separate compose project with the same hardened Redis and Caddy settings, and validated the cloud-init file with `cloud-init schema` in an `ubuntu:24.04` container.
- **What was wrong or changed:** (1) The first restore design copied only `dump.rdb` back into the volume. A throwaway container showed that Redis with AOF on ignores the RDB and starts empty (0 keys), so the restore now loads the snapshot with AOF off and turns AOF on to write a new AOF, and the round trip keeps the data. (2) The first argument parser used the `;;&` case fall-through, which only bash 4 has. Sourcing the script in bash 3.2 (the macOS shell the tests may use) would fail with a syntax error, so it now uses two plain `case` blocks. (3) The first test helper sourced the script with `bash -c '. "$0"'`. That made `BASH_SOURCE` equal `$0`, so the script's `main` ran (and its root check failed) when only the helpers were wanted; the helper now passes the path as `$1`. (4) mypy rejected the test runner's `**env` keyword arguments, because they could fill its `cwd` parameter; the environment is now an explicit dict. (5) On macOS, `tar` added `._` AppleDouble members to the backup in the test; the test sets `COPYFILE_DISABLE=1` (Linux hosts do not add them).
- **Verification:** `make check` (exit 0; 810 pytest, 13 acceptance and 657 Vitest tests; shellcheck clean). `scripts/tests/test_deploy.py` (35 tests): stubbed checks of the IPv4, domain, DNS, OS and port logic, of the `.env` render, of each update and rollback path and of a backup and restore round trip, plus an offline `install.sh --dry-run` in an `ubuntu:24.04` container. `cloud-init schema` reported `Valid schema`.
