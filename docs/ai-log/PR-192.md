## PR-192 — Take input strictly: no type coercion in HTTP bodies, visible display names, clear version error

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Stop the HTTP request bodies from coercing JSON types (`true`, `"90000"` and `1.0` were taken as integers); require at least one visible character in a display name, on the server (mock session and `join`) and in the join form, while keeping invisible characters inside a visible name; answer a non-integer protocol `v` with `INVALID_MESSAGE` and keep `UNSUPPORTED_VERSION` for an integer other than 1, and make protocol §7 say so.
- **Prompt / interaction:** The agent traced the name check to its two copies (the mock session's `display_name` and the service's `join` handler) and moved them into one domain rule. It chose to refuse invisible-only names instead of stripping format characters, because stripping would break zero-width-joiner emoji sequences and the direction marks of mixed-script names. It then made the two request models strict and split the codec's version check.
- **What was wrong or changed:** The first draft of `api/tests/unit/test_names.py` wrote the zero-width and direction-mark characters into the source unescaped; ruff refused them (PLE2502, PLE2515) and the test now uses `\u` escapes. The extra version branch pushed `parse_client_message` over the complexity limit (C901), so the version checks moved into their own helper. The first strict-body test expected `GET /quizzes/VOCAB-42` to answer `open` after a refused create; a quiz that was never created answers 404, which is what the test now checks. The review found that the rule counted unassigned (Cn) and private-use (Co) code points as invisible, so the server (Python 3.14, Unicode 16.0) refused a Unicode 17 emoji that the browser accepts, and `U+F8FF`, accepted before, was refused; only control, format, surrogate, separator, combining and blank characters are invisible now. It also found that control characters inside a visible name passed (tab, line break, ESC), that `str.strip()` and `String.prototype.trim` remove different characters (U+001C–U+001F and U+0085 against U+FEFF), and that the server and client tests listed their own cases with some invisible characters unescaped. Control characters are now refused anywhere, the server trims the JavaScript set, and both sides run `docs/spec/display-names.json`. The session-body test passes in lax mode too, since Pydantic's lax `str` already refuses non-strings; its comment now says it pins the 422 shape.
- **Verification:** `make check` (exit 0, 704 web tests); `make test-integration` (exit 0; 217 passed, acceptance on Redis 11 passed and 2 skipped as expected); without the strict models the six coerced-integer cases in `api/tests/unit/adapters/test_http_routes.py` fail with 201.
