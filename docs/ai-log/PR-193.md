## PR-193 — Publish prebuilt images to GHCR and create the Droplet with doctl from a laptop

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Publish the API and web images to GHCR from the containers workflow (multi-arch, scanned, with SBOM and provenance attestations, `packages: write` only on the publish jobs); run the public host on those images by `IMAGE_TAG` through `compose.images.yaml`, with `--build` / `BUILD=1` to build on the host and a rollback to the images that ran; add `make do-deploy` and `make do-destroy` (`scripts/deploy/droplet.sh`) that drive an already signed-in `doctl`; document the image tags, the laptop path, the measured memory and ADR-012.
- **Prompt / interaction:** The agent extended the existing containers workflow, compose override, prod make targets and deploy scripts rather than adding parallel ones, resolved the action SHAs from each action's latest release, measured memory on an isolated copy of the stack (its own compose project with no host ports, 300 bots from the load image), and tested the DigitalOcean script against a stub `doctl` only, creating no cloud resource.
- **What was wrong or changed:** (1) The first `ops.sh up` ran `make build` and the compose steps as plain lines; `update` calls it inside `if up && ready`, where `set -e` does not apply, so a failed build went on to start the old images and reported success. `scripts/tests/test_deploy.py` (the `BAD_UP` update case) caught it; each step now returns on failure. (2) The first `droplet.sh` set an EXIT trap that removed a `local` temporary file; the trap runs after the function returns, so `set -u` failed on the unbound name and the deploy exited 1 after succeeding. `scripts/tests/test_droplet.py` caught it; the path is now a script-level variable. (3) `render_env` first treated a missing tag argument as an empty one, which would have switched a restored host to building its images; it now leaves `IMAGE_TAG` and `COMPOSE_FILE` alone when no tag is passed. (4) A first `ruff format` from the repository root used the default settings and rewrote twelve unrelated test files; those were restored and the changed files formatted with `api/`'s settings. (5) `make check` failed on SC1091 when pre-commit put `ops.sh` and `install.sh` in different batches; `.shellcheckrc` now sets `external-sources`. CI found three more: (6) the runner's shellcheck flagged SC2015 on an `A && B || C` check in `ops.sh` (the locked shellcheck did not); it is now two statements. (7) CodeQL read a test's `"https://203.0.113.7.sslip.io/" in out` as incomplete URL sanitization; the assertion now matches the whole "live at" message. (8) Under `make check` on CI, the test's inner `make -n` inherited the outer make's flags and printed "Entering directory" lines (macOS's make 3.81 did not); it now runs with `--no-print-directory` and without `MAKEFLAGS`.
- **Verification:** `make check` (exit 0). `scripts/tests/test_droplet.py` (16 tests, also under macOS's `/bin/bash` 3.2), `scripts/tests/test_deploy.py`, `scripts/tests/test_repo_config.py`, `scripts/tests/test_full_stack.py` and `scripts/tests/test_images.py`; actionlint and zizmor clean on the new jobs. The publish jobs run for the first time on `main` after the merge.
