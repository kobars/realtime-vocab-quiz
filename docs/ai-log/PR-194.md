## PR-194 — Extract the Clay design system into a workspace package with a component gallery

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Move the Clay tokens, Tailwind theme, font and components out of the app into the pnpm workspace package `@quiz/clay` with a typed `exports` map, keep the app on its public entry points (ESLint and a guard test), give the package its own tests, a README and a changelog, add a component gallery with every token and every variant and state in light and dark side by side, and cover the gallery in the pinned Playwright run, without changing how the app looks.
- **Prompt / interaction:** The agent moved the files with `git mv`, rewired the app's imports, CSS entry, Vitest projects, ESLint, the Dockerfile and the Playwright container, built the gallery, and compared the app's built CSS and screenshot baselines with the base after each step.
- **What was wrong or changed:**
  - The moved `@font-face` rules kept the bare `@fontsource-variable/nunito/...` URL. Tailwind inlines the theme into the app's CSS entry, so Vite resolved the URL from the app, which no longer depends on the font package; the build left the URL unresolved and emitted no font files. A diff of the built CSS against the base caught it. The URL is now relative to the package, and `web/packages/clay/src/styles/theme.test.ts` checks it.
  - After the move, Tailwind's automatic source detection from `web/` also scanned the package's gallery and README, so the app's CSS gained classes only the gallery uses. The app's entry now scans only `web/src` (`source('.')`) and the theme adds its components with `@source`; `web/src/design-system.test.ts` checks the entry.
  - The gallery's shadow specimens built their class names with a template string, which Tailwind cannot find, so four of the six tiles had no shadow. They are literal class names now; the gallery baseline shows all six.
  - The container change for the package's `node_modules` broke `scripts/tests/test_repo_config.py`, which pins the container's `chown` list; `make check` caught it, and the test now also requires the package's volume.
  - Moving the root Vitest config's `server.fs.allow` into the package's project dropped it from the app's, so after rebasing, the join form's validation (which reads its display-name rules from `docs/spec/`) failed to load in tests; `make check` caught it and the app project allows the folder again.
  - The gallery's full-page screenshot and axe scan exceeded the 30 s test timeout once under amd64 emulation; the spec marks its tests slow.
  - The review found that the app's raw-value guard skipped a `contracts/generated` folder that does not exist while scanning the real generated file, `src/protocol/types.generated.ts`, and let `bg-white`, `text-black`, stock durations and delays (`duration-500`) and side-specific stock radii (`rounded-t-3xl`) through. It now skips every `*.generated.ts` file, refuses those classes and pins its patterns with examples on both sides.
  - The review found that the font test matched only the text of the URLs, although a wrong path still builds and ships no font; it now checks that each file exists (with a broken path it fails).
  - The review found that the gallery spec skipped the narrow projects' baseline inside the test, after `beforeEach` had loaded the page and waited for its toasts; a describe-level modifier now skips before `beforeEach`. The gallery page wrote out each section next to a list of their ids and titles; it renders them from that list, and its baseline is unchanged.
  - The review found four component files the move changed without the AI-ASSISTED marker, two comments that still named `main.css` and `main.test.ts`, and a sentence in CONTRIBUTING.md that the gallery paragraph had split; all are fixed.
  - After rebasing onto `main`, where ADR-012 now records the image registry, the extraction's decision record is ADR-013.
  - The review's claim that `sideEffects: ["**/*.vue"]` keeps every component in the entry chunk did not hold: a build with only `**/*.css` listed emits byte-identical chunks, and the chunk sizes match the build before the move. The claim that the PR should be split was not taken: the moves and the lock file account for much of the size, and the PR carries the size-exception label.
