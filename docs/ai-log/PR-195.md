## PR-195 — Add a host page: create a quiz from a question set, share it, end it

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Build the client side of self-service hosting against the fixed HTTP contract (`GET /api/banks`, `POST /api/quizzes`, `POST /api/quizzes/{id}/end` with `X-Host-Token`). The work covers a quiet "Host a quiz" link on the join screen; a `/host` page to pick a question set, share the quiz (ID, link, copy button, client-side QR code) and watch the player count; End quiz with a confirm step; and every error state with its own copy. The host token stays in `sessionStorage`. The page has unit, visual and accessibility tests, a full-stack browser spec, and a UI spec section.
- **Prompt / interaction:** The agent built the page against mocked HTTP while the API side was built in parallel. It read the existing join screen, the preview client and the clay primitives, and reused them. It picked `uqr` (no dependencies) for the QR code, rendered as one SVG path in the role colours. Each set is one large button, so hosting takes a single click.
- **What was wrong or changed:** The join screen's new bank-list request broke five existing `JoinView` tests that counted every `fetch` call. Their stub now answers the bank list apart from the quiz lookups, which are counted on their own. In the first polling test, earlier tests' host panels stayed mounted. They answered the test's `visibilitychange` event and polled through the new fetch stub, so the count was wrong; `enableAutoUnmount` now unmounts each test's app. Polling first started at mount even in a hidden tab; it now starts and stops with the page's visibility only. The first screenshots showed the quiz ID broken over two lines at 320 px, so phones now use the 24 px size. They also captured the confirm screen scrolled, with the pointer hovering "Keep it open"; the screen now moves the pointer away and scrolls to the top first. The review found four defects in the host flow. The storage helpers read `sessionStorage` in a default parameter, outside their `try`, so with storage blocked `/host` failed to render and a created quiz lost its host token; storage is now resolved inside each `try`, as the join screen already does. A create that answered after the visitor had left `/host` was dropped with its only host token; it is now saved before the unmount check. "Keep it open" stayed active while the end request ran, though the end could no longer be called off; it is now disabled. An empty bank list showed the network message with a retry that could never succeed; it now reads as hosting off. The ended card's "See the results" opened the join screen, so it is now "Open the player link". After the rebase the full-stack host spec failed: pressing "Host a quiz" blurred the focused, empty quiz ID field, whose blur check added a message that pushed the link down before the mouse button came up, so the click was lost. A field left empty is now flagged by the submit only; a throwaway spec in the mocked suite failed without the change and passed with it. Not changed: a 403 on End keeps the panel, which still shares a live quiz and moves to the ended card when the window closes; a stored quiz is not dropped by the client clock alone, since a clock ahead of the server would throw away a live host token; the join screen's bank-list request is one small GET per visit.
- **Verification:** After the rebase onto the `@quiz/clay` package, whose lint rule moved the host page's imports to it: `make check` (exit 0, 1,086 web and design-system tests). The visual and accessibility suite in the pinned Playwright image passed 280, with 14 skipped.
