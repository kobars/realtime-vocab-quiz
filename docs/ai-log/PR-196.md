## PR-196 — Let any visitor host a quiz: public create with a host token, host end, limits

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add self-service hosting to the API, against a fixed HTTP contract:
  - `GET /banks`.
  - `POST /quizzes {bankQuizId}`: a run under the seed script's run-ID scheme, with a host token kept only as its SHA-256.
  - `POST /quizzes/{quizId}/end` with `X-Host-Token`: the admin route's durable host end.
  - Limits: `PUBLIC_HOSTING`, a per-address creation limit through the existing limiter and trusted-proxy rules, and a cap on open self-hosted quizzes across nodes in Redis.
  - Strict bodies and the Origin check.
  - The settings in compose and both `.env` examples.
  - The HTTP and Redis specs, operations and DESIGN.
- **Prompt / interaction:** The agent built to a fixed contract of paths, fields, headers and error codes, because the web host page is written against it in parallel. It reused the store's create and host-end paths, the address limiter, the error format and the seed's run-ID helpers, which moved into the API package.
- **What was wrong or changed:**
  - (1) The first `hold_hosted` on Redis queued its commands in a `MULTI` pipeline. mypy rejected each queued command as an unused awaitable. It also differed from the memory store at the cap: add-then-count against check-then-add. It is now one Lua script, `hold_hosted.lua`, that checks before it adds, the same as the memory store. Both pass the same contract tests.
  - (2) The first bank listing added `quiz_ids` to the `QuestionBank` port. That broke three test fakes of the port, so the offered bank quizzes are now a setting, `HOSTING_BANKS`, and a bank quiz left out of it cannot be hosted.
  - (3) `scripts/tests/test_design_components.py` failed: the DESIGN component rows did not name `GET /banks` or the `hold_hosted` script. Both rows now do.
  - (4) The integration test that sends `GET /quizzes` expected 404. That path now takes `POST`, so it answers 405, and the test now checks an unknown path below a quiz.
  - (5) A rebase onto strict request bodies made `HostIn` use the strict request config too.
- **Verification:**
  - `make check`: exit 0.
  - `make test-integration` with its own Redis container: exit 0.
  - `api/tests/unit/adapters/test_hosting.py` covers create, bad bodies, banks, the per-address limit, the cap, the end, wrong tokens, the Origin check, hosting off, no token in the logs, and run-code collisions.
  - `api/tests/integration/http/test_hosting_redis.py`: two nodes share one cap, and either node ends the quiz.
  - `api/tests/contract/test_store_contract.py` covers the hash, the cap and the window lapse on both stores.
- **Reviewed by:** Claude Code `/code-review` (high) and Codex (`gpt-6-astra`, xhigh reasoning), before the merge. Each finding was checked against the code; the fixed ones have tests:
  - Two requests that drew the same run code both held it in `quiz:hosted`. The loser's failed create released the member that the winner's open quiz needed, so the cap undercounted. The loser now releases it only when the quiz that took the code has no host token.
  - Only the visitor's end route released a quiz's place, so an admin end, or a release that failed after the end, kept it counted for the whole window: the retry stopped at 409 first. `end_by_host` now releases the place in both stores once the end is announced, and the 409 path releases it again.
  - `hold_hosted.lua` set the key's expiry to the newest member's window. After a lower `HOSTING_WINDOW_MS` that dropped quizzes still open; the key now expires at its highest score.
  - `compose.yaml` did not pass `HOSTING_BANKS` to the nodes, and nothing checked that its entries are quiz IDs. Both are fixed; the `.env` examples list the window and bank settings.
  - The per-address creation limit is an in-process token bucket, so the full stack's two nodes allow twice the limit. The docs now say it is counted on each node.
  - A local name in the bank listing shadowed the route's OpenAPI responses; renamed.
  - Not changed: the limit counts refused attempts too (422, 503), which bounds the store work any one address can cause, as the protocol now states; a slot held when the create fails on a store outage stays counted until its window ends, since the create may have run; the 409 on a repeated end is the contract; the copied address-limit dependency differs in its limiter, code and header; the PR's size is one feature, labelled as an exception.
