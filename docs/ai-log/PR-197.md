## PR-197 — Deploy to Fly.io: web edge, two API Machines and Redis behind Fly's HTTPS proxy

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add Fly.io as a second deploy target. One config per app in `infra/fly/`: web, two API Machines and Redis on a volume, all with auto-stop off. A Fly edge config that takes the client address from `Fly-Client-IP`, trusted only from Fly's proxy. `scripts/deploy/fly.sh` with `--dry-run`, behind `make fly-launch`, `fly-deploy`, `fly-demo`, `fly-status` and `fly-destroy`. Tests, the operations section, a DESIGN.md note and ADR-014.
- **Prompt / interaction:** The agent checked Fly's docs for the fly.toml keys, Flycast, `Fly-Client-IP` and the proxy's source range, and read flyctl's own `--help` offline for each flag; it ran no flyctl command that needs a login. It tried the Redis start command and the rendered nginx config in throwaway containers before writing the tests, and modelled the script and its stub-based tests on the existing DigitalOcean script.
- **What was wrong or changed:** (1) The first script set its own `READY_TIMEOUT` default after sourcing `install.sh`, which had already set it, so the new default never applied; the dry run printed the old value and the duplicate line was removed. (2) The first `deploy` passed the image arguments through an unquoted command substitution, which splits a checkout path that contains spaces; they are arrays now. (3) The first dry run printed absolute checkout paths; the script now runs from the repository root and prints relative ones. (4) `make check` failed on typos, which read "6PN" (Fly's private network) as a misspelling; `_typos.toml` allows it. (5) The first try at the Redis command would have left `/data` owned by root on a Fly volume, because the image's entrypoint does not hand over a folder that holds `lost+found`; a Docker run with such a folder showed it, and the data now lives in `/data/redis`, owned by the redis user. (6) After the rebase, `make check` failed when `docker info` took over 30 s on a busy host: the Docker check raised the timeout instead of skipping. A daemon that does not answer now counts as not running. (7) Another ADR took the number 013 on `main` first, so this decision is ADR-014.
- **Verification:** `make check` (exit 0). `scripts/tests/test_fly.py` (31 tests, also under macOS's `/bin/bash` 3.2; the `nginx -T` test needs Docker). Checked by hand in Docker: `Fly-Client-IP` is used from a 172.16.0.0/16 peer and ignored from another subnet. The first real deploy needs a logged-in Fly account.
