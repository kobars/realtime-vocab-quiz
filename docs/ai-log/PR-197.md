## PR-197 — Deploy to Fly.io: web edge, two API Machines and Redis behind Fly's HTTPS proxy

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add Fly.io as a second deploy target. One config per app in `infra/fly/`: web, two API Machines and Redis on a volume, all with auto-stop off. A Fly edge config that takes the client address from `Fly-Client-IP`, trusted only from Fly's proxy. `scripts/deploy/fly.sh` with `--dry-run`, behind `make fly-launch`, `fly-deploy`, `fly-demo`, `fly-status` and `fly-destroy`. Tests, the operations section, a DESIGN.md note and ADR-014.
- **Prompt / interaction:** The agent checked Fly's docs for the fly.toml keys, Flycast, `Fly-Client-IP` and the proxy's source range, and read flyctl's own `--help` offline for each flag; it ran no flyctl command that needs a login. It tried the Redis start command and the rendered nginx config in throwaway containers before writing the tests, and modelled the script and its stub-based tests on the existing DigitalOcean script.
- **What was wrong or changed:** (1) The first script set its own `READY_TIMEOUT` default after sourcing `install.sh`, which had already set it, so the new default never applied; the dry run printed the old value and the duplicate line was removed. (2) The first `deploy` passed the image arguments through an unquoted command substitution, which splits a checkout path that contains spaces; they are arrays now. (3) The first dry run printed absolute checkout paths; the script now runs from the repository root and prints relative ones. (4) `make check` failed on typos, which read "6PN" (Fly's private network) as a misspelling; `_typos.toml` allows it. (5) The first try at the Redis command would have left `/data` owned by root on a Fly volume, because the image's entrypoint does not hand over a folder that holds `lost+found`; a Docker run with such a folder showed it, and the data now lives in `/data/redis`, owned by the redis user. (6) After the rebase, `make check` failed when `docker info` took over 30 s on a busy host: the Docker check raised the timeout instead of skipping. A daemon that does not answer now counts as not running. (7) Another ADR took the number 013 on `main` first, so this decision is ADR-014. (8) A deploy of the branch to Fly.io found four faults that the stub-based tests could not: flyctl refuses an image reference with both a tag and a digest, so Redis is now named by its digest alone; `flyctl apps list --quiet` pads each name with blanks, so a second `launch` tried to create the apps again and `destroy` found nothing, and the names are trimmed now; flyctl reads a `[[files]]` `local_path` from the directory it deploys (the repository root), not from the config's folder, so the path is `infra/fly/nginx.conf.template`; and the edge config replaced the image's `nginx.conf` without loading `mime.types`, so scripts and stylesheets went out as `text/plain` and the page stayed blank. With those fixed, the page, `/api/readyz`, `/api/sessions` and `/ws` answered through the proxy. (9) The review found that `launch` wrote `.env.fly` before creating the apps, so a prefix already taken elsewhere left a file that refused every other prefix; it is written once the apps exist, and the secrets come from the script's existing `new_secret` helper instead of openssl. HSTS was sent only from `location /`, while Caddy sends it on every response on the VM; `/api/` and `/ws` send it too. The edge-drift test compared the configs as sets of lines and missed a dropped repeat of a line; it compares them in order now. The backup steps downloaded `dump.rdb` right after `BGSAVE`, which returns before the snapshot is written; they use `redis-cli --rdb`, which returns once the file is complete (tried in a throwaway container). The ADR now states that nginx, with one Flycast server, cannot retry on the other node. Not changed: the PR is over the 400-line limit and carries the size-exception label; keeping the Fly edge as its own template, pinned line by line against the VM's, is the ADR's choice, so the VM config stays as it is.
- **Verification:** `make check` (exit 0). `scripts/tests/test_fly.py` (32 tests, also under macOS's `/bin/bash` 3.2; the `nginx -T` test needs Docker). Checked by hand in Docker: `Fly-Client-IP` is used from a 172.16.0.0/16 peer and ignored from another subnet. Each fault in (8) and (9) outside the docs has a test that fails without its fix.
