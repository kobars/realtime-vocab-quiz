## PR-199 — Show the top 10 and open all players in place of that list

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Stop "Show all players" from listing the standings a second time under a list that already holds them, and give the live board and the results the usual shape: the top 10, my row pinned under them when I am further down (highlighted in place inside the top 10), the podium kept, and "Show all players" offered only when some players are not in the top 10. The server's frames keep their top 50.
- **Prompt / interaction:** The agent first wrote a component test that renders the results of 22 players and opens "Show all players", ran it on `main` to see it fail, then changed the leaderboard components, the tests, the browser spec, the screenshot baselines and the UI spec.
- **What was wrong or changed:**
  - Reproduction on `main` (`deff6f53`): `web/src/views/ResultsView.test.ts` › `"Show all players" shows each player once, never under a list that already holds the same rows` failed with `AssertionError: expected [ DOMWrapper{ …(3) }, …(1) ] to have a length of 1 but got 2` for `li[data-user="p5"]`.
  - Root cause: the results rendered ranks 4–50 under the podium, and `AllPlayers` opened its panel inline below that list with page 1 of the full standings (ranks 1–100), so with up to 50 players every row after the podium was on screen twice. The live board had the same overlap with its top 50.
  - Fix: `AllPlayers` reports its open state with `v-model:open`, and the live board and the results hide their top 10 and the pinned row while it is open; the display limit is `TOP_ROWS = 10`, and the pinned row is a shared `PinnedRow` component behind a decorative gap mark.
  - The first run of the new live-board test counted 11 rows: my old row was still fading out with its leave class; the test now skips leaving rows, like the existing pinned-row test.
  - Hiding the button at 10 players or fewer broke the existing tests that opened the panel with 3 players (the keyboard test in `PlayView.test.ts`, the paging tests and the after-the-end test); they now run with more than 10 players.
  - With ten rows the sticky dock around the pinned row covered rows in the full-page screenshots (the old baseline had the same artefact over row 7); the pinned row now simply follows the tenth row, and `web/e2e/visual.spec.ts` checks that it sits under it.
  - The browser spec needs more than 10 players, which would push later specs' players on `VOCAB-42` out of the top 10 (the phone spec looks for its own highlighted row), so global setup opens a third quiz, `BIZ-20`, for it alone.
  - The review before the merge (Claude Code `/code-review` high and Codex) found four more mistakes, now fixed:
    - A join to an ended quiz gets the final `snapshot` and `QUIZ_ENDED` but no `joined`, so the client has no user ID. The pinned-row rule looked for my user ID in the top 10, found none, and pinned a second, nameless copy of a row the top 10 already showed (`#4 Ana 997` and `#4 (you) 997`). `PinnedRow` now owns the rule and decides from my rank (above 10), which my row in the list always matches; without `joined` it takes my name from the row at my rank. The same rule had been copied into both screens.
    - The browser spec's quiz, `BIZ-20`, is the one the system tests create, so the two suites failed when run on one stack in the documented order. It now uses `VOCAB-42-CROWD`, a run of the `VOCAB-42` bank that no run code can produce (codes are four characters without O), and global setup refuses an existing one with the restart advice, because the spec counts its players exactly. `CONTRIBUTING.md` lists it.
    - The rule for offering "Show all players" was repeated in both screens, and a frame that counted 10 players or fewer removed the button even with the focus on it (a store restart can lose the last second of joins). `AllPlayers` now decides it and keeps the button once offered.
    - The browser spec did not check the players' own ranks; it now checks the first player highlighted at #1 with no pinned row and the last one pinned at #11, outside the top 10.
  - Review points left as they are: the pinned row no longer sticks to the bottom of the window (a choice of this PR: under ten rows it follows the tenth row, as the UI spec now says); the layout check runs only where the Leaderboard tab exists, and the 1280 px baselines show the board beside every play screen.
