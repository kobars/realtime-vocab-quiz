## PR-20 — Generate the JSON Schema and TypeScript types and check them for drift in CI

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add `scripts/gen_contracts.py` and the `make contracts` recipe, which write `contracts/schema/protocol.json` and `web/src/protocol/types.generated.ts` from the Pydantic wire models, and a CI step that runs `make contracts && git diff --exit-code` so the committed files always match the models.
- **Prompt / interaction:** The agent wrote the generator against the merged message models, chose a custom schema generator that leaves out per-field titles so the TypeScript output has one type per message, and rebased the change onto `main` after the models and the parser had been merged, regenerating the files to confirm they still matched.
- **What was wrong or changed:** The generator was first written in the same change as the models and the parser, which went over the 400-line limit per PR; it was split into this PR and rebased onto the merged models. Regenerating after the rebase produced no diff. No mistakes were found in the generated output.
- **Verification:** `make check` (exit 0) and `make contracts && git diff --exit-code` (no diff, also on a second run). The source models are covered by `api/tests/unit/contracts/test_messages.py` and `api/tests/unit/contracts/test_roundtrip.py`.
- **Found after the merge:** The post-merge review confirmed three mistakes in the AI output. (1) The CI drift step used `git diff --exit-code`, which ignores untracked files, so a generated file that was never committed, or a committed one that was deleted and then regenerated, passed. (2) The drift check ran only in CI, not in `make check`. (3) The generator built new `TypeAdapter`s instead of reusing `CLIENT_ADAPTER` and `SERVER_ADAPTER`, which the codec validates with. A follow-up PR fixed all three: `gen_contracts.py --check` fails on any changed, deleted or untracked generated file, `make check` runs it, and the schema is built from the exported adapters with byte-identical output. `scripts/tests/test_gen_contracts.py` now catches (1) and (2), in `test_check_fails_when_a_generated_file_is_not_committed` and `test_check_fails_on_a_stale_generated_file`.
