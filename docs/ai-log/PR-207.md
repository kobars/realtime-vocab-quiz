## PR-207 — Fail over from a killed API node in 250 ms instead of 2 s

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** After a hard kill of one API node, clients waited about 2 s, the full `proxy_connect_timeout`, before nginx tried the other node, and some `POST /api/tickets` got 504 after 2 s. Shorten the connect timeout in both edge configs, decide whether the two identity POSTs need a retry on the other node, and measure both effects on an isolated two-node compose stack.
- **Prompt / interaction:** The task came with a suggested fix: a shorter connect timeout, plus `proxy_next_upstream ... non_idempotent` on `POST /api/sessions` and `/api/tickets`. The agent measured first. nginx's error and access logs, and nginx's round-robin source, showed that the 504s were connects never sent. They failed because the resolver dropped the killed node's name while they waited, not because POST is non-idempotent. A test run with the retry directives confirmed it, so the PR changes only the timeout.
- **What was wrong or changed:**
  - The suggested retry would not have fixed the 504s → the 504 lines named one upstream and `while connecting`; a run with `non_idempotent`, `proxy_next_upstream_tries 2` and `proxy_next_upstream_timeout 1s` still gave 11 and 12 504s against 12 → left out, and the reason is in `DESIGN.md` §11 and the PR text (`scripts/tests/test_full_stack.py`).
  - The first load script sent tickets from 8 workers in a closed loop. A worker stuck on the dead node sends nothing more, so the 504 count was capped at 8 and could not show the effect of the timeout → the counts matched the worker count exactly → replaced by an open loop of 100 requests a second, where the count followed the timeout (93 against 12).
- **Verification:** `make check` (exit 0); `scripts/check_nginx.sh` on the built web image (successful); `scripts/tests/test_full_stack.py::test_a_killed_node_holds_a_request_a_quarter_second_before_the_other_node` and the two Fly edge tests in `scripts/tests/test_fly.py` failed before the change and pass after it; three kill rounds before and after on an isolated stack (numbers in the PR).
