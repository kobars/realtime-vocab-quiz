## PR-22 — Add the reconnect backoff policy and the seq tracker of the protocol client

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add `web/src/protocol/backoff.ts` (full-jitter backoff, the close-code rules, the 1013 overload wait and the counter reset after 10 s joined) and `web/src/protocol/seq.ts` (`SeqTracker`: broadcasts applied in `seq` order, buffering until the snapshot, gap, restart and lost-last-frame resyncs, `rebase` frames, `quiz_ended`), with Vitest tests for each rule.
- **Prompt / interaction:** The agent implemented the reconnect and resync rules of the protocol spec (§3 and §7) as two pure modules that take the random source and the clock from the caller, so each rule is tested without sockets or timers; the socket client that schedules the waits comes in a later PR.
- **What was wrong or changed:** The first version of the branch also held the tab identity module and came to 470 changed lines, over the 400-line limit; the identity moved to its own PR. The spec says the client resets on `joined.atSeq` and also sends the last applied seq in the following `resync`; the tracker returns that resync from `joined()` before it resets, so both hold. The post-merge review found one AI mistake: `SeqTracker` did not remember an applied `quiz_ended`, so a snapshot read before the end that answered a resync still in flight lowered `lastSeq` below the final seq and replayed buffered pre-end `leaderboard` frames over the final standings (spec §3: an announced end is never undone). A follow-up PR keeps the final seq, ignores a later `status: open` or older snapshot and drops later `leaderboard` frames; `web/src/protocol/seq.test.ts` ("always applies quiz_ended and sets lastSeq, even while resyncing" and the tests after it) now catches it.
