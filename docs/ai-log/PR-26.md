## PR-26 — Fix pong and snapshot sequencing rules in the protocol spec

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix the three confirmed post-merge review findings of #5 in `docs/spec/protocol.md`: a newer `leaderboard` frame conflated ahead of a queued `pong`, `pong.seq` taken from the node's relay cache instead of the quiz's counter, and an in-flight `snapshot` undoing an applied `quiz_ended`; align `docs/spec/redis.md`, `docs/spec/ui.md` and ADR-004.
- **Prompt / interaction:** The agent worked from the verified review table, checked each finding against the protocol, Redis and UI specs, chose one fix per finding (conflation barrier, a Redis read for `pong.seq`, a client rule after `quiz_ended`), and searched the other specs for every rule that depended on the old `pong` semantics.
- **What was wrong or changed:** While choosing the `pong.seq` source, the agent first planned to keep `pong.seq < lastSeq` as a restart signal next to the Redis read. Tracing the order of events showed that the counter read and the pub/sub relay arrive on different Redis connections, so a frame can reach the socket ahead of a `pong` that read an older counter; the rule would fire false resyncs. The spec now ignores a lower `pong.seq` and detects a restart from `seq < lastSeq` and the node's snapshot after its Redis reconnect, and the Redis spec's failure table and the UI spec's `pong` transitions were updated to match.
- **Verification:** `make check` (exit 0 after rebasing on `main`), which runs `scripts/tests/test_ui_spec.py` against the changed UI state chart; `scripts/check_internal.py --commits origin/main..HEAD` (exit 0). Documentation only: no gateway or client code implements these rules yet.
- **Reviewed by:** fix check only, after the merge: another Claude Code agent re-tested on `main` each of the three defects that the review of PR #5 found; all three are fixed in the spec, and the two that still reproduced in client code merged meanwhile were fixed in PR #41. No `/code-review` or Codex round ran on this PR.
