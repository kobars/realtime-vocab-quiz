## PR-27 — Add the tab identity and a fresh ticket before each connect

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add `web/src/protocol/identity.ts`: `connectTicket` keeps the mock identity (`userId`, `sessionToken`) in `sessionStorage`, calls `POST /sessions` once per tab and `POST /tickets` before every connect, and replaces an unknown session (401) once; `httpAuthApi` is the `fetch` implementation of the two calls. Vitest tests for each rule.
- **Prompt / interaction:** The agent implemented the authentication steps of the protocol spec (§8) as a module that takes the HTTP calls and the storage from the caller, so each rule is tested with a fake `AuthApi`, a fake `fetch` and the test environment's `sessionStorage`.
- **What was wrong or changed:** The first version cast the `POST /sessions` and `POST /tickets` replies to their types without checking them, so a reply without `sessionToken` would have been stored as a partial identity and a reply without `ticket` would have returned `undefined` as the ticket. Both replies are now validated (non-empty strings) and an empty stored value counts as broken; a test covers each case. The post-merge review found that two overlapping `connectTicket` calls on one storage each created a session (the last `setItem` won, so the callers held different identities), also when both replaced a session the server had forgotten; a later fix shares the session creation in flight per storage, and the tests "gives overlapping connects one session, each with its own ticket" and "replaces a forgotten session once when overlapping connects both get a 401" in `web/src/protocol/identity.test.ts` catch it.
- **Verification:** `make check` (exit 0); `pnpm -C web exec vitest run src/protocol/identity.test.ts` passes 12 tests in `web/src/protocol/identity.test.ts`.
