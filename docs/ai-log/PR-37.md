## PR-37 — Add the protocol client: socket lifecycle, reconnect, seq wiring and liveness

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add `QuizClient` in `web/src/protocol/client.ts`: a fresh ticket and the `quiz.v1` subprotocol on every connect, a 5 s open timeout, reconnect waits from `Backoff`, `SeqTracker` wiring (one `resync` per `joined`, delayed gap resyncs, a 1 s retry of a rate-limited `resync`), an app ping every 25 s and a reconnect after 50 s of silence. Vitest tests on a fake socket and fake timers.
- **Prompt / interaction:** The agent wrote the tests first from protocol spec §3, §7 and §9, then the client over an injected socket factory, random source and clock; it mutated the client by hand (removed each rule in turn) to confirm that a test fails without it.
- **What was wrong or changed:** The first version repeated a rate-limited `resync` with the tracker's current `lastSeq`, which after `joined` is already the new `atSeq`, not the value that was sent; it now repeats the sent value. The test for that retry first passed even with the retry removed, because it checked only the last message sent; it now expects two `resync` messages. The socket interface first typed the handlers as zero-argument callbacks, which the browser `WebSocket` does not satisfy; `vue-tsc` caught it. The first draft also held the answer retries and came to about 490 changed lines; they move to a follow-up PR.
- **Found after the merge:** The review found seven defects in this PR's client, all fixed in PR-51 with a test that now catches each one. A resync answered with `UNAVAILABLE` was never retried (`retries a resync after UNAVAILABLE with backoff, until the snapshot`). The pong check of `SeqTracker` was never scheduled (`resyncs when the broadcast that a pong announced has not arrived 1 s later`). `start`, `stop`, `start` during a pending ticket request opened two sockets, and a stale ticket failure closed the new one (`opens one socket after start, stop, start while the first ticket request is pending`, `ignores a stale ticket failure after start, stop, start`). A snapshot read before the end reached the UI after `quiz_ended` (`emits a snapshot read before the end after quiz_ended no more, and applies a status ended one`). `send` wrote to a socket that was still connecting, and the fake socket did not throw there as a browser does (`drops next() while the socket is still connecting instead of throwing`). `SeqTracker.joined` set the last applied seq from `joined.atSeq` (`sends one resync with the last applied seq on every joined`). Option defaults were evaluated eagerly, so `url: undefined` opened `undefined?ticket=…` and `sessionStorage` was read even with a `storage` given (`falls back to the default url when url is undefined`, `never reads sessionStorage when a storage is given`). The tests are in `web/src/protocol/client.test.ts` and `web/src/protocol/seq.test.ts`.
