## PR-38 — Memory store: standings reads, dirty-gated publish and the two-step end

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Finish the in-memory `Store`: `standings_page` and `snapshot` (each read at one `seq`, the 200 / top-50 policy), `publish_if_dirty` (the `ended` / `busy` / `clean` / `published` order of `publish_leaderboard` with a 200 ms tick token) and `end_quiz` (the host end marks first and announces on the second call, the deadline end is `not_due` before the deadline), with shared contract tests.
- **Prompt / interaction:** The agent ported the four methods from an earlier working draft of the whole store onto the merged write path, wrote the contract tests first and checked that they failed against the `NotImplementedError` stubs before adding the code.
- **What was wrong or changed:** (1) The draft's leave test never ended the quiz, so a leave after the end was untested; `test_leave_sets_dirty_only_while_open` also leaves after a host mark and checks that the leave still frees the seat and that the announcement takes the next `seq` (3 after the last frame's 2). Correction after the merge: this entry first said the check proves that no frame comes before the announcement. It cannot: a marked quiz never publishes a frame, so whether a leave after the mark sets `dirty` is not observable through the store port, and the test no longer claims it. (2) The draft's `end_quiz` test did not check `end_quiz(deadline)` between the host mark and the deadline; it now expects `not_due`, as docs/spec/redis.md §3.1 says. Found after the merge: (3) The host mark was kept only by moving the state's deadline to `now`, so a clock step-back after `end_quiz(host)` reopened the quiz: joins, answers and frames were accepted again. The mark is now a field of the domain state that `is_open` checks; `test_host_mark_survives_a_clock_step_back` in `api/tests/contract/test_store_contract.py` catches it. (4) The tick token was an absolute time, so after a clock step-back `publish_if_dirty` returned `busy` with `retry_ms` far above 200 and frames stalled for the length of the step. The store now clamps the token to `now + 200` ms; `test_tick_token_holds_at_most_200_ms_after_a_clock_step_back` catches it.
