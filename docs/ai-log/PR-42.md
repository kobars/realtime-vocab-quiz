## PR-42 — Add the mock vocabulary question bank

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Implement the `QuestionBank` port as a mock: three seeded quizzes of ten word-to-meaning questions in `api/src/quiz/adapters/mock_questions/data/*.json`, validated at load (quiz ID pattern, question IDs of the form `vocab42-01` in serve order, four distinct choices, an answer index of 0-3, no unknown fields, no duplicate quiz IDs).
- **Prompt / interaction:** The agent wrote the validation tests first, then the Pydantic models and the loader, and wrote the seed quizzes; it checked with `uv build` that the JSON files ship in the wheel.
- **What was wrong or changed:** (1) The first draft had two parsers, `parse_quiz` for a dict and `parse_quiz_json` for text, with the same body; the loader now calls `parse_quiz(json.loads(...))`, and a JSON syntax error surfaces as the same `ValueError` with the file name. (2) A distractor word in `biz-20.json` and the rejected question-ID literal in the test matched the repository's content-guard patterns (`scripts/check_internal.py` in `make check`); both were replaced (the test now rejects `Q42`). (3) The first change also held the mock identity and ticket stores and came to 567 changed lines, over the 400-line limit; those stores moved to their own PR.
- **Found after the merge:** The post-merge review confirmed three mistakes in the AI output, fixed in a follow-up PR. (1) The models ran in Pydantic lax mode, so an `answer` of `"2"`, `true` or `1.0` loaded as answer index 2, 1 or 1 instead of failing; `answer` is now a `StrictInt`, and the new rejection cases of `test_bad_quiz_is_rejected` catch it. (2) The correct answer indexes of the seed quizzes cycled in a fixed pattern (`VOCAB-42` 0,1,2,3,0,1,...), which every player could predict once the first answers were revealed; the choices were reordered, and `test_seeded_answer_positions_follow_no_pattern` catches a periodic sequence. (3) A folder with no `*.json` file loaded as an empty bank, so missing data files showed up only as `QUIZ_NOT_FOUND` at join; the load now raises a `ValueError` that names the folder, caught by `test_empty_folder_is_rejected`. All three tests are in `api/tests/unit/adapters/test_mock_questions.py`.
- **Verification:** `make check` (exit 0, 297 pytest tests); `scripts/check_internal.py --commits origin/main..HEAD` (clean); `api/tests/unit/adapters/test_mock_questions.py` (18 tests, 13 of them rejection cases) passes.
