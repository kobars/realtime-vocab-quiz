## PR-43 — Mock identity and single-use ticket stores, in memory and in Redis

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Implement the `TicketStore` port as a clearly labeled mock: 24 h sessions that issue single-use 30 s tickets for the same user on every connect, tokens of 32 random bytes in base64url keyed by SHA-256 digest and confirmed with a constant-time comparison, in an in-memory variant (injected clock) and a Redis variant (`SET … EX`, `GETDEL`).
- **Prompt / interaction:** The agent wrote both variants and one shared test suite parametrized over them, with the Redis variant running against a fake client whose `EX` expiry follows the test clock; a second pass rebased the branch on `main`, re-read the diff and re-ran the checks.
- **What was wrong or changed:** The NFC test wrote its decomposed input (`e` plus a combining accent) as a raw literal, which an editor that normalizes on save would silently turn into the composed form, so the test would pass without exercising normalization; the input and the expected name are now `\u` escapes. The post-merge review found two more AI mistakes, fixed in a follow-up PR: the in-memory store removed an expired session only when its token came back, so sessions piled up for the life of the process (now caught by `test_memory_variant_drops_expired_sessions_and_tickets`); and the digest-only key test checked the ticket but never the session token, so a session key holding the raw token would have passed (`test_redis_variant_uses_set_ex_and_getdel` now checks both).
- **Verification:** `make check` (exit 0, 313 pytest tests); `make test-integration` (exit 0); `scripts/check_internal.py --commits origin/main..HEAD` (clean); `api/tests/unit/adapters/test_mock_auth.py` (25 cases over both variants: single redeem, 30 s expiry, unknown ticket, one user per session, unknown or expired session, wire format, display-name rules, `SET`/`GETDEL` calls with digest-only keys) passes.
