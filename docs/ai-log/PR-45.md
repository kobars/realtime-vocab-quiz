## PR-45 — Add the development Redis, the script loader and the create_quiz script

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add the development Redis (`compose.yaml`, `make up` / `make down`, `.env.example`), the quiz key schema, the Lua script loader with one `NOSCRIPT` retry, the shared Lua prelude and points library, the `create_quiz` script, and one Redis test fixture that starts its own container per test session or uses `REDIS_URL`.
- **Prompt / interaction:** The agent wrote the scripts and tests against `docs/spec/redis.md` §2–§3, ran them against a throwaway `redis:8-alpine` container, and cut the change down to a first slice when the full adapter slice came to 674 changed lines.
- **What was wrong or changed:** (1) The first version also held the `join` script, the store class and the contract harness and was 674 lines, over the 400-line limit; it was split, and the `create_quiz` tests were rewritten to call the script through the loader instead of the store class. (2) The fixture's `docker` calls tripped ruff S603/S607 (partial executable path); they now go through one helper that resolves `docker` with `shutil.which` and fails the session with a clear message when Docker is missing. (3) The fixture first started the container with an explicit `--appendfsync everysec`; it was dropped because `everysec` is the Redis default once `appendonly yes` is set. (4) Found after the merge and fixed in PR #55, each with a test that now catches it: `create_quiz` read its TTL from a fifth ARGV the spec does not define, so a call with the four spec ARGV failed after writing keys without a TTL (`api/tests/integration/test_create_quiz.py`); answers were checked with `tonumber()` but stored raw, so `"0x2"` was accepted (`api/tests/integration/test_create_quiz.py`, `numeric-strings`); the fixture leaked its container when startup failed after `docker run` (`api/tests/unit/test_redis_fixture.py`); a `REDIS_URL` Redis ran with AOF off (`api/tests/integration/test_script_loader.py::test_test_redis_runs_with_aof_on`); the development Redis used an anonymous `/data` volume; the Lua `K` table copied the key order by hand (`api/tests/integration/test_script_loader.py::test_lua_key_indexes_follow_quiz_keys`).
- **Verification:** `make check` (exit 0, 306 pytest tests); `make test-integration` with `REDIS_URL` unset (18 passed, container removed afterwards): `api/tests/integration/test_create_quiz.py`, `api/tests/integration/test_script_loader.py`, `api/tests/integration/test_points_parity.py` (Lua points equal `score_answer` for every elapsed value from -1 to T + 1); `scripts/check_internal.py --commits origin/main..HEAD` (clean).
