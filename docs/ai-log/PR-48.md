## PR-48 — Fix the question bank's answer validation, answer positions and empty load

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix three defects confirmed in the post-merge review of PR-42: the bank models accepted a string, bool or float `answer` (Pydantic lax mode), the seed quizzes' correct answer positions cycled in a predictable pattern, and a folder with no `*.json` file loaded as an empty bank without an error.
- **Prompt / interaction:** The agent wrote one test per defect first and saw all five new cases fail on `main`, then made `answer` a `StrictInt`, swapped each correct choice into a new position in the three seed files with a short script that asserted the correct word moved with its index, and added the empty-folder check to `MockQuestionBank.load`.
- **What was wrong or changed:** The first idea for the pattern test (fail only when the whole answer sequence is periodic) would have passed `BIZ-20`, whose cycle starts after its first answer; the test instead counts, for each period 1-4, how often an index repeats that many questions later and allows at most half. `ConfigDict(strict=True)` on the models was not used, because strict mode in Python validation rejects the JSON arrays for the tuple fields; `StrictInt` on `answer` is enough, as the string fields already reject numbers.
- **Verification:** `make check` (exit 0); `api/tests/unit/adapters/test_mock_questions.py` (23 passed; 5 of them failed before the fix); `scripts/check_internal.py --commits origin/main..HEAD` (clean).
