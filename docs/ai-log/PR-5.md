## PR-5 — Add the WebSocket protocol spec and ADR-003, ADR-004

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Write `docs/spec/protocol.md`, the v1 wire contract of the self-paced quiz (envelope, field types, message catalog, `seq` and `atSeq` rules, standings policy, conflation, countdown, error and close codes, ticket authentication, limits, sequence diagrams), and ADR-003 and ADR-004 in `docs/DECISIONS.md`.
- **Prompt / interaction:** The agent worked from a written list of the protocol rules (message names, `seq` rules, answer semantics, codes, limits, the standings policy) and the merged domain spec, and drafted the catalog, the client rules, the diagrams and both ADRs itself.
- **What was wrong or changed:** The first draft of the client's `seq` table ignored every `leaderboard` frame with `seq` at or below the last applied one, with an exception for new sockets; that contradicted the rule that a lower `seq` means the store restarted. It now ignores only `seq = lastSeq` (a duplicate relayed right after a snapshot) and resyncs on a lower one. The draft also let a `pong` overtake a `leaderboard` frame held back for a slow socket, so `pong.seq > lastSeq` could fire a needless resync; the conflation section now keeps the held frame's place in the queue. The post-merge review found three more sequencing mistakes in the draft, fixed in a follow-up PR: (1) replacing a held `leaderboard` frame in place could still put a newer frame ahead of a queued `pong`, which the client then read as a store restart; every non-`leaderboard` message is now a conflation barrier, and a lower `pong.seq` is no longer a restart signal. (2) `pong.seq` came from the node's cache of relayed frames, so a node that had relayed nothing yet reported a stale value and a frame lost on the node's pub/sub link stayed invisible; `pong.seq` is now read from the Redis counter, and the client waits 1 s for a frame still in flight before it resyncs. (3) A `snapshot` read before the end could reach the client after `quiz_ended` and replace the final standings with open ones; the client now ignores a `snapshot` with `status: open` once `quiz_ended` is applied. No test covers these rules yet, because no gateway or client code implements them; the gateway and client tests that add them must cover all three.
