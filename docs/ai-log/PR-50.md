## PR-50 — Quiz use cases: message handlers, error mapping and the snapshot cache

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add the transport-free application layer: one handler per client message, store calls in, unicast replies out, domain and store errors mapped to protocol codes, a rate-limited `resync` whose shared standings are cached per (quiz, seq, status) while the player's own rank is read fresh.
- **Prompt / interaction:** The agent wrote `api/tests/unit/app/test_service.py` first (it failed on the missing module), then the service, then cut both to the 400-line budget.
- **What was wrong or changed:** (1) The first `rank_update` test expected rank 200 for the 200th joiner, ignoring that the one player who scored moves to rank 1; the expected ranks were corrected (u048 is 50th, u049 is 51st). (2) The service called the store's single-user `rank_of`, which a merged PR had replaced with the batched `ranks_of`; mypy caught it after the rebase, and the snapshot now uses `ranks_of`. The post-merge review found six more mistakes, fixed in a follow-up PR, each now caught by a test in `api/tests/unit/app/test_service.py`: (3) only the built-in `ConnectionError`/`TimeoutError` were mapped to `UNAVAILABLE`, but redis-py raises its own classes (`test_redis_faults_are_unavailable_and_ping_answers_null`); (4) the shared-part cache key (seq, status) missed joins, so a snapshot could show a stale player list beside a fresh own rank and send `rank_update` below 201 players (`test_snapshot_never_mixes_stale_standings_with_a_fresh_own_row`, `test_snapshot_rereads_both_parts_when_a_join_lands_between_reads`); (5) `joined.displayName` echoed the request instead of the stored name (`test_joined_echoes_the_stored_name`); (6) the cache had no way to be dropped after a store restart (`test_dropped_cache_refetches_at_the_same_seq`); (7) a `QUIZ_ENDED` refusal without an end seq never called `end_quiz` (`test_first_writes_after_the_deadline_announce_the_end`); (8) `ping` sorted the full standings instead of reading the counter (`test_ping_reads_only_the_counter`). A later whole-codebase analysis found one more, fixed in a later PR: (9) a connection that joined after the end refused every `answer` with `QUIZ_ENDED` before the store's replay check, so a retry whose first reply was lost got an error instead of its stored `answer_result` (`test_lost_reply_replays_on_a_connection_opened_after_the_end`).
