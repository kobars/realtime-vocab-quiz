## PR-51 — Fix protocol client recovery, restart and send-state defects

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix the seven defects that the post-merge review of PR-37 confirmed in `web/src/protocol/client.ts` and `web/src/protocol/seq.ts`: retry a resync after `UNAVAILABLE` with backoff, schedule the pong check, a connect generation for `start`/`stop`/`start`, pass the snapshot `status` and do not emit a snapshot the tracker ignores, send only on an open socket, keep the last applied seq on `joined`, and resolve option defaults lazily.
- **Prompt / interaction:** The agent wrote one test per finding first and saw each fail for the stated reason, then made the fixes; it reverted each fix in turn to confirm that its test fails without it.
- **What was wrong or changed:** The first draft of the stale-ticket-failure test had a comment that named the wrong ticket request as the stale one; reading `connectTicket` showed that the first attempt asks for its ticket only after the shared session exists, so the hanging request is the stale one, and the comment now says so. The fake socket now throws on `send` before it opens, as the browser `WebSocket` does, which the earlier tests did not model. A later whole-codebase review found one AI mistake: the client repeated a resync only after an error whose `requestType` was `resync`, but the gateway's token bucket drops a frame before parsing it and replies `RATE_LIMITED` with no `requestType`, or nothing at all, so a dropped resync left the client resyncing while broadcasts and pongs kept the link alive. A follow-up PR keeps the outstanding resync, sends it again 1 s after an untyped `RATE_LIMITED` and after a 5 s snapshot deadline; `web/src/protocol/client.test.ts` ("sends the outstanding resync again 1 s after a RATE_LIMITED that names no request, while frames keep arriving" and "sends a resync again each time its snapshot does not arrive in time, until it does") now catches it.
- **Verification:** `make check` (exit 0); `pnpm -C web exec vitest run src/protocol` passes 92 tests, including the new ones in `web/src/protocol/client.test.ts` and `web/src/protocol/seq.test.ts`.
