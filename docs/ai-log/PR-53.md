## PR-53 — Add the Pinia quiz store

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add the Pinia store that turns `QuizClient` events into the state the screens read (connection, phase, quiz information, the current question with a display-only deadline, the pending answer, the last result, standings, my rank and score, finished, ended, the last error) with the actions `join`, `answer`, `next` and `loadPage`; add `rejoin()`, `getLeaderboard()` and a `resyncing` status event to `QuizClient`.
- **Prompt / interaction:** The agent read the UI spec's state chart and message table and the protocol spec's sequence rules, wrote the store and its tests in one pass, then shrank both to fit the 400-line limit of a PR.
- **What was wrong or changed:** (1) The first test helpers built server frames with `as const` literals; `vue-tsc` rejected them because readonly tuples and plain strings do not fit the generated message types, so each helper now returns its message type (`Joined`, `Question`, `Snapshot`, ...). (2) The first draft was over the line budget (about 500 changed lines); the store now keeps its state in one reactive object, so a new join resets it in one step, and the separate `QuizClient` unit tests were dropped because the store tests drive the new client methods through a real `QuizClient`. Found after the merge, fixed in a follow-up PR (each now caught by a test in `web/src/stores/quiz.test.ts`): (3) `quiz_ended` during a gap resync left the connection `resyncing` for good, because the snapshot that answered the resync was read before the end and is dropped, so the pill never went (`quiz_ended during a gap resync drops the resyncing pill...`); (4) `pending` was cleared only on `ALREADY_ANSWERED`, so after `QUESTION_NOT_OPEN` the choices stayed locked and the rejoin did not ask for the open question again (`QUESTION_NOT_OPEN on an answer unlocks the choices...`); (5) a `question` reply that arrived after `quiz_ended` moved the phase back to `question` and let an answer go out (`a question that arrives after quiz_ended changes nothing...`); (6) on a rejoin, `finished: true` replaced the feedback for the last question, against UI spec §4.2 (`a rejoin during the feedback for the last question keeps feedback...`).
- **Verification:** `make check` (exit 0, vitest 189 passed); `web/src/stores/quiz.test.ts` (9 tests, three of which fail against the previous `QuizClient`); `scripts/check_internal.py --commits origin/main..HEAD` (clean).
