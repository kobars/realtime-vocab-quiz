## PR-54 — Fix answer retries for request-less RATE_LIMITED, NOT_JOINED and UNAVAILABLE

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Fix four confirmed answer-retry defects in `QuizClient` (`web/src/protocol/client.ts`): resend every answer in flight 1 s after a `RATE_LIMITED` with `requestType: null` and clear the in-flight list, so a later error is not matched to a dropped answer; keep an answer after `NOT_JOINED`, send `join` again and resend the unsettled answers after the next `joined`; retry an `UNAVAILABLE` answer after the full-jitter backoff, growing per retry of that answer, instead of a fixed 1 s.
- **Prompt / interaction:** The agent wrote one Vitest test per defect from protocol spec §2.4, §7 and §9 and ui spec §4.3, saw all four fail on `main`, then changed the client until they passed.
- **What was wrong or changed:** The first draft of the stale-head test passed on `main` for the wrong reason: the old code deleted the dropped answer and then the next one, so both versions ended with nothing to resend. The test now ends with one answer still unsettled, which only the fixed client gets right. The existing test that treated `NOT_JOINED` as final was removed from the final-error list, and the fixed 1 s `UNAVAILABLE` test was replaced by a backoff test.
- **Verification:** `make check` (exit 0); `pnpm -C web exec vitest run src/protocol/client.test.ts` passes 37 tests in `web/src/protocol/client.test.ts`, four of which fail without the fix.
