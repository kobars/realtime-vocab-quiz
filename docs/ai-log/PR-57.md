## PR-57 — Settings, composition root and import-linter layer rules

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add the pydantic-settings configuration with the spec defaults, `create_app()` that wires the memory or Redis store with the mocks and the use cases behind start and stop hooks, a `/healthz` route, and import-linter contracts for the layer rules run by `make check`.
- **Prompt / interaction:** The agent wrote `api/tests/unit/test_config.py` and `api/tests/unit/test_main.py` first (both failed on the missing modules), then the code; it injected one forbidden import per contract to show each contract breaks, then cut the diff to the 400-line budget.
- **What was wrong or changed:** (1) The first draft put the in-memory ticket store on the injected clock, but that clock is quiz time only: a test that moves quiz time 60 s forward would have expired every 30 s ticket. Tickets and sessions now use the wall clock; `test_memory_store_runs_on_the_injected_clock_and_tickets_on_real_time` fails with the old wiring. (2) The memory and Redis branches of the wiring reused one variable name for two store types; mypy rejected it and the branches now use distinct names.
- **Found after the merge:** The post-merge review confirmed eight mistakes, fixed in a follow-up PR. (1) `ADMIN_MOCK=1` accepted an empty `ADMIN_TOKEN`; caught by `test_admin_mock_refuses_an_empty_token_from_the_environment` in `api/tests/unit/test_config.py`. (2) `TICK_MS`, `TOP_N` and `FULL_LIST_MAX` were validated but never reached the stores, which kept their own constants; caught by `test_the_store_limits_come_from_the_settings` in `api/tests/unit/test_main.py` and `test_snapshot_and_tick_follow_the_configured_limits` in `api/tests/unit/test_memory_store.py`. (3) A failing stop hook skipped the remaining stop hooks and replaced the start error; caught by the extended `test_hooks_run_in_order_and_shutdown_runs_after_a_failed_start` and `test_every_stop_hook_runs_when_some_fail_after_a_clean_start`. (4) `quiz.main.app` built a new app, store and Redis pool on every access; caught by `test_module_app_is_built_once_on_first_access`. (5) The resync limit ran on the wall clock, so a backward clock step refused every resync; caught by `test_the_resync_limit_runs_on_a_monotonic_clock`. (6) The ports, use-case and adapter contracts did not forbid `starlette`, `uvicorn` or `pydantic_settings` (nor `fastapi` for the adapters); shown by injecting each import, which now breaks the contract. (7) The trusted-proxy default covered only `172.16.0.0/12`, not Docker's `192.168.0.0/16` pool; caught by `test_defaults_match_the_spec`. (8) `.env.example` said to copy it to `.env`, which the API never loads; it now says the API reads process environment variables only.
