## PR-59 — Add the live leaderboard panel with FLIP rows, a pinned row and paging

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add the live leaderboard panel of the Vue client: rows keyed by `userId` in a `<TransitionGroup>` (FLIP moves, no FLIP when more than 20 rows move), my row highlighted and pinned under the top 50 from `rank_update`, the player counts, and "Show all players" paging through `get_leaderboard` with the page's `atSeq` and a reload of the open page at most once per second; record `seq` and `pageAtSeq` in the quiz store.
- **Prompt / interaction:** The agent read the UI spec's leaderboard, motion and keyboard sections and the protocol rules for `leaderboard_page`, added the store fields test first, then wrote the components and component tests that drive server frames through the store.
- **What was wrong or changed:** (1) The first draft exported constants from a `<script setup>` block, which Vue does not allow; they moved to `limits.ts`. (2) Vue Test Utils stubs `TransitionGroup` by default, so the first component tests found no list element and only the podium's rows; the tests now mount with the real `TransitionGroup`. (3) The "(you)" suffix was a separate text node that the template compiler condensed to "Ana(you)"; it is now one interpolation. (4) A test expected my old row to be gone right after it left the top 50; with the real `TransitionGroup` the row stays in the DOM with its leave class until the fade ends, so the test ignores leaving rows. (5) The first version also held the results screen and was over the 400-line limit; the results screen was taken out of this PR. The post-merge review then confirmed eight mistakes in this code, fixed in PR-74, each with a test in `web/src/components/leaderboard/leaderboard.test.ts` that failed before the fix: (6) opening "Show all players" removed the focused button and focused nothing, so Escape was lost, and the test pressed Escape on the section itself instead of from the focused element; (7) a pending reload survived Previous/Next and a final reply; (8) pages were sliced from one array that assumed every earlier rank was present, so a short first page left page 2 empty; (9) full replacements (`snapshot`, `rebase: true`) still ran FLIP, and my row's 1 s tint on moving up was missing; (10) the reload compared `seq <= atSeq`, so a store restart that lowered `seq` stopped it; (11) a first page request with no reply was never retried; (12) the throttle read the wall clock (`Date.now()`) instead of the store's monotonic clock; (13) a leaving row, `position: absolute` in a flex column with no `top`, faded at the top of the list. A later keyboard pass found one more AI mistake, fixed in PR-154: Next on the last page (or Previous on the first) disabled the focused button, the browser moved the focus to `body`, and Escape no longer closed the panel. `web/src/components/leaderboard/leaderboard.test.ts` ("a pager button that disables itself hands the focus to the panel, so Escape still closes it") now catches it.
