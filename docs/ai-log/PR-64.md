## PR-64 — Build the landing and join screen

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Build the landing and join screen of UI spec §3.1: quiz ID and display name checks (upper-case as typed, `^[A-Z0-9-]{3,16}$`, 1-32 characters after trim), the share link `/q/:quizId` filling the quiz ID, and the join outcomes (`joined` and `QUIZ_ENDED` open the quiz route, `QUIZ_NOT_FOUND` shows a message under the quiz ID field).
- **Prompt / interaction:** The agent wrote the component and rule tests first against UI spec §3.1 and confirmed they failed, then built the screen on the existing quiz store, driving it in the tests through a fake socket client.
- **What was wrong or changed:** (1) The first draft also held the quiz preview from `GET /quizzes/{id}` and changed about 570 lines, over the 400-line limit; the preview was moved to a follow-up PR and the two form fields were folded into one `JoinField` component. (2) The test for "`joined` opens the quiz" checked the route after one `flushPromises`, which is not enough while the lazily loaded quiz view resolves for the first time, so it failed only when it ran first; it now waits with `vi.waitFor`. (3) A design change, not a mistake: `/q/:quizId` used to redirect straight to `/quiz/:quizId`, which skipped the join; it now opens the join screen with the ID filled in, and `docs/spec/ui.md` §2 was updated.
- **Mistakes found after the merge:** the post-merge review confirmed five AI mistakes in this PR, fixed in a follow-up PR. (1) The join watcher handled only `joined`, `QUIZ_ENDED` and `QUIZ_NOT_FOUND`, so any other failed join (for example `UNAVAILABLE`, or a final close) left the form locked on "Joining…"; caught by the "unlocks the form after …" cases in `web/src/views/JoinView.test.ts` and "another failed first join stops the client" in `web/src/stores/quiz.test.ts`. (2) The name field had a native `maxlength=32`, which counts UTF-16 units before the trim and cut valid names such as 32 emoji; caught by the "no native length limit" test in `web/src/views/JoinView.test.ts`. (3) `readName` and `saveName` read the `sessionStorage` default argument outside their `try`, so a blocked storage getter stopped the screen from rendering; caught by "survives a sessionStorage property that throws on access" in `web/src/components/join/join.test.ts` and "renders when sessionStorage cannot be read" in `web/src/views/JoinView.test.ts`. (4) `displayNameError` counted code points without NFC normalization, unlike the server; caught by "counts characters after NFC normalization" in `web/src/components/join/join.test.ts`. (5) Upper-casing the quiz ID moved the caret to the end when a lower-case letter was typed mid-ID; caught by "keeps the caret in place" in `web/src/views/JoinView.test.ts`.
