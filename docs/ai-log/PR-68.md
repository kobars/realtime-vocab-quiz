## PR-68 — WebSocket gateway: upgrade checks, auth, frame and rate limits

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add `GET /ws`: before accept, an exact Origin match, the `quiz.v1` subprotocol, ticket redeem and the per-process and per-address caps (client address from `X-Forwarded-For` behind trusted proxies only). Per frame: a 16 KiB size limit, a token bucket before parsing, the strict parser and the use cases. Logs keep the path and drop the query string.
- **Prompt / interaction:** The agent wrote `api/tests/integration/ws/test_gateway.py` first: one in-process client test per rule, all failing on the missing route. It then wrote the code, checked it under real uvicorn on an ephemeral port with a `websockets` client, and cut the first draft from 441 to under 400 changed lines.
- **What was wrong or changed:** (1) The first test helper passed one shared default headers dict to Starlette's `websocket_connect`, which adds its own headers to the dict it gets. After the first call, every connect carried `sec-websocket-protocol: quiz.v1`, so the missing-subprotocol test never sent a request without it and failed with "DID NOT RAISE". The helper now passes a copy. (2) Under real uvicorn, the default `websockets-sansio` protocol logs a spurious "returned without completing handshake" error after a denial response. The client still gets the right status. This is recorded as a known limit, not changed. (3) The post-merge review confirmed six mistakes, fixed in a follow-up PR: the Redis ticket store let redis-py's `ConnectionError` and `TimeoutError` through, which are not the built-in errors the gateway maps to 503 (`test_redis_variant_raises_the_builtin_errors_when_redis_is_unreachable` in `api/tests/unit/adapters/test_mock_auth.py`, `test_an_unreachable_ticket_store_answers_503` in `api/tests/integration/ws/test_gateway.py`); the log filter missed `uvicorn.asgi`, whose trace lines print the scope with the ticket in `query_string`, and the log test called the filter by hand, so it never checked the wiring (`test_logs_hold_the_path_but_never_the_ticket` now checks both); `MAX_PAYLOAD_BYTES` above 16 KiB let a frame between the two limits get `MESSAGE_TOO_LARGE` without the 1009 close (now refused at startup, `api/tests/unit/test_config.py`); and the image ran uvicorn with its own proxy-header handling, which trusts loopback peers before the gateway's rule, and with `permessage-deflate` on, which the spec turns off (`test_api_image_leaves_x_forwarded_for_to_the_gateway_and_turns_deflate_off` in `scripts/tests/test_images.py` reads the command line with uvicorn's own parser). The same review found uvicorn's 16 MiB default frame cap, which a separate image fix had already lowered to 64 KiB.
