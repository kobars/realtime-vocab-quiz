## PR-72 — Finish the Redis store: publish, leave, end and standings reads

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add `publish_leaderboard.lua`, `leave.lua`, `end_quiz.lua` and `read_standings.lua` of `docs/spec/redis.md` §3, map them in `RedisStore`, and run the whole store contract suite on Redis with no xfail left.
- **Prompt / interaction:** The agent wrote the scripts and the integration tests from the Redis spec, checked that the new tests fail with the source changes stashed (24 failures), and ran everything against a throwaway `redis:8-alpine` container.
- **What was wrong or changed:** (1) The first `events` fixture subscribed with `ignore_subscribe_messages=True` and did not wait for Redis to confirm, so a frame published right away could be missed; it now waits for the `subscribe` confirmation first. (2) The first test for `ranks` drove real answers, but a correct answer always lifts the scorer into the top 50 of 201 players at total 0, so the test never reached the branch it named; it now seeds `scored` with one top-50 member and one outside it, as `score_answer` leaves them, and asserts only the outside one is listed. Separately, `_ok` now raises only for protocol error codes, so the script statuses `stale`, `busy`, `clean`, `marked` and `not_due` pass through to the store methods.
- **Found after the merge:** The post-merge review confirmed four mistakes, fixed in a follow-up PR. (1) The tick gate returned the token's `PTTL` with no upper bound; Redis stores expiry as wall-clock time, so a backward clock step blocked publishing on every node for as long as the step. The contract test for this passed on Redis only because its clock helper cannot move the Redis clock. Caught by `test_tick_token_stretched_by_a_clock_step_back_is_cut_to_one_tick` in `api/tests/integration/test_tick.py`. (2) The script loader took every regular file in `lua/` as a script, so a stray `.DS_Store` made startup fail; caught by `test_only_lua_files_beside_lib_are_scripts` in `api/tests/unit/adapters/test_redis_scripts.py`. (3) The new scripts used the default tick, `TOP_N` and `FULL_LIST_MAX` instead of the configured limits; recorded with its test in the PR-57 entry. (4) `docs/spec/redis.md` §6 and the C6 row of `docs/spec/domain.md` named five tests that were never written; they now cite the contract and integration tests that cover the same behavior.
- **Verification:** `make check` (exit 0); `make test-integration` with `REDIS_URL` unset (82 passed, no xfail): `api/tests/integration/test_tick.py`, `api/tests/integration/test_deadline.py` and the `redis` cases of `api/tests/contract/test_store_contract.py`; `scripts/check_internal.py --commits origin/main..HEAD` (clean).
