## PR-75 — Show a quiz preview on the join screen

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add the quiz preview of UI spec §3.1 to the join screen: look up a valid quiz ID with `GET /quizzes/{id}`, show the title, question count, player count and open or ended state, block the join on a 404 with "No quiz with this ID", offer "See results" for an ended quiz, and let a failed lookup fall through to the socket `join`.
- **Prompt / interaction:** The agent wrote the request tests (`fetchQuizPreview` with an injected fetch) and the screen tests (stubbed global `fetch`) against UI spec §3.1, then built the preview module, the preview card and the lookup in the join view; it was split out of the join screen PR to keep both under 400 lines, then rebased on `main`.
- **What was wrong or changed:** The first version read the player count from a `playerCount` field, but the quiz info endpoint names it `players`. Every real reply would have failed the shape check and been treated as unavailable, so no preview would ever show; the tests passed because their fixtures used the same wrong name. The preview type, the card and both test fixtures now use `players`. The post-merge review found five more defects, fixed in a follow-up PR: any 404 counted as "no such quiz", so a 404 from a missing route or a proxy blocked the join (now only a 404 with `QUIZ_NOT_FOUND`; `web/src/components/join/join.test.ts`, "treats a 404 from a missing route as unavailable"); the lookup had no timeout, so a request that never answered left the button on "Joining…" (now 3 s, headers and body; "gives up on a request that never answers and aborts it"); a share link opened during the lookup made submit apply the old answer to the new ID or join an unchecked ID (now ignored while joining, and a stale answer is dropped; `web/src/views/JoinView.test.ts`, "while the lookup runs"); leaving the field again cleared "No quiz with this ID" (`keeps "no quiz" when the field is left again without an edit`); and no screen test covered the fallback after a 5xx, a network failure or a wrong-shape body, or the second lookup on submit ("shows no preview after … and still joins", "asks again on submit after …").
- **Verification:** `make check` (exit 0; vitest 249 passed). `web/src/components/join/join.test.ts` (found, 404, 5xx, wrong-shape body, network failure) and `web/src/views/JoinView.test.ts` (preview shown, 404 blocks the join, ended message and "See results"); `scripts/check_internal.py --commits origin/main..HEAD` (clean).
