## PR-76 — Add the HTTP endpoints: sessions, tickets, quiz info, mock admin and probes

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Add the HTTP adapter (`api/src/quiz/adapters/http/`): `POST /sessions` and `POST /tickets` over the mock ticket store, `GET /quizzes/{id}` with one 404 body for every unknown ID, the mock `POST /admin/quizzes` behind `ADMIN_MOCK=1` and `X-Admin-Token`, `/healthz` and a Redis-pinging `/readyz`, and a 503 mapping for store outages; add `title()` to the question bank port.
- **Prompt / interaction:** The agent read the protocol and Redis specs and the locked acceptance harness (which fixes the `/admin/quizzes` shape and the ticket reply), wrote the endpoint tests first, then the adapter, and ran the acceptance suite against the result. The first draft also held metrics, JSON logs and the host end route; it passed 400 changed lines, so those parts were taken out for a later PR.
- **What was wrong or changed:** (1) `/readyz` first returned `Status | JSONResponse`; FastAPI cannot build a response model from that union, so every app failed to start. It now sets `response.status_code = 503` and returns the model. (2) The error handlers were registered app-wide. For a WebSocket scope, Starlette calls the handler and drops the `JSONResponse` it returns, so a store error raised in the `/ws` endpoint would have been swallowed. The handler now re-raises on any scope that is not HTTP. No test covers this path yet; the gateway catches store errors itself today. (3) The metrics scrape test of the first draft expected the `text/plain; version=0.0.4` content type and `# TYPE` names without `_total`; prometheus-client 0.26 serves version 1.0.0 and keeps `_total` in the `# TYPE` line. That test moved to the later PR with the metrics.
