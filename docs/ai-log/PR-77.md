## PR-77 — Play view with the question screen and countdown ring

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Replace the quiz placeholder with `PlayView` (header, intro, question and results by phase) and build the question card and countdown ring of UI spec §3.3 and §5.3: keys 1–4, one answer per question, a pending state, a ring on the monotonic clock, and choices locked while the socket is down.
- **Prompt / interaction:** The agent was given the acceptance criteria and the UI spec sections, built on the merged quiz store (`msLeft()`, `pending`, `connection`) and wrote component tests that drive the view through the store with server frames and a fake clock.
- **What was wrong or changed:** The first AI draft of the 1–4 key handler called `event.target.closest(...)` on whatever target the event had; a key event dispatched on `window` has no `closest`, so the handler threw before choosing. The handler now checks `event.target instanceof Element` first, and the tests dispatch keys from the focused element. The first draft also covered feedback and status messages in one change of about 700 lines; this PR keeps the question screen, and the rest follows separately. The post-merge review found seven more AI mistakes in this code, fixed in a later PR: Skip, Start and Continue stayed enabled while the socket was down, so the client dropped the `next`; a join on an open question showed the intro with a Continue that would send `cursor`; a direct load of `/quiz/:quizId` rendered a dead screen; the countdown never announced 10 s and 5 s left; score and rank had no live region; the intro left out the quiz time left; and "Waiting for the connection…" stayed forever after a final close or `QUIZ_NOT_FOUND`. `web/src/views/PlayView.test.ts` and `web/src/router.test.ts` now catch each one. A later layout and keyboard pass found two more AI mistakes, fixed in PR-154: the phone layout grid had no column template, so a long player name in the Leaderboard tab widened the page, and the choice buttons drew their ring offset in white instead of the page color. `web/src/views/PlayView.test.ts` ("phones: the one column may shrink below a long name…" and "the focus ring of a choice is offset by the page color") now catches them.
- **Verification:** `make check` green (vitest: 18 files, 245 tests); `web/src/views/PlayView.test.ts` covers the countdown with a far-future wall clock, time up with a pending answer, keys and locking, focus on the prompt, Start and Continue, and the lock while reconnecting.
