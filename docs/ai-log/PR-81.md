## PR-81 — Play screen: connection pill and error messages

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Show the connection state and the player-facing errors calmly on the play screen (UI spec §3.7, §4.3, §6.3): a `role="status"` pill for connecting, reconnecting and resyncing; one short message per error code that clears after six seconds; a `role="alert"` card for `SESSION_REPLACED` that replaces the quiz column, takes the focus and offers "Use this tab"; and a store change so `SESSION_REPLACED` stops the client.
- **Prompt / interaction:** The agent took the status components, strings and store change from an earlier, larger play-screen draft that had been split, ran the store test against the old store to see it fail, then mounted the components in `PlayView.vue` and extended the component tests.
- **What was wrong or changed:** (1) Before the store change, `SESSION_REPLACED` only set `lastError`, so a following close 1006 made the client open a new socket and take the session back from the other tab; the store now calls `stop()` on it, and the new store test fails without that line. (2) The first version of the session-replaced test called `.exists()` on the result of `wrapper.get()`, which `vue-tsc` rejects (`get` throws instead of returning a missing wrapper); it now uses `wrapper.find()`. (3) The post-merge review found six defects in this change, fixed in a follow-up PR: the card kept its visibility in a local copy set by a non-immediate watch, so a play screen mounted after `SESSION_REPLACED` was empty; in the finished and results phases the card showed next to the results; close 4001 and `UNSUPPORTED_VERSION` had no blocking card, because the pill inferred "the player left" from close 1000, which `stop()` reports for every stop; `NOT_JOINED`, `INVALID_STATE` and `INTERNAL` showed a red "Something went wrong" message; and "Server busy, retrying" cleared after a fixed 6 s although the retry backoff reaches 10 s. The store now has a `blocked` state and a `busy` state that the pill, the card and the play screen read. The tests that now catch them are in `web/src/views/PlayView.test.ts` (mounted after the error, after finishing, close 4001, `UNSUPPORTED_VERSION`, the silent error codes, the busy pill) and `web/src/stores/quiz.test.ts` (blocked on both errors and on close 4001, busy until the reply).
- **Found after the merge (second review):** UI spec §3.7 has two more blocking cards that this change left out: close 1008 showed only the "Disconnected" pill instead of "Can't connect to this quiz" with Reload, and there was no "Still can't connect" card with Try again. Fixed in PR-112, caught by the close 1008 and the 10-connects tests in `web/src/views/PlayView.test.ts` and `web/src/stores/quiz.test.ts`.
- **Verification:** `make check` (exit 0); `web/src/stores/quiz.test.ts` (16 tests; the `SESSION_REPLACED` test fails on the previous store); `web/src/views/PlayView.test.ts` (10 tests: the reconnecting pill through the snapshot, five error messages and their timeout, the session-replaced card); `scripts/check_internal.py --commits origin/main..HEAD` (clean).
