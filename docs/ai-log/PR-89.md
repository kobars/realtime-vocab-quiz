## PR-89 — WebSocket send buffers: one writer per socket, conflation, 1013 and session replacement

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Give each socket one writer with a byte-bounded send queue: above 64 KiB conflate `leaderboard` frames (newest only, sent with `rebase: true`, every other message a barrier), above 256 KiB send `error UNAVAILABLE` and close 1013, and close a socket that cannot drain within 5 s of a close. Add a per-node registry of joined sockets that broadcasts to a quiz and closes a replaced connection with `SESSION_REPLACED` and 4001.
- **Prompt / interaction:** The agent read the flow-control rules of `docs/spec/protocol.md` §5 and wrote the sender, then tests that drive it with fake sockets (one that never reads, one that drains late, one that reads at once) and an in-process client test for two sockets of one user. The first draft also held the server heartbeat and the leave grace; at 526 changed lines it was cut to this PR, and those two parts follow separately.
- **What was wrong or changed:** (1) The first replacement test entered both Starlette test sessions by hand and never exited them, so the test client hung at shutdown waiting for their tasks; the test now opens them with `with`. (2) The first sender built `ProtocolError` without `requestType`, a required field; mypy caught it before the tests ran. (3) Until this PR the replaced connection id returned by `join` was ignored, so an older socket on the same node stayed open until the store fence refused its next write; the registry now closes it at once. (4) The post-merge review found four defects in the AI-written code, fixed in a later PR, each with a test in `api/tests/integration/ws/test_connections.py`: the hard-limit path queued its `UNAVAILABLE` error through `send()`, which re-entered the limit check while a large frame was in flight and recursed instead of closing 1013 (`test_the_hard_limit_closes_1013_even_when_the_frame_in_flight_fills_it`); the flush deadline passed an absolute loop time to `asyncio.timeout`, a relative delay, so a close before the writer ran never timed out (`test_a_close_before_the_writer_runs_still_ends_within_flush_s`); `close()` rescheduled the timeout after a failed write had finished it and raised inside the caller (`test_replacing_a_socket_whose_writer_failed_does_not_raise`); and the receive loop kept handling frames while a replaced socket flushed, so it could join again and take the session back (`test_a_closing_socket_hands_no_more_frames_to_the_use_cases`).
