## PR-98 — Server heartbeat through the image's uvicorn config, and the leave grace

- **Tool:** Claude Code (claude-opus-5-5)
- **Task:** Turn on the server WebSocket heartbeat in the image: a uvicorn ping every `HEARTBEAT_MS`, with a pong timeout that closes a silent socket by the next ping. Add the `GRACE_MS` leave grace in the gateway registry: a rejoin on the node cancels it, and a failed `leave` is logged.
- **Prompt / interaction:** The agent started from an earlier tested draft of the grace timers and `server_config`. It wired the image to run through `server_config` (`python -m quiz`) and replaced the CMD-flag checks in the image tests with checks on the config.
- **What was wrong or changed:**
  - The draft built `server_config` with the heartbeat options, but the image still started uvicorn from the Dockerfile's CLI command, so production never applied the heartbeat. The image now runs `python -m quiz`, and `scripts/tests/test_images.py` asserts that command and the 25 s ping interval and timeout.
  - The first version of the entry point let `uvicorn.Config` apply its default logging config. The app is now built before the config, so that default replaced the app's JSON handlers, and uvicorn's own lines came out as plain text. A `docker run` of the image showed this. The fix sets `log_config=None`, which a test in `scripts/tests/test_images.py` asserts.
  - The draft caught only outage and domain errors around the timer's `leave`. Any other error would have ended the background task with an unretrieved exception, so the handler now logs every exception.
- **Verification:**
  - `make check`: green (446 pytest, 311 vitest).
  - `make test-integration`: green (115 passed).
  - Tests in `api/tests/integration/ws/test_connections.py`: a spy on `store.leave` sees one leave, for the newer connection only; a real uvicorn on a free port drops a raw socket that never pongs while a pinging client stays open; a failing `leave` is logged.
  - `docker build -f api/Dockerfile .` then `docker run`: the container turns healthy, and its log lines are JSON.
